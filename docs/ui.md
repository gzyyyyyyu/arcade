# 界面规范（平台和所有游戏）

> 平台和各游戏的界面照这份做，审界面类 PR 也按这份对。每条写的是要求和理由；能量化的给数字，验收时照数字查。
> 已经写在别处的不重抄，只引用：
> - 牌桌互动（头像菜单、表情、道具）：[table-fun.md](table-fun.md)；
> - 错误码给玩家怎么说：[api.md](api.md) 15.10；
> - 平台自己的配色、动效、声音：`platform/docs/style.md`。
>
> 各游戏的画风可以不同（开盘的卡通纸面、牌馆的毡布、夜巡的水墨），**交互方式要一样**：玩家从大厅进不同的游戏，不用重新学怎么关弹窗、怎么回去、哪个按钮是"确定"。

## 0. 怎么验收

界面类 PR 至少看三个尺寸的截图，截图按 [engineering.md](engineering.md) 第 7 节放：

| 尺寸 | 代表 |
|---|---|
| 1280×720 | 电脑（最常见的笔记本） |
| 390×844 竖屏 | 手机（主流 iPhone） |
| 844×390 横屏 | 手机横屏（牌桌、动作游戏的主要姿势） |

动到布局的再加两个：1920×1080（宽屏不能拉伸或空一大片）、360×640（小屏不能溢出）。下面的像素都是**屏幕上的 CSS 像素**。按舞台缩放的游戏（德州、雀馆、画布游戏）要按缩放后的实际大小算，不按设计稿算。

## 1. 回大厅

- 左上角常驻，小房子图标加"大厅"两个字，可点区域 ≥ 44×44；窄屏可以只留图标，但点区不缩。
- 任何界面最多两步回到大厅：弹窗里点一次关掉，再点一次"大厅"。
- 对局中离开先确认一次（"这一局还没打完，确定离开吗？"），离开前补传云存档；不在对局中就直接走，不问。冒烟里点一次。
- 单独部署（没有平台）时这个入口回游戏自己的首页，文字改成"首页"（kit 的 `detectPlatform()`）。
- **Esc 不能直接离开游戏**：Esc 先关最上面一层（弹窗、面板、选中）；什么都没开时，平台可以回大厅首页，游戏什么都不做。

理由：所有游戏同一个位置、同一个样子，玩家不用找；误按 Esc 丢掉一局是最伤的体验。

## 2. 按钮和可点区域

| 要求 | 数值 |
|---|---|
| 触屏上的可点区域 | ≥ 44×44（看得见的部分可以小，用透明外扩补足，看得见的不小于 32） |
| 相邻两个可点区域的间距 | ≥ 8 |
| 电脑（鼠标）上的可点区域 | ≥ 32×32 |
| 一个界面同时出现的主按钮 | 1 个 |

按钮分四档，每个模块各有一套实现，但档位和含义一样：

| 档 | 什么时候用 | 样子 |
|---|---|---|
| 主按钮 | 这一屏最该点的那一个（开始、确定、出牌） | 实色、最醒目（各游戏的主色），最大 |
| 次按钮 | 其他正常操作（取消、换一桌、看规则） | 浅底加描边 |
| 文字按钮 | 不重要的（跳过、以后再说、看详情） | 只有字或小图标，不加底 |
| 危险按钮 | 丢东西、走人、没法撤回的（认输、离桌、删存档、退出好友房、实盘带入大额） | **单独的危险色**（红系），不和主按钮同色 |

- 每个按钮都要有五种状态：常态、悬停（只在 `(hover: hover) and (pointer: fine)` 的设备上）、按下（下沉 2–3px 或缩到 0.97）、禁用、键盘焦点。
- 禁用：透明度约 0.5，点了没反应。能说清原因的，在旁边或长按时说原因（"筹码不够一份"），不只是变灰。
- 键盘焦点：`:focus-visible` 时画一圈 3px 的描边，颜色和底色对比明显；画布游戏用自己的焦点框。
- 图标按钮要有文字说明：旁边写字，或者给 `aria-label` 并在悬停时显示提示。只有图标、玩家猜不出用途的不行。

理由：手指的平均触点约 9mm，换成 CSS 像素约 44，再小就容易点错；主按钮只有一个，玩家才不用想"该点哪个"；危险操作和主按钮同色，最容易误点。

## 3. 字号

| 用途 | 字号 |
|---|---|
| 最小字号（任何地方，包括角标、说明小字） | 12 |
| 金额、筹码、分数这类数字的最小字号 | 14 |
| 正文 | 14–16 |
| 按钮文字 | 主按钮 ≥ 16，其他 ≥ 14 |
| 小标题 / 标题 | 18–22 / 24–28 |
| 大数字、结算标题 | 自定，不受上限约束 |

- 每个模块用一组字号变量（CSS 变量或画布的常量表，比如 `--fs-xs` 到 `--fs-3xl`），界面里引用变量，不在各处写死数字。
- 画布游戏的字号是世界坐标的，要换算成屏幕像素后再对照最小值。手机上设一个下限，比如牌馆的 `TYPE_FLOOR_PX`、开盘的 `MIN_TEXT_SIZE`，保证缩放后不小于 12。
- 字号阶梯控制在 6–8 级，层级之间差至少 2px，不然看不出层级。

理由：12px 是中文在手机上还能看清笔画的下限，数字要比汉字更大一点才不认错；散落各处的写死字号，正是"有的地方 10px、有的 13px、有的 15px"这种不统一的来源。

## 4. 颜色和状态

- 颜色都定义成变量（CSS 变量或画布的颜色表），界面里不写死色值。
- **状态色**，每个模块都要有，而且各自分开：

  | 状态 | 要求 |
  |---|---|
  | 选中 | 描边加浅底，或者换底色；**不和主按钮同色**，否则分不清哪个是选了的、哪个是要点的 |
  | 禁用 | 见第 2 节 |
  | 危险 | 红系，只给第 2 节的危险按钮和"会丢东西"的提示用 |
  | 赢 / 好 | 绿系 |
  | 输 / 不够 | 红系；和"成功"不能同色 |
  | 提醒 | 黄 / 橙系 |

  开盘的"红涨绿跌"是题材需要，可以切换，例外照它自己的设计文档。
- 对比度：正文文字对底色 ≥ 4.5:1，大字（≥ 18）和图标 ≥ 3:1。画在图案或光效上的字要加底或描边，不能指望背景刚好够暗。
- 颜色之外再给一个提示（图标、文字、形状），不只靠颜色区分：色弱的玩家也要分得出输赢、选没选中。

## 5. 弹窗

| 项 | 要求 |
|---|---|
| 同时 | 只开一个；新的打开时旧的先关（确认框可以叠在面板上，但最多两层） |
| 遮罩 | 深色半透明，45%–65%；遮罩下面的东西不响应点击 |
| 进场 | 淡入加从 0.92–0.96 放大到 1，140–200ms |
| 退场 | 淡出，100–150ms；淡出过程中已经不响应点击（防止连点穿透） |
| 关闭方式 | 右上角 ✕（点区 ≥ 44）、Esc、点遮罩，**三种都要有** |
| 例外 | 必须做决定的不许点遮罩关（结算、匹配中、"确定离开吗"），但 ✕ 或"取消"要有 |
| 焦点 | 打开时焦点移进弹窗，Tab 不跑出去；关掉后焦点回到打开它的按钮 |
| 确认框 | 按钮写动词（"离开""认输"），不写"确定 / 取消"；危险的那个用危险色，回车默认选安全的那个 |

理由：关弹窗是玩家最常做的动作，各游戏做法不一样（有的能点遮罩，有的不能；有的 Esc 关，有的 Esc 没反应），玩家每进一个游戏都要重新试。

实现上每个模块只有一个弹窗函数或组件，所有弹窗都经过它，不各处手拼遮罩。以后可以收进 `arcade-kit`。

## 6. 提示和报错文案

总规矩见 AGENTS.md 第 4 节"用户看到的文字"：中文、大白话、少术语。这里补三条：

1. **同一件事用同一个说法**，全站统一：

   | 说法 | 不用 |
   |---|---|
   | 筹码 | 余额、金币、积分（游戏里自己的资源除外，比如海岛的金币木材） |
   | 筹码不够 | 余额不足、资金不够 |
   | 一份 | 一单位、一注（档位见 [economy.md](economy.md)） |
   | 补给 | 救济、低保 |
   | 好友房 | 私人房、包间 |
   | 连不上，稍后再试 | 网络错误、请求失败、错误码 |

2. **出了错说三件事**：出了什么事、东西有没有丢（"筹码没动"）、现在该怎么办（按钮：重试 / 换一桌 / 回大厅）。照 api.md 15.10 的"给玩家看"那一列，不显示错误码和英文。
3. **术语第一次出现时解释**：麻将的役种、德州的位置这类，结算页上点了能看一句话的解释，不在每一局都重复一长句。

## 7. 加载、空状态、断网

| 情况 | 要求 |
|---|---|
| 等待超过 300ms | 显示占位（骨架块或转圈），不让界面空着或跳动 |
| 等待超过 1 秒 | 加上文字（"正在进房间…"）；超过 10 秒给出"重试"或"返回" |
| 空列表 | 一句话说为什么空，加一个下一步的按钮（"还没有好友 → 加好友"），不只写"暂无数据" |
| 断网 / 失败 | 按第 6 节第 2 条；能自动恢复的（重连）显示进度，恢复后自动收起 |

## 8. 设置

- 一个入口：右上角的齿轮。所有设置都收在一个面板里，不散在顶栏上（德州的做法：顶栏只留齿轮、聊天和问号，声音、动画、互动、止盈都在面板里）。
- 分组，顺序固定：
  1. **声音**：音效和音乐分开开关；有音量的给滑条，或至少四档（含静音）：手机上点分档比拖滑条准（牌馆用的就是分档）；
  2. **画面**：动画速度、减少动态效果（默认跟系统的 `prefers-reduced-motion`）、震屏或振动；
  3. **玩法和互动**：本游戏的规则选项、聊天、表情互动、提示；
  4. 最下面一个"恢复默认"。
- 改了立刻生效、立刻保存，不要"保存"按钮。存在 `<游戏id>.settings` 这类带前缀的 key 里（AGENTS.md 第 1 节第 5 条）。

## 9. 电脑端

- **悬停**：能点的东西悬停时都要有变化（变亮、抬起、描边），只在鼠标设备上生效（第 2 节）。
- **快捷键**：Esc 关最上一层（第 1 节）；空格或回车是这一屏的主操作；`?` 打开快捷键说明。有快捷键的按钮在鼠标设备上显示角标（海岛的 `1`–`9`、开盘的空格）；规则或帮助里有一页快捷键表。
- **滚轮**：长列表翻页（页面本身不滚，见第 11 节）；地图、海图这类能缩放的，用滚轮缩放。滚轮不能翻掉牌桌或改下注额，除非界面上写明了（德州的加注滑条）。
- **宽屏**：1920×1080 下内容不拉伸变形，也不缩在中间留出一大片空白。要么设最大宽度并居中（平台 1120–1280），要么按比例放大舞台；面板和列表在宽屏上可以分两栏。
- **页面结构**（平台的页和游戏里的菜单页都照这个）：
  - 页面外框正好一屏高：顶栏、内容区、页脚都在这一屏里，内容区自己不滚（第 11 节）；
  - 内容按主题分页签，不按"从上到下堆卡片"排。按游戏分的内容（排行、战绩、钱包明细）一律"总览 + 每个游戏一个页签"；
  - 分两栏时两栏等高、一起填满内容区，内容按栏分配，不出现一栏只有一小块、另一栏拖得很长；内容少到一栏就够的，一栏居中，不硬拆两栏；
  - 数字右对齐，正数绿、负数红；同一类卡片的标题、内边距、圆角一样。

## 10. 手机

下面五条是在 iPhone、iPad 上实际踩过的坑，所有游戏照做；共用包的 `arcade-kit/viewport` 已经实现（默认值取自开盘），游戏用它，不各写一套：

- **省内存设备渲染倍数封顶 2**：手机平板（iOS、触屏）上画布的渲染倍数最多 2，不按 `devicePixelRatio` 拉到 3；整屏的大背景按 1 倍光栅化。
  老 iPhone 只有 2GB 内存，开盘按 3 倍画时估算占 400–870 MB，网页反复崩溃；封顶后约 170 MB。
- **高度按看得见的区域算，不用 `100vh`**：iOS Safari 的 `100vh` 是工具栏收起时的高度，横屏时画面顶上一截被地址栏压住。
  CSS 依次写 `100vh` → `100dvh` → 脚本按 `visualViewport`（没有就 `innerHeight`）写的变量；转屏、收放地址栏后重算，转屏后稍等再补算一次。
- **双指放大时不改尺寸**：`visualViewport.scale` 明显不是 1 时，可见区的宽高是放大后的，这时不改画布、不滚动、不重排，缩回 1 倍再说。
- **WebGL 上下文**：丢了（显存吃紧时 iOS 会收回）等几秒还没恢复才提示刷新；`webglcontextrestored` 时收起提示，同一时间只有一条。
- **safe-area 带兜底值**：四边用 `env(safe-area-inset-*, 0px)` 让出刘海和圆角（配 `viewport-fit=cover`），不支持的浏览器按 0 算。

冒烟里模拟一次省内存设备（开盘的 `--lowmem`）、双指放大和上下文丢失/恢复。界面上另外要做到：

- 390×844 竖屏、844×390 横屏、360×640 小屏下：不重叠、不溢出、字不被截断。按钮里的副标题放不下就换短说法，不缩小到 12 以下，也不用"…"截断金额（AGENTS.md 第 5 节自查第 2 条）。
- 底部固定的按钮要让出 `env(safe-area-inset-bottom, 0px)`，也不能盖住版本号、说明这类内容：把内容区底部留出按钮的高度。
- 转屏后 500ms 内布局到位；横竖屏都支持的游戏，两种都要截图验收。
- 竖屏下主要内容至少占屏高的 60%（海岛竖屏的岛只占约 1/3，上下各有 500 多像素的空海）。
- 手机顶栏的图标最多 4 个，加上左上的"大厅"；其余收进设置或"更多"。

## 11. 信息密度

大厅和各游戏的首页、主界面要清爽，**不放常驻的信息条**。

- 首页和主界面不放常驻的公告条、提示条、底部固定条。要告诉玩家的事：
  - 只和某个操作有关的，放到那个操作旁边；
  - 一次性的，做成能关掉的提示，关了不再出现（本机记住）；
  - 同一时间最多一条提示条。管理员发的公告也算在这一条里：有公告时只显示公告，别的提示等公告关掉或过期后再出现。
- 一屏里同时出现的独立信息块（卡片、条、面板）：首页 ≤ 5 块，对局主界面除了牌桌或战场本身 ≤ 4 块。超了就把次要的收进二级界面（战绩、详情、设置）。
- 同一个内容在一屏里只出现一次（开盘的推荐卡在中间和右栏各一处，平台的"继续玩"在大横幅和列表里各一次）。
- 主选项（玩法、档位、开打）不折叠：开局页面上这几样一屏直接看得到、点得到，不收进"更多选项"，放不下就缩按钮、改排布，不靠藏；规则细节可以收成一行摘要，点开再改。
- **一屏放下，不用滚动**：任何游戏的任何界面，在第 0 节的尺寸下都要一屏放下，不需要滚鼠标或上下划才能看到内容和按钮。
  放不下的先缩按钮和间距（电脑上可点区域可以小到 32，触屏仍按第 2 节的 44），再改排布（多列、并排）；长列表（排行、图鉴、记录）用翻页或分页签，不用页面滚动。
  验收：五个尺寸各截一张，页面 `scrollHeight` 不超过视口高度。
- 新手引导的气泡不能挡住要操作的区域（出牌区、手牌、主按钮）；看过一次就不再自动出现。

理由：常驻信息条会让第一眼看不到游戏本身；同一屏东西越多，新玩家越找不到"开始"。

## 12. 动效

平台的做法见 `platform/docs/style.md` 的"动效"一节，各游戏照同样的原则：

- 只动 `transform` 和 `opacity`，不动会引起重排的属性；
- 界面过渡 120–260ms（弹窗见第 5 节）；演出（结算、名场面）可以更长，但能点一下跳过；
- `prefers-reduced-motion: reduce` 和设置里的"减少动态效果"打开时，关掉所有非必要的动画；
- 自动化浏览器（`navigator.webdriver`）关动画，冒烟截图才稳定。
