# 牌馆：掼蛋 + 斗地主

> 掼蛋模块里两个玩法：掼蛋和斗地主（经典叫分）。本文写分层、两个玩法共用什么、斗地主各模式怎么接；
> 斗地主的规则取舍在 `docs/rules.md` 的"斗地主"一节，电脑在 `docs/ai.md` 的"斗地主"一节，实盘数字在 `docs/stake-ddz.md`。
> 不变的东西：模块 id `guandan`、Worker `guandan`、路径 `/games/guandan/`、存储前缀 `guandan.`、好友房的流程和按钮。
> 不做的东西：癞子、加倍、抢地主（叫分制本身就定地主）。以后要加再单独提。明牌只在娱乐开：单机娱乐和好友房的娱乐房间（第 4、5 节）。

## 1. 分层

```
src/core/                 通用层（纯函数，约束同规则核心：不碰 DOM、Date、Math.random），不引用任何玩法
  rng.ts                  带种子、按用途分流的随机数
  cards.ts                牌的编码（0..107，一副牌就是 0..53）、点数、花色、王
  seats.ts                n 人座位环
  play.ts                 牌型识别框架：一手牌的通用形状 Play 和 PatternSet 接口（interpret / beats / enumerate / choose），
                          "选中的牌 → 候选读法 → 首出让人挑、跟牌取压得上的"这套流程两个玩法共用
  stake.ts                实盘档位表（两个玩法同一套，钱包只认 small / mid / big / lux）
src/variants/guandan/     掼蛋：core、ai、net、stake
src/variants/doudizhu/    斗地主：core（patterns、game）、ai（hand 拆牌、search 残局、decide）、net（rules 房间规则、match 匹配档位）、stake
src/net/hall.ts           牌馆的房间规则：一个 kit RoomGame 按状态里的 variant 转给掼蛋或斗地主
src/view/                 画面层两个玩法共用：手牌、出牌区、座位、按钮、弹窗、牌面、音效、kit 的互动和聊天
```

- 玩法之间互不引用，通用层不引用任何 `variants/*`；`tests/architecture.test.ts` 守着，纯度约束覆盖 `variants/*/core|ai|stake`。
- 出牌轮转没有抽成通用的：两个玩法的接风、结束条件差得多，各写在自己的 `game.ts` 里比加钩子简单。
- 画面没有抽"玩法接口"，抽的是流程骨架：两个牌桌场景（`TableScene`、`DdzScene`）继承 `scenes/shared/TableSceneBase.ts`（弹层、电脑计时、联机帧泵、倒计时、结算页等人、坐标换算这些两边做法一样的部分；归通用层，不引用任何玩法，架构测试守着），玩法特有的流程留在各自场景和会话（`DdzSession`）里，复用手牌、出牌区、座位等部件；手牌由玩法给"怎么理牌"（`HandOrder`，不给就是掼蛋原样），出牌区由玩法给"一手牌怎么写"（`DescribePlay`，必传）。

## 3. 斗地主的规则核心

要点（细节和取舍见 `docs/rules.md`）：一副 54 张、3 人各 17 张、3 张底牌；叫 1 / 2 / 3 分，叫 3 分立刻结束；三家都不叫重发，连续 3 副都没人叫，第 4 副先叫的人以 1 分当地主。
一副的分 `s = 叫分 × 2^k`（k = 炸弹 + 王炸 + 春天 / 反春），地主赢 +2s、农民各 −s，反之相反，三家和恒为 0。

- 选项 `DdzOptions { deals, dealCap, cap, mingpai?, noShuffle? }`：一场几副、每副封顶、一场累计封顶（到了就结束，最后那副截的是 `s`，仍然零和）、明牌玩法（默认关，规则见 `docs/rules.md` 的"明牌"）、不洗牌玩法（默认关，见下）。娱乐是 `DDZ_FUN`（6 副、不封顶、不明牌）。
- 不洗牌（`noShuffle`，叠在娱乐上的是 `DDZ_NOSHUFFLE`：成团发牌、每副封顶 48 分）：只换发牌，叫分、出牌、结算一条不改；电脑看到视图里的 `noShuffle` 会更舍得炸（`docs/ai.md` 斗地主一节）。`clumpDeck` 把牌按点数排好，切 3 刀、随手换 6 对，再按 3–5 张一叠轮着发（流 `ddz-clump`）：单机按种子、第几副、重发次数分（`rngFor`），好友房按房间密钥（`clumpRng` 包一层 `stream(key, 'ddz-clump', …).below`，看得见的牌推不出后面的牌）。
  被每副封顶截了的那副记 `capped`（经典玩法照旧只记一场封顶）。视图带 `noShuffle: true`，经典玩法没有这个字段。
  量过的数：三家手里平均每副 2.30 个炸弹（含王炸；经典洗牌 0.59），没有炸弹的副 7.8%（经典 52%）。
  `ddz-stake-sim --fun --time --noshuffle` 对比 `--fun --time`，普通玩家对两个新手：一局中位 7.2 分钟（经典 8.3），超 2 分钟的一手 0.9%（经典 3.3%），胜率 82% 对 78%；6 副里至少碰一次封顶的局 23%，小白乱炸时 35%。三家都是普通档电脑时，电脑攥着炸弹不爱出，每副只炸 0.73 次，很少碰封顶。
  单机娱乐开局时页面另传 `DDZ_FUN_OPTS`（`src/view/doudizhu/session.ts`，`mingpai: true`）；每日挑战、实盘不开；好友房的娱乐房间一律开（`src/variants/doudizhu/net/rules.ts`）。
  明牌只在娱乐：实盘每档的电脑、每场期望（`docs/stake-ddz.md` 第 2–3 节）按不明牌配平，明牌让倍数翻倍，原来的配平就不成立。不洗牌的实盘（0.39.0）单配了一套数（规则版本 3：每分 1/200、每副封顶 48，豪华档电脑换普通 + 高手，`docs/stake-ddz.md` 第 5 节）。
  每日挑战两样都不开：比的是全服同一副牌的累计分，开了它们一副的分能差出几倍，榜上比的就成了开没开，而不是打得好不好。
- 规则版本 `DDZ_RULES`（现在是 1），和掼蛋的分开记；存档、房间按它认旧局。
- 发牌：单机按种子派生；联机按房间的 256 位熵 `stream(key, 'deal', 第几副 × 4 + 第几次重发)`，同一副重发也不重复。
- 测试：`ddz-patterns`（每种牌型的边界）、`ddz-game`（回放确定性、零和、`viewDdz` 不泄漏手牌和未翻开的底牌）、`ddz-bots`（随机机器人大批量无非法动作、无死锁）、`ddz-mingpai`（明牌：关着时整局哈希和加明牌前逐位相同、倍数、超时、视图公开与防泄漏、电脑亮牌、整局无非法动作）、`ddz-noshuffle`（不洗牌：成团发牌是一个排列、同种子同结果、炸弹数在 2–3 之间、整局打完零和、截了才记 `capped`、经典玩法不记）。

## 4. 画面

- 三人桌：0 我（下）、1 老周（右，下家）、2 王姐（左，上家），锚点 `table/layout.ts` 的 `seatAnchors3`（两侧座位上提，让开地主标记和气泡）。
- 叫分时按钮区换成"不叫 / 1 分 / 2 分 / 3 分"（比当前低的灰掉，让开"理牌"），状态行按 `decideDdz(视图, 'normal')` 写一句"这手牌建议叫 X 分"（只是建议）；顶上写底分、倍数和底牌（叫完才翻开）。
- 明牌（单机娱乐和好友房的娱乐房间，快速匹配的娱乐桌同样）：地主拿到底牌后按钮区换成"不明牌 / 明牌 ×2"（控件 `show:0` / `show:1`），电脑当地主时写"某某在想要不要明牌"。明了牌出大字"明牌"、顶栏倍数跟着翻；
  电脑地主的手牌摊在地主头像下面（和残局摊开农民的牌同一个 `drawOpenHands`，一排最长 400，20 张时挤紧一点；左家让开"互动"按钮），每出一手重画；结算页的说明多"明牌"一项。玩法说明"算分"页有一句。
- 记牌器（`src/view/doudizhu/counter.ts` 的 `countLeftDdz`，设置里和掼蛋共用同一个开关）：出牌阶段顶栏下面居中一排，大王、小王、2、A……3 各还有几张没露面，出完的变淡、剩 4 张标红，点一下收成小签。只用自己的手牌和视图里公开的已出牌、底牌；底牌翻开后三家都算已露面（地主的在手牌里）。好友房实盘条在右边时记牌器往左让。
- 主页：标题"牌馆"，下面"掼蛋 / 斗地主"切换，上次选的玩法存 `guandan.variant`（没有就是掼蛋）。
- 斗地主的玩法说明只有一份：文字在 `src/view/doudizhu/rules.ts`（牌型 / 叫分 / 算分三页），牌型图示用 `ui/patterns.ts` 的 `DDZ_PATTERNS`，由 `openDdzRules` 打开；牌桌右上的"规则"和主页右上的"规则"（当前玩法是斗地主时）共用它，掼蛋的主页仍是掼蛋的规则。改规则要一起改这里和 `docs/rules.md`。
- 新手引导：第一次进单机娱乐牌桌，发完牌弹 4 步（先叫分 → 地主先出 → 出牌 / 提示 / 不要 → 分怎么来），外壳与掼蛋共用；看过记在 `guandan.ddz.tutorial`（只在本机，不进云同步）。好友房、实盘、每日挑战、托管和带 `seed` 的调试开局不弹。
- 冒烟：`npm run shot -- --only ddz`（引导、单机一整场和每日挑战）、`npm run stake-smoke -- --ddz-only`（单机实盘，加 `--clump` 走不洗牌、核对余额按 1/200 变）、`npm run stake-smoke -- --ddz-room`（好友房实盘）、`npm run online-smoke -- --ddz`（加 `--clump` 开不洗牌房间）。

## 6. 残局闯关

规则核心在 `src/variants/doudizhu/puzzles/`（纯函数，不碰画面；画面另接）。玩法：明牌残局，三家手牌全部公开，玩家是地主（0 号座位）先出，两家农民用最优应对，地主在任何应对下都先出完才算过关。只在娱乐，不接实盘：每关手牌固定、必胜的出法是求解器算定的，答案能背、能抄，接实盘就是稳赚（每日残局同理，全服同一道）。

- **关卡**：`puzzles.ts` 的 `DDZ_PUZZLES` 共 20 关（`p01`…`p20`），每关有名字、一句不剧透的提示、三家手牌。手牌用易读的写法（`'BJ SJ 2 2 A 10 7h'`：点数加可选花色，没写花色的由 `parseCards` 补），每家 ≤ 10 张、整关不重复。由易到难：前几关 2–3 手（留大牌压轴、拆三张、飞机带翅膀），中间加"不要"、炸弹和对方的炸弹，最后几关三家各 9–10 张，要出 5–6 手。
- **怎么保证有解**：题目是离线随机发牌、用求解器筛出"必胜但容易走错"的，表里只留结果；`tests/ddz/ddz-puzzles.test.ts` 对每一关跑求解器，必须 `win`，并用 `hint` 一路打到地主出完。改牌或改求解器后重跑它；加新关时先用 `solve` 和 `rootMoves`（必胜出法占的比例越小越难）验过。
- **求解器**（`solver.ts`）：极小极大 + 记忆化（键 = 三家手牌的点数 + 要压的牌 + 轮到谁，每个局面记"几手内能赢"的上下界）。两家农民当成一方：只要有一个应对让地主输，地主就输；地主要找一手使所有应对都赢。着法按点数组合对每家手牌全部子集用 `interpretDdz` 枚举（带牌是全枚举，不像 `enumerateDdz` 只给最小带法，否则农民少了应对，"必胜"就是假的），出牌合法性用 `chooseDdz`，"不要"和清空一轮的轮转与 `dispatchDdz` 一致。地主也能"不要"，有的关必须让一手才赢。测试里和 `dispatchDdz` 对拍（所有子集的合法性、小牌局和暴力搜索的结论）。
- **农民怎么应对**：`bestReply(状态)` 给农民的动作（确定性，同一局面同一答案）。能出完就出完；有让地主输的应对就选"最像人"的；地主已必胜时选让他要出最多手的（拖得最久）。"像人" = 不浪费炸弹、能压就压、用最小的牌压、尽量多出张数，"不要"排最后。
- **接入画面**：`puzzleState(p)` 造一个 `dispatchDdz` 能直接推进的出牌阶段状态（地主 0 号、底牌空、叫分 1，`deals: 2` 所以打完落在 `dealEnd`）；玩家的动作和农民的 `bestReply` 都走 `dispatchDdz`。`hint(状态)` 给玩家提示（最少手数的必胜着法，已走错则回 `null`）。求解最慢一关冷启动约 1 秒（之后同一关有缓存），画面在进关时先 `solve` 一次预热。

画面（`src/view/doudizhu/puzzle.ts`、`ui/puzzles.ts`、`DdzScene` 的残局分支）：

- **入口和选关**：主页斗地主面板的战绩条右边，"残局"（控件 `puzzles`）和"每日挑战"并排，单独部署也有（不用平台）。点开是选关弹窗：顶上一张"今日残局"大卡（控件 `puzzle:daily`，见下面"每日残局"），下面 20 格七列三行（控件 `puzzle:p01`…），过了的绿底打勾，下一关金底，锁着的灰底画锁、点不了。开放规则：第一关总是开放，其余只开放"已过关卡的下一关"，过了的关可以重玩。选关弹窗也在过关 / 失败后的"选关"里用。
- **会话**：`PuzzleSession` 继承 `DdzSession`，从 `puzzleState` 开局，进关先 `solve` 预热；我的动作和农民的动作都走 `dispatchDdz`，农民用 `bestReply`（不用普通电脑），不存档、不记战绩、不计成就。地主先出完才在 `guandan.ddz.puzzles`（`{ v: 1, done: id[] }`，坏数据当空，只在本机）记一笔。
- **牌桌**：顶栏写"残局 第 n 关 · 关名"，右上多一个"重来"图标（`puzzle:restart`）；顶栏下方一条小横幅写关卡提示。两家农民的手牌摊开，画成宽 44、间距 26 的一排牌，摆在各自头像和名牌下面（右家右端对齐头像外沿，左家左端对齐头像外沿但不小于 x=130，让开我的头像和"地主"牌子），牌排中心在头像中心下 118（上沿在名牌下面，下沿比操作按钮上沿高约 20），不压出牌区和按钮；每次出牌后重画。不画记牌器，不开牌桌互动，电脑不说话，不弹新手引导、不报好友动态。
- **提示**：残局里"提示"按钮用 `hint()`，直接选中必胜着法的牌（必胜着法是"不要"就说明一句）；走错了（回 `null`）提示"这步之后已经赢不了了，重来试试"。
- **结果**：地主先出完弹"过关！"，带"下一关"（最后一关换成"重来"）和"选关"；农民先出完弹"农民先跑了"，带"重来"和"选关"。弹窗大字用正文字体（标题字体的字表里没有"关、农、民、跑、残"）。
- 测试：`tests/ddz/ddz-puzzle-session.test.ts`（用提示一路打能过关并记进度、农民走 `bestReply`、坏存储容错、解锁规则）。

### 每日残局

每天全服同一道自动生成的明牌残局，一分钟左右一题，按用时上每日榜，打完能分享。

- **生成**（`puzzles/daily.ts` 的 `dailyPuzzle(date)`，纯函数，只看北京时间日期字符串，随机只用 `rngFor('ddz-pz-daily', 日期, 第几次)`）：发一副小手牌，用 `withBudget` 限制搜索节点（`DAILY_BUDGET`）求解，留下"地主必胜、必胜首出占全部首出的比例 ≤ 50%、最少手数 ≥ 3"的；不满足就换下一个子种子（最多 400 次），所以结果和日期一一对应。
  牌数比原定的地主 6–9、农民 5–8 张收紧成**地主 6–7、农民各 5 张**，点数只取连续的 5 个（3..A 里随机一段，2 和两张王各一半机会加入）：求解的节点数随牌数爆炸，整副里随便抽牌，满足条件的题只有百分之几、多半算不完。
  浏览器里按日期缓存，第一次打开选关弹窗时现算；`tests/ddz/ddz-daily-puzzle.test.ts` 扫 60 天并打印最慢和平均耗时（本机约 0.1 秒平均，最慢零点几秒；中等手机按 4 倍估，目标最慢 ≤ 1.5 秒）。
  每天一个四字名字（前缀表 × 后缀表，按种子拼，如"连环飞机"）和一句提示（按这题的特点从模板选：有王炸、炸弹、对方有炸弹、三张、对子、手数多等，不剧透出法）。
- **会话**（`doudizhu/puzzle.ts` 的 `DailyPuzzleSession`，继承 `PuzzleSession`）：计时从第一手出牌开始，到地主出完为止；"重来"（顶栏图标、失败弹窗）计时不清零、重来次数加一；过关后"再打一次"是全新的一场。提示按钮每用一次（得到必胜着法时）记一次。
- **计分**（`daily.ts` 的 `dailyPuzzleScore`）：`max(10, 600 − 秒数 − 30 × 重来次数 − 60 × 提示次数)`，越高越好。
- **榜**：打完交到平台每日榜 `daily-<日期>-ddzpz`（`dailyBoard(date, 'ddzpz')`，子榜 `ddzpz`，平台登记名"斗地主残局"；`public/daily.json` 的 `ddzpz` 写显示：`{n} 分`，说明"今天的残局，越快越高"）。平台按每人取最好的一次，所以可以重打；单独部署（`standalone()`）时不交分，照样能玩。
- **本机记录**：`guandan.ddz.dailyPuzzle`（`{ v: 1, date, best, tries }`，`store.ts`）记今天的最好分和打完了几次，换一天就从头记，坏数据当没打过；选关弹窗的今日大卡写"今天最好 n 分"。
- **画面**：入口只在选关弹窗顶上（主页不加按钮）；牌桌顶栏写"今日残局 · 题名 · 用时 mm:ss"，每秒刷新；过关弹窗"过关！"加用时、分数的数字滚动（`anim=0` 时直接到终值），配过关音效和彩带，下面是交分结果一行，按钮"选关 / 分享 / 再打一次"（控件 `puzzle:pick` / `share` / `puzzle:retry`）。分享卡（`share-card.ts` 的 `dailyPuzzleCard`）写日期、题名、用时、分数、重来和提示次数，不画手牌。全部用正文字体，不碰标题字体的字表。
