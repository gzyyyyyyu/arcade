# 弹里个弹：数值和配平

> 规则里的数都在代码里一处（文件见各条），这里写现在的值、模拟器（`scripts/sim.ts`）跑出来的结果和调出来的过程。
> 设计目标见 [DESIGN.md](../DESIGN.md) 2.6、第 3 节；改了数值或电脑，照第 2 节跑一遍，把结果更新到这里。

## 1. 规则里的数

- 世界 3000×780，地形网格每格 4×4（`core/terrain.ts`）；格子存材质，地图自带的坑和井口边上的格子打个"焦"标记（画坑边用；武器的坑不打，焦痕另画）。悬空的地断开以后不塌落。
- 炮弹：位置、速度以 1/1024 单位存，每帧 `vx += 风 × 6`、`vy += 256`（`core/physics.ts`）；力度 1 点 = 初速度 256，满力 45° 大约打 2500 远。每帧的位移切成不超过 2 单位的小段查碰撞。
- 地图（`core/mapData.ts`、`core/mapData2.ts`）：11 张，画本都薄，每块地有材质（材质码写进格子低 7 位，规则上都一样；50 种，1–50 号）。
  寿司长台 3600 宽（别的 3000），远景烘焙（地图宽 + 1400）、镜头、全图、缩略图、出生点的间距都按地图宽算。
- 出生点：每张图一张候选表（只写 x，至少 10 个：前五张 11 个、早餐吐司桥 10 个；脚下都厚 80 以上），开局用 `open` 洗牌、两队交错挑，离对手至少"地图宽 ÷ (人数 + 1)"、离队友至少 240（`core/rules.ts` 的 `pickSpawns`，算法见 DESIGN.md 第 3 节）；开局朝着最近的对手。
- 武器（`core/weapons.ts`）：8 把，攻、防、爆炸范围、角度照 DESIGN.md 2.6；爆炸范围三档：小（伤害半径 22、挖 19）、中（30、26）、大（40、35），挖坑照包子蒸笼的比例。
  特技还没做。基础伤害是调平用的（设计表里没有）：包子 36、西瓜 31、球拍 39、萝卜 36、烟花 36、拖鞋 68、飞盘 38、奶茶 34，见第 4 节。
- 爆炸：以命中点为坑心、按这把武器的坑形挖（`core/craters.ts`，整数运算，只扫 ≈1.3 倍挖坑半径的方框；坑形固定，不随方向转）：
  包子圆、西瓜又宽又平的椭圆、球拍 2 格一块的网格方块、萝卜又窄又深的竖坑、烟花六角星、拖鞋鞋底印、飞盘扁长浅槽、奶茶圆坑带一道往下的流痕。
  直接打中人时坑心放在他身子中间，坑一定挖到他脚下。伤害 = 基础 × (70 + 5 × 攻)/100 × (100 − 3 × 对方防)/100 × 距离衰减（到半径边上一半）× 道具倍率，整数，按圆形的伤害半径算，不跟坑形走。
  命中不推人：脚下的地被挖空了就往下掉，掉出画本只靠挖。
- 体力：每回合 100，爬和道具共用（`core/rules.ts`）。爬一步 4（一格）扣 2，往上每 2 单位高差多 1，一步最多上下 12；前面是空的就停住。
- 血量上限 180（`core/rules.ts` 的 `MAX_HP`）。
- 道具（`core/items.ts`）：常用道具一回合能选多个、同一个能选多次，只看体力；三岔、加力 50% 一回合最多 1 个（规则里显式校验）；纸飞机独占。
  轮数不另设上限（体力决定，100 体力最多 7 轮：三个 +2），规则里只留防异常的 10 轮。
  轮数 = 1 + 连发数（+1 算 1、+2 算 2），选了三岔每轮 3 颗；每颗伤害按总轮数取（1–10 轮：100 / 54 / 37 / 29 / 23 / 20 / 17 / 15 / 14 / 13%），三岔每颗再乘 35%，
  加力相加后乘到每一颗上（向下取整的万分比）。一手不止 1 颗时每颗的挖坑半径打 98 折（取整：包子 26 → 25、西瓜 35 → 34、拖鞋 19 → 18），伤害半径不变。
  价钱：连发 +1 18、+2 30、三岔 52，加力 10% 16、20% 30、50% 72（加力 50% + 20% 是 102，买不起）；特殊道具纸飞机 60（每局不限次数）、锅盖 30（每局 2 次）。三岔 + 连发 +1 + 连发 +2 正好 100。
  一轮一轮来（前一轮的坑、掉落会影响后一轮，自己出局了就不再扔）；三岔一轮三颗（角度 −6°、0、+6°，夹在 0–90°）同时飞、按落地先后炸（一样快按角度从小到大）。
  地形一手只复制一次，每颗在这份上挖。
  纸飞机落地不炸、人瞬移到落点上方第一个站得下的地方，撞到人就落在他旁边最近的空位，飞出画本作废；不能和别的道具一起用。
- 掉落：脚下（中间和左右各 3）都没地就往下掉；摔超过 60 每 10 扣 1、最多 20；掉到底边或出了左右边就出局。
- 对阵：两队各 1–3 人（`setupError` 检查），座位顺序就是开局设置里 players 的顺序（蓝队我、队友，再黄队）。
- 出手和轮：两队交替出手、队内按座位轮，出局的跳过；还活着的每个人都出过一次手算一轮（人少的那队一轮里有人出手两次），打满 15 轮按全队剩余血量总和定胜负（`MAX_ROUNDS`；开局设置的 `maxRounds` 只给模拟器用）。
  `turn` 是第几次出手（风和电脑的随机流按它取），`round` 是第几轮，顶栏写"第 N 轮 / 15"。
- 电脑（`ai/index.ts`）：只朝对手那边打；伤到自己扣 1.5 倍、伤到队友扣 2 倍。每位电脑人物偏好的武器见 `ai/personas.ts`（也是准备房间里电脑座位的默认武器）。
- 准备房间（`room.ts`）：同一只小动物一局只上一次（我和五个电脑座位互不相同，换成在场的那只就对调）。默认阵容两队均衡（各有一把大范围的武器），见 `room.ts` 的 `defaultRoom`；1v1、2v2 按座位顺序截。
- 好友房一手的动画停顿（`net/anim.ts`）：炮弹飞行按 1.6 倍时长放（`FLIGHT_SLOW_PCT`，多出来的最多 1 秒：`FLIGHT_EXTRA_MAX`）；一手连扔好几轮时从第 3 轮起放快（3 倍，往后每轮翻一倍：`volleyPace`）。

## 2. 模拟器怎么跑

电脑对电脑打 N 局（种子 0..N−1），同一套代码、同一组参数，结果逐格一样。改了数值（`core/weapons.ts`、`core/items.ts`、`core/rules.ts` 的常量、`core/physics.ts` 的重力风力、`core/maps.ts` 的地形和出生点）或电脑，跑这一组：

```bash
npm run sim 100 ab          # 1v1 厨房面团岛，各道具"会用"对"禁用"的胜率
npm run sim 100 2v2
npm run sim 100 3v3
npm run sim 16 weapons      # 8 把武器两两 1v1 对打（加 map:all 换成 11 张图轮着打）
npm run sim 50 1v1 map:all  # 11 张图各打一遍
npm run sim 30 3v3 map:all
npm run sim 100 3v3 room    # 准备房间的默认阵容
npm run sim 100 online      # 好友房的联机档电脑对单机档
```

其余选项（`mix`、`cap:N`、`map:<id>`、`ab:<道具>`）见 `scripts/sim.ts` 开头的注释。每格只有 30–100 局，两队胜率差两成以内都是噪声。

## 3. 结论

- 常用道具：单项"用对不用"胜率 47%–57%，都在目标 47%–65% 里；最常用的叠法"连发 +1 + 加力 50%"占三成，其余都在 15% 以下。
- 一局长短和掉出画本：1v1 平均约 10.4 轮、掉出画本约三成；3v3 约 12.5 轮、掉出画本约六成。
- 11 张图：除了寿司长台（慢图）都在新图的目标里（1v1 掉出画本 20%–60%、平均 ≥ 6.5 轮，3v3 ≤ 85%）；便当群岛最快。
- 8 把武器 11 张图轮着打，平均胜率 40%–60%（西瓜、飞盘压线）。
- 好友房的联机档电脑比单机档弱（1v1 胜率两成多），想一手不到 1 ms；服务器每一步 p99 在 3 ms 预算以内（第 5 节）。

## 5. 好友房的时长和服务器 CPU

**一手的动画停顿**（`net/anim.ts`，3v3 房间默认阵容 6 张图各 20 局、7157 手）：中位 9.3 秒、九成九 16.8 秒、最长 19.7 秒（三岔 + 连发 +1 + 连发 +2 满力往上打），`test/net.test.ts` 卡住不超过 20 秒。
一发典型炮弹（中位 96 步）规则里 1.6 秒，画面上 2.56 秒；九成以内 158 步，2.63 秒 → 3.63 秒。
飞行放慢以前是中位 8.1 秒、九成九 15.7 秒、最长 19.6 秒；放慢以后照原来的放快倍数（第 n 轮 n − 1 倍）最长一手要 26.5 秒，所以改成第 3 轮 3 倍、往后每轮翻一倍，高抛多出来的封顶 1 秒。

**服务器每一步的 CPU**（`npm run cpu`，真的 kit 房间、3 个真人对 3 个电脑、11 张图各一局；同一局原样打 3 遍，每一步取最快的一遍，开发机 Node）：

| 局面 | 真人出手 p50 / p99 | 电脑一步（想 + 结算）p50 / p99 |
|---|---|---|
| 典型（房间在内存里） | 0.35 / 0.52 ms | 0.76 / 1.47 ms |
| 最坏（每一步前都被驱逐、从存储重建；真人每手都上买得起的最重叠法：三岔 + 连发 +1 + 连发 +2（4 轮 12 颗）和三个 +2（7 轮）轮流，能爬就爬） | 0.76 / 1.36 ms | 1.06 / 1.97 ms |
| 其中最宽的寿司长台，最坏 | 0.95 / 1.36 ms | 1.39 / 2.09 ms |

- 预算是每一步 p99 ≤ 3 ms（免费版每次请求 10 ms）；有环境变量 `CI` 时（GitHub 的共享机器）放宽到 8 ms。一步里包括读状态、规则、存一行、给每个人发视图；
- 只打一遍、直接看墙上的钟时，开发机上别的进程抢 CPU，偶尔一步能到 5–7 ms，所以取 3 遍里最快的；vitest 里跑会慢一倍（转译过的模块多绕一层），所以用普通 Node 跑；
- 挖坑先是逐格调坑形函数（烟花的星形每格建一遍多边形），驱逐重建的那一步 p50 到了 2.7 ms、p99 5 ms，没过预算；
  改成每种"坑形 × 大小 × 坑心在格子里的位置"第一次挖时算出占哪些格、记下来（`core/terrain.ts` 的 `craterMask`），以后照着挖，回到上表；
- 电脑在心里试炮弹（`core/physics.ts` 的 `simulate`）改快了：同样的结果（6 张图 18 局逐手比过事件），单机电脑一手快三成多；一手里地形只复制一次（每颗在同一份上挖）。
