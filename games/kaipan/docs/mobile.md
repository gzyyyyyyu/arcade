# 手机和平板

电脑按 1280×720 的世界布局。手机和触屏平板换一套「手机世界」，字号、点击区按渲染到屏幕上的实际像素定。
验收标准：正文 ≥ 12 像素、数字 ≥ 14、可点的 ≥ 44（都是屏幕上的 CSS 像素）。

## 什么时候用手机布局（`theme.ts` 的 `pickPhoneLayout`）

- 短边不超过 500 的横屏，或短边不超过 500 的触屏竖屏（微信里点开链接默认竖屏，先看到转屏提示，转过来铺满的是手机版）；
- 触屏平板：电脑布局缩到这块屏上 11 号字到不了 12 像素（1024×768、1180×820 都是这样），也用手机布局，不看方向；
- URL 参数 `layout=phone` / `layout=desktop` 强制。

开局时定一次，中途改窗口、转屏都不换布局（转屏只是同一块画布换方向铺满）。

## 世界尺寸和最小字号

- 世界高固定 404，宽 = 404 × 屏幕长边 ÷ 短边，取偶数，限制在 718–960（`phoneWorld`）。iPhone SE（667×375）是 718×404（0.93 倍），
  844×390 是 874×404（0.97 倍）；更长的屏宽封顶 960，更方的屏宽取 718，多出来的部分由 EXPAND 补背景。
- `PHONE_SCALE` 是手机世界铺到屏幕上的倍数（平板在 1.4 以上）。比 SE 还矮的屏（640×360、780×360 约 0.89，568×320 约 0.79）按它抬下限：
  正文最小 `max(13, ⌈12 ÷ 倍数⌉)`（`ui/text.ts` 的 `MIN_TEXT_SIZE`），数字最小 `max(16, ⌈14 ÷ 倍数⌉)`（`MIN_NUM_SIZE_PHONE`，
  只有数字的文字没标 `num` 也按数字算），点击区最小 `max(50, ⌈44 ÷ 倍数⌉)`（`ui/button.ts` 的 `HIT_MIN`）。
- 场景声明 `phoneReady` 才按手机世界布局（`viewport.ts`）；没声明的（只有启动页）按电脑布局整体缩小放进来。

## 竖着拿（`src/platform/orientation.ts`）

触屏设备（`(orientation: portrait) and (pointer: coarse)`）竖着拿时盖一层 DOM 提示「把屏幕横过来」，手机和平板都提示；
提示层左上角也有「大厅」（按 safe-area 让出刘海），一局进行中先问一次。提示里写明原因（看板、持仓、群聊要排一排，竖着只能缩得很小），
并有「照样玩」：点了收起提示层，画布本来就按看得见的区域铺（EXPAND），横屏的画面缩小居中放在里面（字很小，只是让人能先看一眼或打完一局）；
转回横屏时提示层不显示，同时清掉这个标记，下次再竖过来仍先提示。标记只是提示层上的一个 class，不写存储。

## 主页（`meta/homeGeo.ts` 的 `phoneHome`）

- 要点的都在下半屏一排（高 112）：右下是大卡（继续 / 快速开始，宽 = 世界宽 × 0.42，300–404；有 4 张模式卡时收窄到 × 0.34，244–340），左边是模式卡（每日挑战、闪电盘、实盘、新一局，单独部署没有实盘；4 张时每张不窄于 100）；
  有没打完的局时大卡是「继续」，快速开始挪到大卡正上方。上半屏是 Logo、一句玩法和主视觉（按 0.62 缩，小人的脚踩在卡片上沿）。
- 版本号在右上角小入口下面。

## 弹窗和结束页

- 整屏弹窗统一按 `ui/dialog.ts` 的 `phonePanel`：宽 = min(940, 世界宽 − 16)，高 = min(430, 世界高 − 12)，SE 上 702×392。
- 结束页纸卡也是这个大小；右栏战绩格一格不到 140 宽时竖排（`meta/bits.ts` 的 `statTile` 的 `stacked`），金额用短写法，月份轨道一格的间距按宽度算。
  左上「大厅」和头像、徽章、标签之间留出间距（头像一行往右让 112），标题往下让一点；标题下的说明按逗号分行（`EndScene.ts` 的 `clauseWrap`），
  不在句子中间硬折，不留单字孤行；底部按钮离纸卡下沿 64（`btnBottom`）。「收获」一行的图标格高 44，月份轨道的深色条顶在它下面至少 6，不压住图标（手机、电脑都一样）。
- 实盘开局的档位卡在手机上排三行，一万以上的筹码写成「万」，不截断。

## 交易页（`trade/layout.ts` 的 `mobileLayout`）

- 右边群聊 / 风口一块宽 = 世界宽 × 0.355（256–338），左边是持仓（高 214），下面是小结和开盘键（开盘键宽 140）。
- 顶栏（`trade/topBarGeo.ts`）：设置、怎么玩、银行贴右边；中间按「要还的钱 → 账户 → 日期」的顺序让宽度，还不够就收道具栏（放不下的进「+N」；没有道具时不画占位）。「开盘」键的副标写短（「第9天·冲刺」「3月·第5天」），键的主字 24，副标不缩到 12 以下。
- 持仓卡在 SE 上约 104 宽：小人、走势框收窄，「跑赢 / 跑输」挪进悬停，累计那条放不下就只写数字，热度和连涨签放不下就只留连涨签。
- 持仓卡的「卖出」一步全卖，右边的小按钮「加减」（44 宽）打开加仓 / 减一半；两个按钮的点击区都按 `HIT_MIN` 撑到不小于 44 像素（往下撑，不盖住卡片）。
- 紧挨着的按钮，点击区撑开时不越过邻居：顶栏「怎么玩」「设置」相邻的那一边不撑（`Button` 的 `hitPadX`）；银行「押给银行」的点击区上下撑满行距、和邻行只贴边：手机矮屏（世界高 404）上按钮行最多 4 行（4 件抵押品），空着的那段只占 28 高的占位，两段小标题各 20 高，行距按 44 像素反算（844×390 上 46，点击区约 44×108）。`hitPad` 在所有 `HIT_MIN > 0` 的触屏设备（手机、省内存平板）上生效，电脑不撑（`usesHitPad`）。
- 选格子时的提示条（「放进哪一格？」）压在顶栏那一行上，左端让到回大厅右边（窄屏居中会盖住回大厅，看不见还点得到），右边放不下就往左收、再缩字。推荐卡可以拖进空格买、持仓卡拖出持仓区卖（拖拽见 `art-v3.md` 4.1）。
- 小结一枚至少 96 宽，放不下的几只点「详情」看；更窄时不放头像。
- 推荐在「推荐」页签里，按数字键买的时候自动切过去。「群聊」页里，推荐人今天有没买的推荐的那条消息，气泡下沿挂一枚「买 ›」小签，点这条消息就买（文字短、同一行放得下时小签在气泡内靠右；放不下就在气泡下沿多留一行，不盖字，算法在 `buyTagLayout.ts`）
  （走 `onBuy`，和推荐卡「买入」同一条路径：有仓位玩法时先选买多少，满仓时先选换哪一格），不用切页签。
- 昨日回顾卡（`trade/recapCard.ts`）和猫的提示共用左下角：卡出现 7 秒后收成右下角一枚 92×44 的角标（图标加涨跌百分比），不再盖着现金格和市场屏；
  点角标展开（展开后不再自动收），收起时猫的提示露出来。展开着看「详情」时不收。电脑上小结不自动收，但默认就是一行（总账一句 + 「详情」），猫有话时同样挂小猫，一次只露一个。
- 抽新股横条（`chat.ts` 的 `addIpoBanner`，申购日盘前）是群聊页最上面一条，高 44（触屏点区够大）；推荐页上没有它，控件 `ipo` 只在群聊页出现。
  申购面板和「买多少」一样是居中弹窗（560×330）；申购中的卡和持仓卡同尺寸（SE 上约 104 宽：新股名缩放进卡宽，「冻结 N 份」缩小到 12），名字左边的「新」签让名字往右挪、必要时缩一点。
- 群聊页当天消息一条不省：字号已在手机下限，放不下时依次收昨日新闻、多日消息小签，最后把名字行、气泡内边距和条间距收紧（`chat.ts` 的 `tight` 档）；热闹元素只填剩下的空白。

## 省内存设备

iOS 和触屏设备渲染倍数封顶 2，整屏背景按 1 倍光栅化（`theme.ts` 的 `LOW_MEMORY`，原因见仓库根 `AGENTS.md` 第 4 节）。
`node tools/mem-probe.ts` 按几种视口和 DPR 估算显存；冒烟 `npm run shot -- --lowmem` 模拟一次。

## 怎么验

`npm run shot -- --phone`（改开局面板时加 `--live`）。改结束页、群聊点买、昨日回顾角标、竖屏「照样玩」时跑 `npm run shot -- --pages-a --phone`。多尺寸检查按手机横屏 568×320 到 932×430、手机竖屏（只看转屏提示）、平板竖横、
电脑 1280×720 / 1366×768 / 1920×1080 一组跑：不出屏、不互相压、字和点击区到下限、控制台零报错。

一屏放下（仓库根 `docs/ui.md` 第 11 节）：页面 `overflow: hidden`，画布按看得见的区域缩放，游戏里没有会滚动的区域，长内容用翻页（说明书、图鉴、排行）。
`npm run shot -- --noscroll` 在 1280×720、1920×1080、844×390、390×844、360×640 五个尺寸上量开始菜单和每个面板、交易页（手机三个页签）、局内设置、结束页：
页面 `scrollHeight` / `scrollWidth` 不超过视口，画布和所有按钮都在视口里；负载高时用 `--sizes=390,360` 分开跑；`--sizes=ipad` 另量省内存平板（1366×1024、iPad 的 UA，点击区最小 56），不在默认的五个尺寸里。
同一趟还量画布里的重叠和裁字（DOM 的 `scrollWidth` 量不到画布，走调试桥的 `layout()`，见 `src/debug/layout.ts`）：任意两个控件的底板、点击区不相交；文字不伸出屏幕、不伸出自己按钮的底板、不压在别的按钮上，两段文字不互相压住。
有整屏遮罩的弹窗时只量最上面那层；被不接点击的不透明层（纸面、实心底）盖住的文字看不见，不算压字，被它盖住的按钮却还点得到，单独算一处重叠。
每个按钮的点击区按页面像素量大小：触屏两边都要 ≥ 44，电脑 ≥ 32（Button 在电脑上按 32 补足，`ui/button.ts` 的 `DESK_HIT_MIN`），同一尺寸同一按钮只记一次。
有意的重叠或出框登记在 `tools/shot/modes/noscroll.ts` 的 `OVERLAP_OK` / `CLIP_OK` 里并写理由；最后输出「重叠 N 处 / 裁字 N 处 / 点击区小 N 处」和清单，有一处就算失败。
只改了几个画面时用 `--screens=title,trade,layers,month`（段名：title、trade、layers、ipo、end、month、story、challenge）只量这几段。
