# 存档和平台

《开盘》怎么存档、怎么接平台的账号、云存档、排行榜、实盘、好友挑战等功能，以及单独部署时少什么。入口见 [README](../README.md)。

## 1. 存档和平台功能

- **存档**：`kaipan.save` 存完整的局面快照和版本号（格式 5），读档直接用快照，小版本调数值后旧存档按当时的局面继续；
  更早格式的存档和 0.4 开发期的真实行情局（`state.real` 没有 `track`）接不上，读到时清掉并提示开新局。存档损坏时先备份到 `kaipan.save.corrupt`。启动时清掉早年留下的旧 key（`src/platform/storage.ts` 的 `LEGACY_KEYS`）。
- **档案**：`kaipan.profile` 和单局存档分开，记图鉴、成就、解锁和各人设、难度、每日挑战的最好成绩；损坏时备份到 `kaipan.profile.corrupt` 后重建。
- **云存档**（`src/platform/cloud.ts`，同步哪些槽在 `src/view/cloudSync.ts`）：登录后同步档案（槽 `profile`）和教程标记（槽 `tutorial`），
  打到一半的局和设置不同步。元数据在 `kaipan.cloud`，合并前的本地备份在 `kaipan.<槽>.pre-sync`；换账号时上一个账号的本地进度存在
  `kaipan.<槽>.pre-switch.<userId>`，它回来时并回去，并完改名 `.restored`。教程重新开启记一次 `reset`，合并时次数多的一边说了算。
  切回前台、上传前、收到 409 时重新确认账号；多个标签页靠 storage 事件互通。接口见总仓库 `docs/platform-backend.md`。
- **每日排行榜**（交分和读榜 `src/platform/board.ts`，一局的交分状态 `src/view/dailyBoard.ts`）：每日榜分子榜，一局结束交一次分，
  经典每日挑战交到 `daily-YYYY-MM-DD-classic`（通关分 = 1e11 + 账户元数，没通关 = 还上的月数），闪电盘交到 `daily-YYYY-MM-DD-flash`（分数 = 最终资产元数）
  （北京日期），显示规则在 `public/daily.json` 的 `boards.classic` / `boards.flash`；平台那边要在登记里写这两个子榜。
  本周市场交到周榜 `week-YYYY-Www-rules`（周号是北京时间 ISO 周，分数 = 最终资产元数，只收当周），显示规则在 `public/weekly.json` 的 `boards.rules`，平台登记里也要写这个榜。
  只有用当天冻结段池（`src/core/content/dailySegments.ts`）里那段真实行情的局才交；段池顺序和数量不随便改（改的那一天前后打的不是同一局）。
  429（限流）结束页写「成绩稍后补交」，照平台给的 retryAfter（没给按 60 秒）自动补交一次，再被限写「这局成绩没交上」；busy、wrong_user 不重试，连不上给「重试」。读榜按榜和范围缓存 45 秒，交上分时作废。
- **请求超时**（`src/platform/fetchTimeout.ts`）：排行榜、好友挑战、实盘的请求最多等 10 秒，云存档 20 秒；超时按连不上处理，走各自原来的说法和重试。
- **实盘**（设计 `design-live.md`）：规则在开局设置 `RunSetup.live` 和 `src/core/live.ts`（四档对应难度 1/2/3/3，杠杆 1× / 2× / 3×）；
  档位表和带回算法在 `src/core/liveTiers.ts`（Worker 也用）。钱包走浏览器 → 开盘 Worker（同域 `POST api/live/{buyin,settle,refund}`，`src/worker/live.ts`）
  → 服务绑定 `WALLET`；浏览器只给 `ref`、`tier`、`bp`，金额和到期时间由 Worker 定。这台设备上的账在 `kaipan.live`（`src/platform/live.ts`）：
  带入前记 `buying`，带回或放弃先记 `settling` 再发，连不上、busy 都留着重发。带回时带战绩小结（`src/core/career.ts`），称号中文名在 `public/titles.json`。
- **好友挑战**（第 5 节）：娱乐局打完、登录了，结束页「挑战好友」把种子、开局设置、行情段和版本交给平台拿链接 `?challenge=<id>`；
  好友打开先弹挑战卡，接受就是同一个开局，打完交成绩看名次。挑战局照每日挑战的规矩记档案。
- **分享卡**（第 4 节）：结束页「分享」，开盘只交数据，画卡和分享在共用包 `arcade-kit/share`；链接按当前页面推出游戏地址，代码里不写站点地址。
- **社交**：有登录提示时挂共用包 `arcade-kit/social`，报「在玩开盘」、收好友邀请。
- **回大厅**（`src/view/lobby.ts`）：跳平台首页 `/`。主页和结束页左上角的「大厅」直接走；对局里从设置走先确认一次，走之前先补传云存档
  （keepalive 额度记账在 `src/platform/keepalive.ts`）。电脑上叠了一个透明的 DOM 按钮（`src/view/ui/domProxy.ts`），读屏和自动化能点到。
  画布外的 DOM（这个影子按钮、转屏提示、出错面板、好友面板）上的按下不冒到 window（`src/main.ts`）：Phaser 会把它当成点画布，触屏上会连带点到正下方的画布按钮。
- **安全头**（`public/_headers`）：CSP、`frame-ancestors 'self'`、`X-Frame-Options: SAMEORIGIN`；经 Worker 回的首页也带上。用到新来源时同时改这里，`tests/repo/headers.test.ts` 锁底线。
- 未捕获的错误弹独立面板，可以继续、重新载入、放弃存档开新局或复制错误信息；最近 20 条错误记在 `kaipan.errors`。没人接住的报错同时经共用包 `arcade-kit/report` 发给平台 `/api/client-error`（单独部署时没有这个接口，发不出去就算了）。

单独部署（没有平台）时：有完整的单机游戏、本机的每日挑战、闪电盘和本周市场；没有登录、云存档、排行榜、好友挑战和实盘。页面启动时问一次同域 `/api/me`，
回 404 或不是 JSON 就当没有平台，把这些入口藏起来；实盘接口回 `501 no_wallet`。开盘没有好友房。

## 2. 部署

### 2.1 单独部署

开盘是一个 Cloudflare Worker（名字 `kaipan`）：静态资源加一小段 Worker 代码。`wrangler.jsonc` 是能单独部署的独立配置，不带平台绑定、`GATE`、路由和站点地址。

在本目录 `npm ci && npm run deploy`（需要环境变量 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`），或用 README 里的「Deploy to Cloudflare」按钮。
部署完用 `https://kaipan.<你的 workers.dev 子域>/` 打开，根路径会跳到 `/games/kaipan/`。

健康检查 `GET /games/kaipan/health` 回 `{"ok":true,"version":"<版本>"}`：走在登录闸门前面，不要登录、不读存储、不问平台，单独部署时一样能访问，给监控用。

### 2.2 和平台一起部署

挂在平台同一个域名的 `/games/kaipan` 下，站点主机名由部署工具注入。部署时 `tools/deployer/deploy.mjs` 在独立配置上叠加：

| 名字 | 类型 | 说明 |
|---|---|---|
| `ARCADE` | 服务绑定 → `arcade` | 登录闸门问平台 `/api/me` |
| `WALLET` | 服务绑定 → `arcade` 的 `WalletService`，`props.game = kaipan` | 实盘的带入、带回、放弃 |
| `GATE` | 变量 `login` | 登录闸门：没登录跳 `/login?from=kaipan`，平台有问题回 503 不放行 |

另外关掉 `workers_dev`、`preview_urls`，注入 `<站点>/games/kaipan` 和 `<站点>/games/kaipan/*` 两条路由。独立配置里只有 `ASSETS`，没有 secret；开着 Workers 日志（`observability`）。
写了 `GATE=login` 却没有 `ARCADE` 时首页回 503。只有根路径、首页、实盘接口 `/games/kaipan/api/*` 和健康检查进 Worker（分流在 `src/worker/route.ts`），其余静态资源不经过 Worker。

本仓库的正式站由 `.github/workflows/game-kaipan.yml` 部署：改动经 PR 合并进 `main` 后测试、打包，再由部署工具补上平台绑定和路由部署；PR 上只测试不部署。
要拆成单独仓库时，在仓库根运行 `tools/split-module.sh games/kaipan`。

## 3. 本地和平台联调

开发和预览服务监听所有网卡，同一局域网里的手机、平板可以直接打开测试（不登录，云存档、排行榜、实盘不可用）。

联调登录、云存档、排行榜、实盘：平台目录先 `npm run build` 再 `npm run dev:api`（5181），开盘 `npm run dev` 会把 `/api` 转过去；
先在 http://localhost:5181 登录，再用 http://localhost:5173 打开开盘（`__Host-` cookie 要求安全上下文，用 IP 打开时登录状态带不过来）。

## 4. 分享卡

> 社交规范（仓库根 `docs/social.md` 1.1）：游戏只交数据 `{ game, title, big: { value, label }, stats: [{ label, value }] ≤ 3, line, accent, art? }`，画法在 kit。
> 本节写开盘交什么、为什么。数据全从结束页已有的 `runSummary`（`src/core/queries.ts`）取，规则核心不改。

### 4.1 三种结算页各交什么

| | 卡片标题 `title` | 大数字 `big` | 小数据 `stats`（≤ 3 条） |
|---|---|---|---|
| 实盘 | 「实盘小档 · 2,000」 | `×3.40`，「杠杆 ×2 · 带回几倍」（1× 写「带回几倍」）；清零的局 `×0`，「杠杆 ×3 · 跌到清零线」 | 还上几个月（「5/5 个月」）、最赚的一笔（说明写股票名「韭菜芯片」，值写「↑61.5%」） |
| 娱乐 | 「短局 · 5 个月」或「完整一年」 | 资产涨跌 `28.6%`，「这局资产涨了」（跌了写「这局资产跌了」，数字不带负号） | 结果（「通关」或「撑了 3 个月」）、人设和难度（说明写「职场新人阿韭」，值写「普通」）、最赚的一笔 |
| 每日挑战 | 「每日挑战 10/15」 | 同娱乐的资产涨跌 | 今天第几名（读到名次才有，没有就换成「还上 4/12 个月」）、人设和难度、最赚的一笔 |

共用包每格的值约 6 个字宽、说明约 8 个字，所以值只放短的，名字放在说明那一行。名场面 `line` 三种都按 4.2；`player` 是平台昵称加这局的称号（`sum.title`），单独部署没有昵称就不写。

- **大数字为什么是倍数或涨跌幅，不是钱数**：三个人设的开局本钱不一样（10 万、8 万、9.4 万），钱数比不了；百分比、倍数能直接比。
  实盘用带回倍数是因为带回就是按它算的，和结算页、顶栏同一个数（含杠杆）。
- **资产涨跌** = 最后剩下 ÷ 开局本钱 − 1（`account / startAccount − 1`），一位小数，正数带 `+`。娱乐局输了也照写，不藏。
- **最赚的一笔** 用 `bestTrade`（含没卖的持仓），股票名是游戏里的化名；没赚过（没买、或者全亏）就去掉这一条，写「最赚」却是跌的不对劲。
- `title`：「开盘」；`accent`：主题橙 `COLOR.accent`；`art`：最赚那只股票小人的图（现在海报用的同一张，图集里已有）；没有就用人设头像。
- 链接：游戏地址（`gameLink`，和现在海报一样，不带参数）。每日挑战当天所有人同一局，好友点开首页的「每日挑战」就是这一局；
  不用 URL 里的 `daily=`，它是调试参数，带着开的局不计入档案。直接点开某一局留给第二期的异步挑战（`social.md` 第 2 节）。

### 4.2 名场面模板（按顺序取第一条符合的）

| # | 条件 | 模板 |
|---|---|---|
| 1 | 实盘带回 ≥ 3 倍 | 「杠杆 ×{N}，{月数} 个月带回 ×{倍数}」（1× 不写杠杆） |
| 2 | 实盘跌到清零线 | 「杠杆 ×{N}，第 {月} 个月清零」 |
| 3 | 最多连涨 ≥ 3 天（`maxBoards`） | 「连涨 {n} 天，全程坐在车上」 |
| 4 | 最赚的一笔 ≥ +50% | 「{股票}一把赚了 {涨幅}」 |
| 5 | 娱乐通关 | 「{月数} 个月的账全还上了」 |
| 6 | 其他 | 这局的打法评语 `style.line`（结束页称号下面那句，已经是按局面写的大白话） |

- 数字和名字由代码填，模板本身是固定文字，放进 `tests/repo/view-copy.test.ts` 的扫描范围（不出行话、不用 emoji）。
- 模板压在一行放得下（约 16 个字宽）：卡上给名场面加了引号、跟着折行，稍长一点就剩一个引号掉到第二行（`tests/view/share-card.test.ts` 按字宽锁住）。
- 实盘的几条照实盘结束页的规矩（设计稿 `design-live.md` 第 5 节）：不出现「回本、翻本、再来一把、就差一点、马上、限时」这类催人再赌的话；输了的局不推更高的档位。
- 不写年份、真实公司和行情段的故事（故事里的花名能对上真实年份，分享出去等于剧透这一段）。

### 4.3 实现要点

- 数据在 `src/view/shareCard.ts`，画法在 kit，开盘不自己画卡。
- iOS 只许在点击的那一下里调系统分享：结束页一出来就用 kit 的 `prepareShare` 画好，点击里直接 `share()`（前面不 await）；每日挑战读到名次后再画一张带名次的，画好才换上。
- `art` 直接交图集和切片框（`{ image, crop: { x, y, w, h }, fit }`），不另导出整图。
- 验证：`tests/view/share-card.test.ts` 按 4.2 的顺序逐条覆盖模板选择；`npm run shot` 的结束页段点一次「分享」，检查生成了图、控制台零报错。

## 5. 好友挑战

> 规范见仓库根 `docs/social.md` 第 2 节：结算页「发给好友挑战」，把这一局的种子和设置做成链接，好友打开就是同一个开局，两人的成绩挂在同一个挑战下互相看得到；
> 靠规则核心的确定性，不需要服务器重算；每个挑战一行，结果每人一行。本节写开盘要交给平台存什么、怎么开局、成绩比什么；平台接口见 `docs/platform-backend.md` 15.18。
> 代码：`src/core/challenge.ts`（payload 生成和校验、分数）、`src/platform/challenge.ts`（调平台接口）、`src/view/challenge.ts`（画面状态）。

### 5.1 「同一个开局」要带哪些东西

| 字段 | 内容 | 为什么 |
|---|---|---|
| `seed` | 这局的种子 | 规则核心的随机全从它分流出来 |
| `setup` | 这局的开局设置原样（`RunSetup`：`persona`、`difficulty`，短局还有 `short: { months, billMult, goal }`） | 人设和难度决定开局资产、账单和消息失真；短局的规则开局时已经抄进设置，跟着设置走，以后改 `BALANCE.short` 也不影响这个挑战 |
| `segment` | 这局用的行情段 id；模拟行情为 `null` | 段平时按种子哈希在段库里挑，段库加了新段，同一个种子就会挑到别的段。所以要写明是哪一段，开局时强制用它（和每日挑战用冻结段池同理） |
| `v` | 发起时的开盘版本号（`APP_VERSION`） | 账单、情报、事件这些数值不在设置里，跨版本可能变（每次改数值都会动）。版本对不上照样能打，但结果页标一句「版本不同，结果可能对不上」 |

- 整个 `payload` 是开盘自己的 JSON（约 200 字节），平台原样存、原样回，不解析。开盘读回来时自己校验：种子格式、`setup` 只许上面这几个键（`isRankedSetup` 的口径）、人设和难度合法、段 id 在段目录里。不合格就提示「这个挑战打不开」，不开局。
- **哪些局能发**：娱乐局（短局、完整一年）能发。
  - 每日挑战不用发：当天所有人本来就是同一局，已经有全站榜。
  - 实盘有意不做好友挑战，不给按钮：比的是带回倍数，挂筹码对不上。实盘的成绩连着钱包，好友那边开出来是不带筹码的局，规则也不一样（5 个月、按档放大）；硬挂上去也容易让人以为是在赌筹码。
  - 调试设置开的局（带 `account`、`items` 等）也不能发。
- **种子会不会泄露行情**：链接里有种子和段 id，懂行的人能在本地把这一局先模拟一遍。开盘的取向是「排行榜不防作弊」，这里同样不防；正常玩的人看不到这些。

### 5.2 流程

1. **发起**（结束页，娱乐局，有平台、已登录）：「分享」旁边多一个「挑战好友」。
   - 点了把 `payload` 和发起人这局的成绩（5.3）交给平台，拿回挑战 id。
   - 发起人这局要已经记进档案、交过分（不是被判无效的局），按钮才出来。
   - 链接是游戏地址加 `?challenge=<id>`，弹一个小框：「复制链接」，有系统分享时多一个「发给朋友」（点击里直接调，iOS 才认）。
2. **打开链接**：开盘启动时看到 `challenge` 参数，就向平台要这个挑战（`payload`、发起人昵称和成绩、已有结果）。
   - 先弹一张卡：「老王挑战你：职场新人阿韭 · 普通 · 短局 5 个月，他通关、剩 ¥13.2 万」，按钮是「接受挑战」和「先不了」。
   - 本机有没打完的局时，提示会顶掉它（和「新游戏」一样问一次）。
   - 平台的挑战接口都要登录（站点本来就要登录才能进游戏），所以不做「没登录也能打」。读完就把 `?challenge=` 从地址里去掉，刷新不会再弹。
   - 打不开（不存在、过期、payload 校验不过、不是开盘的挑战）一律说「这个挑战打不开了」；人满、平台在省额度、连不上各有一句。
3. **开局**：按 `seed`、`setup` 开局，行情强制用 `segment` 那一段（`segmentFor(seed, 段 id)`）。
   - 行情段下载失败时**不退回模拟行情**（那就不是同一局了），提示一句、不开局，可以再点链接重试。
   - 发起人当时是模拟行情的，这边也用模拟行情。
   - 接下的挑战记在 `kaipan.challenge`（挑战 id、种子、发起人、版本，只记最近一个）：中途关页面，回来点「继续」打完，按种子认出来照样交。
4. **打完**：结束页交成绩到这个挑战，交完写「挑战里第几名 · 共几人」，「看成绩」打开成绩表（前 50 名，我那一行标亮）。
   - 已经交过的人再打一遍，平台回「交过了」和原来那条，结束页写「之前交过，只算第一次」。
   - 交不上（连不上、平台在省额度）给「重试」，不自动重试；打不开了、人满了不给重试。
   - 交过成绩的人再打开同一个链接，直接看成绩表，不再弹挑战卡。
5. **档案**：照每日挑战的规矩记。
   - 人设、难度可以是还没解锁的，不算进解锁进度，也不占「最好成绩」。
   - 图鉴和成就照常点亮。
   - 档案按局记，不按挑战去重：同一个挑战再打一遍，图鉴、成就照常算，成绩只有第一次交给平台。

### 5.3 成绩比什么

- **分数**沿用每日挑战的 `dailyScore`，同一套设置下是公平的：
  - 通关 = `1e11 + 最后账户（元）`；
  - 没通关 = 还上了几个月。
  - 也就是先比通没通关，通关的比剩多少钱，没通关的比撑了几个月。同一个挑战人设相同、开局资产相同，直接比钱数没问题（和分享卡用比例不一样，那是跨局比）。
- **每人只算第一次打完的那一局**：链接里有种子，再打一遍等于背过了行情，不公平。想再打可以，但结果页写「只算第一次」，不再交。
- **交给平台的**：
  - `score`（整数，平台拿它排序）；
  - `stats`（成绩表显示用，开盘自己的 JSON）：`{ title, growth }`，称号和资产涨跌（千分之几）。通关与否、钱数、月数都能从 `score` 读出来，不重复交。
  - 这些只是展示，平台不解析；读别人的按白名单校验，不合格的整份不用。
- **平台排序的规矩**：分数高的在前，同分先交的在前。

### 5.4 平台接口（总仓库 `docs/platform-backend.md` 15.18）

开盘直接调（不经共用包），写请求带 `X-Arcade: 1`：

| 动作 | 开盘传 | 开盘要回 |
|---|---|---|
| 发起 `POST /api/challenges` | `game: 'kaipan'`、`payload`（5.1）、发起人的 `score` 和 `stats` | `id`、`until` |
| 打开 `GET /api/challenges/<id>` | — | `game`、`payload`、发起人、前 50 名（昵称、`score`、`stats`、是不是我）、人数、我的名次 |
| 交成绩 `POST /api/challenges/<id>/results` | `score`、`stats` | `ok`，或 `already` 和原来那条 |

- `payload` 和 `stats` 都是游戏自己的 JSON，平台只限大小（各 ≤ 1 KB）、原样存。
- 平台定的：30 天过期、每人每天发起 20 个、每个挑战最多 100 人。开盘按状态码说话：401 没登录、404 打不开了（不存在和过期一样）、409 人满了、429 今天发得太多、503 平台在省额度；400/403/413 是开盘自己交错了，当 bug。
- 单独部署（没有平台）不显示「挑战好友」，`?challenge=` 打开时直接进开始菜单。
- 验证：`tests/platform/challenge.test.ts`（payload 校验、同一 payload 两次开局逐位相同、分数、状态码、档案）；冒烟 `npm run shot -- --challenge`（假平台走发起 → 打开 → 接受 → 打完 → 交成绩，行情段下载失败不退回模拟行情）。
