# 文档索引

文档写的是代码现状；各版改了什么看 `../CHANGELOG.md`。早期版本的设计稿已经删掉，需要时从 Git 历史里找。文档和代码对不上时以代码为准，并顺手把文档改对。

## 玩法和规则

- `design.md`：玩法总纲：设计支柱和各节在哪个分册的目录表（引用「design.md 第 N 节」按这张表找文件）。
- `design-play.md`：小白词表、文案规矩、一局怎么玩、节奏（月度主题、目标、高光）、道具事件奖励日历（第 2、3、4、9、10 节）。
- `design-market.md`：真实行情怎么驱动、仓位押跌抵押、群聊与情报、月供与突发账单（第 5、6、7、8 节）。
- `design-persona.md`：人设与难度、成就、结局称号、其他模式指路（第 11–14 节）。
- `design-modes.md`：闪电盘、黑天鹅 Boss 日、本周市场、打新（第 15–18 节）。
- `core-api.md`：规则核心接口总则和各节在哪个分册的目录表。
- `core-api-engine.md`：入口函数、GameState、操作、一天的时序与事件、查询函数（第 2–6 节）。
- `core-api-market.md`：真实行情与行情段文件、仓位押跌抵押（`ext`）、节奏（第 7–9 节）。
- `core-api-modes.md`：局的种类、内容与 id、隐藏信息、数值表、URL 参数（第 10–14 节）。
- `design-chat.md`：群友和股票小人：每局状态、这局手气、性格表、收盘按局面接话、台词轮换和验证口径。
- `design-lesson.md`：新人：为什么输、新手课（固定一局 + 老师傅建议）、新号前几局的照顾、炒股心法卡。
- `design-balance.md`：配平：小白、普通两个玩家模型，实盘各档和娱乐各难度的实测，一局多久怎么估。

## 模式和平台功能

- `design-live.md`：实盘（筹码）：一局的样子、带入结回、杠杆、钱包接口、战绩小结、错误文案对照。
- `design-challenge.md`：好友挑战：链接里带什么、怎么开局、成绩比什么、平台接口。
- `design-share.md`：分享卡：交给 `arcade-kit/share` 的数据和名场面模板。
- `platform-integration.md`：存档和平台：本地存档与档案、云存档、每日榜与周榜、实盘钱包、好友挑战、分享卡、回大厅、安全头，以及单独部署时少什么。

## 画面

- `art-v3.md`：美术与界面：方向、材质、字体、小屋的光、主页、对局画面、关键时刻、铺满。
- `design-visual.md`：画面上的信息怎么放：少写字、信息不减、各处放什么。
- `mobile.md`：手机和平板：什么时候用手机布局、世界尺寸、最小字号和点击区、竖屏提示、各画面在手机上的排法。

## 代码和开发

- `architecture.md`：代码结构：各目录和几个大文件怎么分工（交易场景、群聊、持仓、结束页、规则引擎），冒烟截图怎么做到可复现，待重构的两处。
- `play.md`：怎么玩：一天、一个月、各种玩法、主页、操作和快捷键、设置（README 里的玩法详述挪到这里）。
- `changelog/`：0.28.1 及更早的更新日志，按版本段分四个文件。

## 资料

- 故事稿的化名表是数据，在 `tools/data/story-aliases.json`（`tests/core/story.test.ts`、`tools/data/check.ts` 读它），不在 docs 里。
- `history/`：数据核对和几个年份的事件时间线；`research/`：当前规则的依据（交易规则和文献核对）。两者都是创作研究底稿，不上线、不进游戏；游戏里不出现真实年份和公司名（故事用化名，行情段只存相对涨跌）。
