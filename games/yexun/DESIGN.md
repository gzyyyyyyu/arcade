# 《夜巡》设计稿

> 模块 `games/yexun`（Worker 名 `yexun`，路径 `/games/yexun/`）。本文是这个游戏的设计正本：现在是什么、为什么这样设计、怎么验收、怎么配平。
> 数值的实际值以 `src/content/` 为准，配平结果以模拟器跑出来的表为准（第 8 节）；逐版变化看 [CHANGELOG.md](CHANGELOG.md)，本文不记过程。
> 跨模块的规范以仓库根 `AGENTS.md`、`docs/economy.md`、`docs/balance.md` 为准；冲突时以它们为准。界面流程和布局规则见 [docs/art.md](docs/art.md)，配色见 [docs/palette.md](docs/palette.md)。

## 0. 一句话

**道士夜巡雪夜古镇**：只管走位，法器自动出手，升级三选一、法器进化，成群的跳尸纸人小妖扑上来；
两个模式平起平坐：**守夜**（撑到天亮）和**夜探**（进镇搜宝，按时撤出）。都能娱乐，都能带筹码（实盘）。

题材只是化名的民间志怪：跳尸、纸人、灯笼鬼、狐火都是幻想造型；不涉及真实伤亡，不嘲弄真人，不出现真实宗教团体、人名、地名。

## 2. 两个模式

| | 守夜（经典幸存者） | 夜探（搜打撤） |
|---|---|---|
| 场地 | 古镇外的雪原，3,200 × 3,200 的有界场地，稀疏的枯树、石头、残碑（只装饰，不挡路） | 古镇大地图 6,400 × 6,400：街巷、院墙（挡路）、四座镇门；宝箱散在院子和街角 |
| 目标 | 撑到天亮（15:00）；14:00 起大怪"尸王"出场，打倒它天提前亮 | 搜宝箱捡宝物，在撤离点开着的时候走进去撤出 |
| 时间线 | 每分钟一档刷怪表，定点事件（围圈、精英、群冲）见 2.2，14:00 大怪 | 撤离门分三个时段开（2.3）；15:00 天亮还在镇里算"迷失"（和死亡一样） |
| 节奏 | 越到后面怪越多越硬，法器成型后清屏 | 怪随时间变强，深处的宝箱更值钱、有守宝的巡夜将；越晚撤搜得越多、风险越大 |
| 娱乐 | 局外成长（铜钱买永久加成、解锁角色和地图）、成就、每日挑战排行 | 宝物进"藏宝阁"图鉴，可换铜钱；铜钱和成长两个模式通用 |
| 实盘 | 带入一份，按撑了多久结回：太早死输光、中段约保本、撑到天亮赢、打倒大怪赢最多 | 带入一份，撤出时按带出的宝物价值结回；死在里面（或迷失）这一份和背包都丢 |
| 波动 | 小，看技术 | 大，看技术也看胆子 |
| 胜（娱乐胜率口径） | 撑到天亮 | 活着撤出 |

共同点：一场 15 分钟上下（夜探早撤更短）；同一套主角、法器、被动、升级、进化；同一套操作。
另有一个 5 分钟的每日**首领连战**（守夜的子模式，2.5）。

### 2.1 一局怎么玩（两个模式共用）

- **只管走位**：键盘 WASD / 方向键（两套同时按同一方向不叠加），手机左半屏任意处按下出虚拟摇杆（松手消失；横屏只认左半屏，半透明不挡怪）。方向量化成 32 向，力度分慢走（刚拖出死区的一小圈 10–18px，速度 ×0.5，摇杆头缩小变淡）和全速两档（第 5.4 节）。
- **法器自动出手**：每件法器有自己的冷却、目标规则（最近的、朝向、随机、绕身）。
- **吃魂火升级**：怪死掉落魂火（经验），靠近自动吸；升级时暂停弹出三选一卡片（新法器 / 法器升级 / 被动），最多 6 件法器 + 6 件被动（合成一次多一格）。
- **进化**：法器满级（8 级）且持有对应被动时，下一个宝箱必出进化（第 3.3 节）。
- **宝箱**：守夜里精英掉落；夜探里散在地图上（也是宝物来源，第 2.3 节）。规则 57 起一个宝箱先把满足条件的进化、合成 / 双修一次结完（不占件数），再照常升 1 / 3 / 5 件，升完又凑齐的当场再结；结出来的一次列全（进化、双修 / 合成、升级分三组）。
- **掉落**：铜钱（局外货币）、肉包（回血）、符纸卷（吸全屏魂火）、符咒炸弹、铜钱袋，按掉落流随机；场上还有可碰碎的摆设（灯笼架、纸扎）。数值在 `src/content/player.ts`。

### 2.2 守夜的时间线（雪原；数值在 `src/content/waves.ts`）

精英、首领的时间（`EVENTS`、`EVENTS_57`、`regions.ts` 的 `elites` / `elites57`）规则 57 起每张图一样（本节规则 57 的内容由 `World.new57` 把关：娱乐 57 起、实盘 58 起）：1:45、3:00、5:00、6:30、7:30、8:00 首领、10:00、11:00、12:00、13:00、14:00 尸王，最长空 2 分钟（原来 2、3 分钟和首领前没有精英、没有宝箱，玩起来空）；规则 56 及以前没有 1:45、13:00 这两只，雪原、义庄也没有 6:30、11:00。危险 0、1 精英整体晚 30 秒，危险 3 早 20 秒，危险 4 起每次多一只（1:45 那只不多）。
规则 57 的配平（`BALANCE_57`）：精英多了、宝箱更大且一箱结完以后娱乐明显变容易（小道士普通危险 2–5 胜率 +8～+14 点），不砍 3 件、5 件的概率，改成怪每分钟变硬 0.29 → 0.35（只压后期）。试过加精英血量（×1.3–1.6）：普通胜率压得下来，但 3:00、5:00 的精英缠得更久，新手撑的时间变短，不用。1:45 那只先用过白狐，太快，危险 4 新手 420 局有 49 局在第 4 分钟前被它追死，换成走得慢的纸轿并打折。
  结果（小道士 7 图合计、每格 420 局，危险 0/2/3/4/5/6/8，规则 56 → 57）：普通胜率 100→100、77→86、68→78、63→71、41→54、41→52、19→34；新手平均撑（分）13.7→13.6、12.1→12.1、11.3→11.6、8.8→9.1、7.1→7.3、6.0→6.1、4.0→4.1。新手不比原来短，普通偏容易 8–15 点：这是宝箱更大、一箱结完带来的，目的就是让宝箱更好拿，后期变硬再往上压只多挤掉新手，不再压。
强度曲线不是直线：每个大事件后给 20–30 秒"收获期"（刷怪减半、掉落多：精英倒下后 25 秒、爆点刷出来后 30 秒），节奏验收见 13.3。会远程的怪（灯笼鬼、雪魅）每种不超过刷怪比例的 8%。
危险 3 起另有常规怪**提灯鬼**（不怕火，给火流派一个对手）：5 分钟起占常规怪 15%，12 分钟起 25%。

### 2.3 夜探

- **地图**：按格子生成骨架（街、院、墙），三个模板（古镇、渡口、山寺）+ 种子决定宝箱、巡夜将、撤离门的位置。第一次进夜探是**教学镇**：小地图、第 3 分钟开第一座门、死了不丢包。危险 0 也在第 3 分钟开第一座门。
- **宝箱三档**：木箱（街边，打开 1 件普通宝物）、铜箱（院里，2 件，有时带一只精英守着）、金箱（镇子中心和庙里，3 件，巡夜将守着）。
  宝箱打开要站在旁边 1.5 秒（读条，挨打不打断但会被推开）：搜就有风险。
- **宝物**：45 种，分四档（凡 15 / 良 14 / 珍 10 / 绝 6），每件有铜钱价值；捡到放进背包（不限格）。藏宝阁记"见过哪些"，娱乐模式撤出后背包换铜钱。
- **怪**：和守夜同一套怪物表，按夜探自己的刷怪表（`RAID_MINUTES`）刷，并随时间加强；离镇子中心越近越凶（`RAID_ZONE`）。每个镇有一种特色怪（古镇更夫鬼、渡口溺鬼、山寺石僧）。
  巡夜将是会追人的精英，另有两只夜里游荡的；最值钱的院子由守门 Boss 镇门石兽守着。
- **撤离**：撤离门开着时走进门圈站 3 秒撤出（挨打不打断）。四座镇门：5:00–6:00 随机开一座、10:00–11:00 再开一座、14:00–15:00 四门全开；15:00 天亮还在镇里算"迷失"（和死亡一样）。
- **别让人因为找不到门输光**：14:00 起顶部换成醒目的"天亮倒计时"（最后 30 秒变红、心跳音），屏幕边上常驻箭头指向**最近的**开着的门并写距离，
  地面上从主角脚下画一串指向那扇门的脚印；每扇门开的时候全屏提示一次"东门开了"。机器人小白也只靠这些提示找门，配平时量"小白迷失的比例"（目标 ≤ 10%）。
- **死亡 / 迷失**：这一局背包里的宝物全丢；娱乐模式还能拿到这局捡的铜钱的一半（不让人输得太难受），实盘这一份结回 0。
- **后半段**（为的是 6 分钟以后不只剩躲怪等门；参数在 `RAID_LIVE`/`RAID_LATE`，规则在 `src/explore/raid.ts`；教学镇没有）：
  - 补货：6:00 起每 90 秒，挑 3 个开过的箱子（离主角 500 以外，不挑宝库）重新封上、换一批东西，一波比一波深（深度 +0.25 / 波）；
  - 宝妖：5:00、10:00 各一只，从离主角 900–1,600 的路口出来，见人就跑（比主角慢一点，被墙角堵住跑不掉），不打人；45 秒后钻地跑掉；打倒直接进背包两件好宝物（按金箱、深度 1 抽）；
  - 鬼市：7:00–8:00 镇中心最近的路口摆三个摊，各摆一件（中间那摊按金箱抽，绝品机会大），站在摊前 1 秒、身上铜钱够就按价值 × 0.7 买下。
    这是把局里捡的铜钱换成能带出去的宝物，所以会抬高撤出价值、也就抬高实盘倍数（配平时机器人普通玩家要会逛鬼市）；
  - 宝库和钥匙：最深的金箱开局就贴着封条，8:00 以后、身上有钥匙才能搜，开出 6 件；钥匙是 5:00 以后打倒的第一只精英或守卫掉的（宝妖不算），一局一把。
    这里的时刻是开局后已过的时间；局里的提示一律按 HUD 的"离天亮"倒计时写（写"8:00 以后"玩家会按倒计时理解，早到了打不开），走近宝库时箱子上方显示还差多久开封、开封后有钥匙显示"可以搜了"。
  - 都按夜探自己的随机流（`raid-late`）抽，同种子同输入逐位相同，录像和每日挑战能复现。**不加"越晚撤越多倍"的倍数**：越晚撤多出来的价值全来自上面这些，配平只调基准价值（4.2）。

### 2.4 新手保护和受伤补偿（规则核心里，确定性；实盘档照用，对谁都一样）

都是明写的规则，不藏；数值在 `src/content/waves.ts`（DANGERS、OPEN_TICKS、EARLY_TICKS、FIRST_RUN_GUARD）和 `src/content/player.ts`（MERCY）。

| 规则 | 触发 | 幅度 | 为什么 |
|---|---|---|---|
| 开场慢怪 | 危险 0 前 30 秒 | 怪走路 ×0.5 | 原地不动也撑得过第一次升级 |
| 大吸珠 | 危险 0 全程（危险 1 ×1.4） | 吸珠范围 ×2.4 | 剑砍死的怪掉的珠子站着也吸得到 |
| 先给法器 | 危险 0 前 4 次升级 | 三张里至少两张是法器 | 先有能打的 |
| 第一局不死 | 这台设备上的第一局，3 分钟前 | 血最少留 1 | 第一局至少玩到第一个精英 |
| 开局减伤 | 危险 0–2 前 5 分钟 | 挨打 ×0.8 | 开局手忙脚乱少掉点血 |
| 受伤补偿 | 血低于上限的 40% | 肉包掉率 ×3；补出来的肉包最多每 20 秒一个 | 挨打多的人帮得多，会躲的几乎用不上 |

受伤补偿有上限，故意卖血不占便宜：机器人"站着挨打"（不躲、只等肉包）的胜率和撑的时间都远低于正常躲怪（`tests/core/pace.test.ts` 锁住）。

另外两条新手保护：
- 第一局锁危险 0（菜单只给危险 0，`dangerOpen`）；
- 连着倒下 3 局（认输、赢了都清零）问一次"要不要降低伤害"：开着时挨打 ×0.7（`ASSIST`），成绩不进总榜，设置里随时能开关。

**危险档**（`DANGERS`，危险 2 是配平基准；表里是代码里的绝对值，血和伤害相对基础怪）：

| 档 | 血 / 伤害 / 数量 | 其他 |
|---|---|---|
| 0 | ×0.72 / ×0.6 / ×0.85 | 开场慢怪、大吸珠、先给法器；难的常规怪晚一分钟出；精英晚 30 秒 |
| 1 | ×1.0 / ×1.0 / ×1.0 | 怪种按时出；精英晚 30 秒 |
| 2 | ×1.2 / ×1.2 / ×1.1 | 精英按时间线 |
| 3 | ×1.38 / ×1.36 / ×1.16 | 没有开局减伤；精英比时间线早 20 秒；出提灯鬼 |

### 2.5 首领连战（每日，守夜的子模式；`Setup.rush`）

目标：短、每天不一样、有高光、能炫。守夜一局 15 分钟，大部分时间在发育，精彩的是后半夜打精英和尸王；连战把这一段单独拿出来，五分钟打完，打完就有一个能晒的数。

- **一局**：开局直接给一套成型的构筑，没有常规怪、摆设、夜市、地图事件，精英和首领一关一关上，打倒全部或 5 分钟到点收工（`RUSH.limit`）。两关之间喘 6 秒（`RUSH.rest`），身边掉 2 个肉包。
  开局 14 级（`RUSH.level`），升级要的魂多，一局只升一两级；精英和首领不掉宝箱：构筑是给好的，比的是走位和打法。
- **构筑**（`core/rush.ts` 的 `rushPlan`，数值在 `src/content/rush.ts`）：从七个流派（`content/guide.ts` 的 `SCHOOLS`，含水府）里抽一个，拿它的前三件法器：第一件满级、一半概率直接进化（带上进化要的被动），第二件 6–7 级、第三件 4–5 级，四成概率再带第四件 3 级；被动一到两件 2–3 级。
- **关卡**（`RUSH_STAGES`）：常规精英 → 常规精英 → 特色精英（第 2、3 关先后按种子换）→ 两只常规精英 → 本图的中期首领（纸扎老爷 / 千年竹母 / 水猴王 / 冰魄娘娘 / 无面佛 / 画皮）→ 特色精英 + 常规精英 → 尸王，一共 9 只。
  常规精英是石狮怪、白狐、跳尸将军、纸轿，抽完一轮再重来；特色精英先上这张图自己的（竹王、河伯、冰魄、荒庙的石狮），雪原和义庄从竹王、河伯、冰魄里抽。
  精英的血和伤害按守夜第 9–15 分钟的强度算（`RUSH.minute`，一关一档）；中期首领（纸扎老爷和各图的）、尸王是守夜的 6 成、7 成血（`lordHp`、`bossHp`）。召出来的小跳尸、纸轿碎出的纸人、纸扎老爷召的纸轿、画皮甩的人皮不算关底。
- **每天不一样**（`src/online/rush.ts`）：北京时间的日期 → 种子（`hash32('yexun-daily-rush-<日期>')`）→ 地图（从写死的六张图 `RUSH_MAPS` 里抽，鬼市不在里面：新图加进守夜不改已开打日子的图，要加进连战就从某天起换一张新表）；构筑和关卡由核心按种子算，所以同一天全服一样，录像只存种子和输入就能重放。危险 2、小道士、不带加成和咒印。
- **难度**（`node tools/sim.ts --mode rush --n 60`，普通机器人按当天的流派选卡）：全清约 30%（目标 20–40%），平均打倒 7.9/9，97% 的局打倒过半；难点在压轴的尸王，没全清的局多半倒在它手里。小白全清约 2%、平均 5.4 只。
- **分数**（`rushScore`）：全清 × 1e9 + 打倒几只 × 1e7 + 一共几只 × 1e5 + 尾数。全清的尾数是剩下的秒数（越快越大），没全清的是正在打的那一关打掉了百分之几。
  所以先比全清没有，再比打倒几只，全清的比快、没全清的比最后一关打得多深。一共几只同一天都一样，编进去只为榜上能写成 N/M。只交平台每日榜的子榜 `rush`（榜名 `daily-<日期>-rush`），显示写在 `public/daily.json` 的 `boards.rush`。
- **高光**（`view/game/rush.ts`）：一关上场有横幅（第几关、来的是谁），打倒一只先定格一下、再放慢一秒左右（只改画面推拍的快慢，规则照常），白闪、震屏、手机震动、屏幕中间盖"某某伏诛"大字；
  全清是更长的慢动作加"全清"大字和用时。顶上的血条是这一关剩下的关底加在一起的血，写着"连斩 N/M"。结算页（`view/ui/rushResult.ts`）标题写"全清"或"连战 N/M"，写用时和这一局的首领一排；分享卡写"全清"或 N/M 和用时。
- **入口**：主页右上那排小按钮里，紧挨"每日"的"连战"。只有每日这一种，娱乐，实盘不开；不记守夜的纪录、解锁、成就，不发铜钱（构筑是给好的，和守夜不可比）；认输的不交榜。

#### 3.3c 规则 55 的搭配（早合）和幡下招魂

起因：河滩、荒庙（规则 55 又加了克制镇守的新怪，见 3.6）这些图上，镇魂铃起手（含第二起手）的幽冥或镇守一家独大，别的流派和它差 0.2 以上，更夫、小道士的烈火和符箓、阴阳先生的镇守和阵法凑不够「和最强差 ≤ 0.15」的 3 个（口径见 8.1）。按「往上补，不往下砍」，不改任何已有法器和搭配的数值，只加下面这些，**全部只在规则 55 起出现**（`MergeDef.since`；旧录像宝箱里不出，实盘和娱乐一样）。

#### 3.3f 规则 63 的两段式合成（只娱乐局）

起因（11-16 实测，机器人普通危险 2，200 局中位数）：第一次合成在 10.4 分钟，卡在升级上——第一件满级 7.4 分钟、进化 8.9 分钟、条件齐 10.3 分钟；而两件料都到 5 级只要 6.8 分钟。一局 15 分钟，搭配到最后几分钟才出现，玩家很少看到。

做法：每个搭配（33 个，合成和双修一样）分两段。
- **初成**：两件料都到 5 级（`MERGE_STAGE.halfLevel`，进化了的也算），下一个宝箱合上。搭配的联动全部照常，只是效果打五折（`MERGE_STAGE.halfPower`）；不空法器格。
- **大成**：到原来的条件（合成两件都进化；双修一件进化、另一件满级），下一个宝箱升大成，效果满额，空出一个法器格（法器格上限 = 6 + 大成数，`World.fullMerges`）。条件一开始就齐了的直接合大成。

打折统一走 `World.mergePower(id)`（初成 0.5、大成和关着的局 1；乘 1 时逐位不变）。伤害类直接乘；不是伤害的按下表处理：

| 搭配 | 初成怎么打折 |
|---|---|
| 阴阳镇魂 | 减速隔一拍生效一次（平均一半）；光波照旧从光环边放 |
| 铃落桃花 | 追踪范围 × 0.5 |
| 乾坤护阵 | 挡弹的半径 × 0.5（盾碎光波伤害也减半） |
| 一苇渡江 | 水洼留的时间 × 0.5 |
| 阴兵借道、锁魂幡 | 按一半的概率生效（用法器那一路的种子随机） |
| 雷劫锁魂、爆竹驱年、买路符钱、寒钟 | 道数 / 个数 / 冻住的拍数减半（至少 1） |
| 钟鼓齐鸣、判阵 | 多出来的易伤减半（1 + (倍数 − 1) × 0.5） |
| 雷雨 | 「先劈泉」的选目标照旧，导电伤害减半 |

`tests/core/merge-stages.test.ts` 每个搭配一条：同一摆法下初成的效果量严格大于不合、严格小于大成；另有两段流程（5 级合初成不空格、升大成、直接大成）、空格（初成时刷 200 次卡都不出第 7 件法器）、实盘九个角色和规则 62 逐位一致。

界面：HUD 法器格上初成的格子虚线边、右上角紫色「初」字角标，名字后缀「·初成」；宝箱演出写「X·初成 … 效果减半，还差 … 升大成」或「X·大成」；升级卡的提示写「再把 X、Y 练满升大成」（`buildRows.ts upgradeHint`）；选卡提示先指向初成、合了初成再指向大成（`mergeHint.ts`）；图鉴和玩法说明的「怎么合」写两段。

只在娱乐局（`World.mergeStages` = 规则 63 起、非实盘）：实盘和规则 62 以前的局一步合，逐位不变。指纹只在有初成时哈 `mergeHalf`。等整体重拟实盘时一起并进实盘。

配平（机器人危险 3，同种子同提交对规则 62）：普通每格 200 局全在 −1～+4.5 点；小白每格 500 局 +0.4～+5.6，只有符师两格超过 ±8 的护栏——符箓 59.2% → 67.8%（+8.6）、烈火 56.6% → 64.6%（+8.0）。原因是小白很少练到原条件，两件 5 级就能合，平均合成数 1.07 → 3.35，符师池里多是纯伤害搭配（雷火符箓、符剑、买路符钱）；这两格原来是小白最低的，涨完仍低于小白平均（约 75%），是往平均拉，主线定不调。第一次合成（13.3 口径）中位 10.4 → 6.9 分钟。

#### 3.3d 谁凑得出（组合可达性）

能不能合由两样叠起来决定：规则核心按专属和规则版本放行（`mergeFor`），料抽不抽得到看角色池（3.7「法器池」）。所以一个搭配对某个角色凑不出，原因只有三种：别人的专属、两件料有一件不在他的池里、进化用的被动不在他的池里（合成要两件都进化，双修要至少一件进化）。
`src/content/combos.ts` 是唯一的判断（`mergeReach`），界面上所有「谁能合」都读它：
- 图鉴「搭配」页按一个角色看（默认当前出战的），先列他凑得出的，再压暗列凑不出的并写原因；角色页的主修一行写「能合 N 个搭配」。
- 玩法说明「合成·双修」页把当前角色凑不出的压暗，不是人人能合的标「N 人能合」；「例子」页每个流派只推荐主修它的角色里有人凑得出的搭配。
- 图鉴「法器」页的合成卡写谁能合；双修的配方写两件法器的名字（一件进化、另一件满级），合成写两件进化后的名字。
- 选卡提示（`mergeHint.ts`）只提示这个角色凑得出的搭配。
- 能选的角色里谁都凑不出的搭配（现在是摆渡人专属的渡魂灯）在界面上不列、不算收集度；数据和规则留着，摆渡人放回来就恢复。

「人人能合」只写给九个能选的角色都凑得出的（现在只有引魂鹤铃）。每个角色凑得出的数量（娱乐局，规则 62）：纸匠 17、采药女 15、货郎 15、小道士 14、胖师叔 14、阴阳先生 13、符师 11、剑侠 11、更夫 11。
测试：`tests/content/combos.test.ts` 遍历全部搭配 × 能选角色，结论和规则核心（料给齐开宝箱合不合）、角色池、图鉴搭配表、玩法说明例子、选卡提示一致；`tests/core/combos-effect.test.ts` 每个列出的搭配一条：照门槛给料、开宝箱合上，和同样给料但抹掉搭配的世界逐拍比，一分钟内局面必须分开（效果真的起作用）。

### 3.6 地图

守夜七张，场地都是 3,200 × 3,200 的有界场地；挡路的东西是轴对齐矩形（只算脚底那块地），主角和怪都推不进去，子弹和掉落物不管（掉进去的宝箱、肉包挪到边上）。
空气墙在画面上看得见（栅栏、竹篱、石堤、院墙、挂红布的木栏，墙外盖夜雾；docs/art.md）。卡上"难"字看 `MapDef.hard`（义庄、荒庙）。

- **雪原**：开阔，稀疏的枯树、石头、残碑（只装饰，不挡路）。一开始就开。
- **义庄**：出生点四周一圈院墙（边长 1,040），四面墙中间各留一个门洞（宽 400），四个角也各空出 150；院里北边是正堂，两排棺材；院外散着棺材和残墙；跳尸 ×1.5、枯骨 ×1.3 的刷怪比例。一开始就开，卡上标"难"。
- **竹林**：约 90 丛竹子（轴对齐块，有血，血随面积），十字宽路加一条斜路；桃木剑、火舌、飞出去和转着的法器、雷、金钟罩碎裂、炸弹碰到就扣血，同一丛 8 拍内只算一次，倒了就从 `w.blocks` 拿掉、不再长回来。
- **河滩**：一条横河、一条竖河，桥是水区之间的缺口；水里主角和怪 ×0.55（蝙蝠、水鬼和各图自己的特色怪不受水和冰影响），河岸有石头、芦苇。
- **冰湖**：中间 2,080 见方的冰面，冰上主角速度逐拍靠向输入、松手按摩擦滑停（约 100–150 单位），怪同样滑、被打退滑得更远；冰上散着石头。
- 院墙不留死角：小白被怪追着贴墙跑，钻进封死的墙角就出不来，被灯笼鬼的火球点死。0.17.3（规则 41）把义庄四角、荒庙西北和东南角打通、义庄门洞放宽，之前的录像按 `MapDef.blocksV40` 的旧墙回放。
- **荒庙**：正中一座破庙，院墙塌了好几处（四个角都通），北边大殿；院里一尊香炉，庙外三尊。**香火区**（`MapDef.incense`）：每尊香炉四周 260×240 的一块，站在里面每秒多回 1.6 血，但香火引怪（怪的上限 ×1.3，刷怪速度 ×1.7），回血和被围之间要自己拿捏。

## 4. 实盘

### 4.1 规则

- 两个模式的配置固定，**永久加成（perks）、咒印、降低伤害不生效**（公平、好配平）。实盘可以**选已解锁的角色**；守夜还可以**选已解锁的地图**（夜探的"地图"是镇子，本来就能选）。
  **不带加成、咒印的理由**：它们是拿铜钱买的永久成长，带进实盘就等于老玩家固定多赚，新老玩家同一份筹码的期望不同；角色和地图是并列的选择，不是成长，所以放开。
  不传角色、地图就是小道士、雪原。局内机制（卡池、选卡三件套、夜市、角色初始数值和小特权）实盘和娱乐一样（0.4.7 起）。
- 档位 = 危险度的固定配置：小 / 中 / 大 / 豪华（`docs/economy.md` 第 2 节档位表，一份 2,000 / 10,000 / 50,000 / 200,000）守夜分别**固定映射娱乐的危险 0 / 2 / 3 / 4**，只维护一套怪表。
  局内铜钱和娱乐一样，打完存入账户（账户铜钱只买永久加成和请角色，永久加成不进实盘，不影响赔率公平）。夜探开小、中、大三档（对应夜探危险 0 / 1 / 2，见 4.2），豪华档等模拟器出表再开。
- 带入固定是这一档的一份（Worker 定，浏览器只报档位）；`mode: client`；结回走 Worker（第 5.6 节）。夜巡自己的档位名是 small / medium / large / luxe，带入时换成钱包的 small / mid / big / lux（`LIVE_TIERS.wallet`）。
- 默认一场最多赢 3 份、最多输 1 份（`docs/economy.md` 第 2 节）。平台还有每个游戏每天净赢 10 份的上限兜底。

### 4.2 结回倍数（`src/content/live.ts`、`src/content/explore.ts`，数值由模拟器定，这里是形状）

**守夜**：按撑到的时间连续地涨（逐拍插值，不跳台阶），打倒尸王额外加。曲线是 `VIGIL_SHAPE`（3:00 以前为 0，5:00 占天亮倍数的 5.6%，10:00 22%，14:00 28.8%，15:00 100%），
四档形状相同、只按各档的天亮倍数 `dawnBp` 缩放，打倒尸王再加 0.2（`VIGIL_BOSS_ADD_BP`，不缩放），一场封顶 3 份：

| 撑到 | 小（危险 0） | 中（危险 2） | 大（危险 3） | 豪华（危险 4） |
|---|---|---|---|---|
| ≤ 3:00 | 0 | 0 | 0 | 0 |
| 5:00 | 0.08 | 0.09 | 0.10 | 0.11 |
| 10:00 | 0.30 | 0.37 | 0.39 | 0.42 |
| 14:00 | 0.39 | 0.49 | 0.51 | 0.55 |
| 天亮 15:00 | 1.35 | 1.69 | 1.76 | 1.92 |
| 打倒尸王 | 1.55 | 1.89 | 1.96 | 2.12 |

为什么是这个形状：中途回得少、天亮给得多，小白（早死）和普通（多半撑到天亮）的期望才拉得开，四档才能同时落进 balance.md 4.4 的区间；曲线从 3:00 起平滑上升，没有"4 分 01 秒才有钱"的断崖。
天亮倍数随档位不降（小 ≤ 中 ≤ 大 ≤ 豪华，`tests/platform/live-client.test.ts` 锁住），不然玩家看到的是"大档更难、给得更少"。选档卡上画这条小曲线（横轴时间、纵轴倍数，标出保本点、天亮、尸王），结算时标出这一局停在哪。

目标（balance.md 4.4，实盘期望，份；收益要配得上难度，整体 +0.15，规则 58 起按它拟）：小 普通 +0.60～0.75 / 小白 +0.30～0.45，中 +0.45～0.60 / +0.15～0.30，大 +0.35～0.45 / +0.05～0.15，豪华 +0.20～0.30 / −0.10～0。守夜、夜探同一张表。
配平两头管：普通点估计超上限 +0.15 的压回上限；普通低于下限 0.10 以上的抬到带中点（两条线都不超上限、最多抬到原系数 2 倍）。小白偏低不单独抬。
（规则 57 及以前用的旧带：小 普通 +0.45～0.60 / 小白 +0.15～0.30，中 +0.30～0.45 / 0～0.15，大 +0.20～0.30 / −0.10～0，豪华 +0.05～0.15 / −0.25～−0.10；下面按日期记的配平过程用的都是旧带。）
定"夜巡是普通玩家每天拿筹码最有效的途径"后，小档目标最高。每次改内容或危险档都要重拟 `dawnBp`。
0.6.0 全量（地图事件开着；6 角色 × 6 地图 × 4 档，每格 300 局普通玩家、六个流派各 50；小白按小道士、雪原每档 1,000 局）锚小道士各图平均到区间中点：
普通 小 +0.53 / 中 +0.37 / 大 +0.25 / 豪华 +0.09，都在区间里；小白 小 +0.36 / 中 −0.02 / 大 −0.19 / 豪华 −0.47。事件让中高档好撑了一点，天亮倍数比 0.4.10 低（中 1.73 → 1.69、大 1.84 → 1.76、豪华 2.01 → 1.92）。
已知的取舍：一个天亮倍数同时管小白和普通，以普通为准：小白小档比上限高 0.06、中档比下限低 0.02、大档低 0.09、豪华低 0.22（小白在危险 4 撑不到 3:00 的局多）。
豪华档两格偏出 ±0.15：更夫 × 义庄 −0.30（胜率 19.9%）、更夫 × 荒庙 −0.16（25.7%），组合系数都已到上限 2.5。

各版本的系数拟合记录（每次重量的范围、改了哪些格子、为什么）见 [docs/balance-yexun.md](docs/balance-yexun.md) 第 1 节。

**夜探**：撤出时倍数 = clamp((带出的宝物价值 + 早搜奖励) ÷ 基准价值, 保底, 封顶 3)；死亡、迷失、认输、中途关页面为 0。基准按"档位 × 镇子"各一个（`RAID_LIVE.base`），不按一个数，免得"挑镇子赚钱"。
档位 → 夜探危险：小 0、中 1、大 2。夜探的危险档单独一条更缓的坡（`waves.ts` 的 `RAID_DANGERS`）：危险 1、2 取守夜危险 0→1 的三分之一、三分之二处，危险 3 起顺延守夜的 1、2、3。
理由：夜探没有天亮可撑、还有巡夜将，同一档比守夜难得多（普通玩家用守夜的危险 1 只撤出 45%、危险 2 约 30%），中、大档怎么定基准都够不着目标区间。

**认真搜要比开门就走多拿至少 0.15 份**（否则认真玩的人会觉得白搜了）。三处设计：
- **保底按撤出时刻给**（`liveFloor`）：从 1 份线性涨到这一档的满额。小档 5 分钟给满 1.6；中档第一座门 5 分钟才开，开门就走也在 6 分钟左右，所以拖到 10 分钟给满 1.6；大档 8 分钟给满 1.25。
- **早搜奖励**（`RAID_EARLY`）：前 5 分钟开离出生点 1,200 以内的木箱、铜箱，宝物结算时价值 ×1.3（不改抽到什么，只在结算加价；死了包丢了奖励也没了）。纯刷保底不碰箱子拿不到。
- **后半段提价**：补货每波深度 +0.25、宝库 6 件（2.3）。只奖励待到 6、8 分钟以后的人。

拟合口径：全量模拟，每格 2,000 局：三镇 × 三档 × 小白 / 普通 / 贪心。普通玩家 10 分钟后才走，贪心 13 分钟后，小白第一座门开就走。"开门就走"= 手熟、几乎不死的人只拿保底，按 95% 撤出 × 小白撤出时间中位（小档 4 分钟、中大档 6 分钟）时的保底 − 1 估。
0.4.10 重拟（三镇 × 三档 × 6 角色，每格 600 局普通玩家；小白小道士每格 500 局），基准锚小道士普通玩家到区间中点：普通 小 +0.53～0.54 / 中 +0.38～0.39 / 大 +0.24～0.26；
小白 小 +0.11～0.18 / 中 −0.20～−0.09 / 大 −0.32～−0.15。取舍：小白中、大档比区间低（选卡三件套、夜市让普通玩家多搜多撤，同一个基准压下来小白就亏），以普通为准；山寺小白一直最低。
"开门就走"和贪心这轮没重量（上一轮普通比开门就走多 0.16、贪心比普通多 0.06～0.12）。

戏楼镇、粮仓镇（0.17.6）：小道士每格 300 局，普通锚区间中点、两条线期望 + 2SE 不超上限。基准 戏楼镇 176 / 184 / 135、粮仓镇 246 / 224 / 210（小 / 中 / 大）。
普通 戏楼镇 +0.464 / +0.316 / +0.155、粮仓镇 +0.494 / +0.332 / +0.175（大档两镇低于下限 0.05 以内）；小白 戏楼镇 +0.038 / −0.253 / −0.306、粮仓镇 +0.227 / −0.170 / −0.413，和老镇一样以普通为准。
别的角色在这两镇还没量，`RAID_LIVE.charBp` 先取同档三个老镇里最低的系数（保守）。

结回 = 带入 × 倍数（向下取整，按万分之一传 `bp`，同开盘）。

### 4.2a 角色、地图系数

选哪个角色、哪张地图，同一档的实盘期望（份）不应差出 0.15 份以上，否则玩家会"挑角色、挑地图赚钱"。差出去的单独给一个**实盘倍数系数**（万分比，没写 = 10_000 = 不调），小道士、雪原是基准，永远不写；角色、地图本身的数值和对局规则不动：

- **守夜**：`LIVE_CHAR_BP`、`LIVE_MAP_BP`（`src/content/live.ts`），按档写，乘在这一档的 `dawnBp` 上，所以天亮、尸王前的曲线一起按同一比例缩放，尸王加成不缩放；结果始终封顶 3 份。按档写是因为难度随档位涨得快的角色、地图（义庄、冰湖）在各档需要的补偿不一样。
- **开了技能的格子**（`LIVE_SKILL_OPEN`，4.2）：用单独的一套 `LIVE_SKILL_BP`（dawnBp、角色系数、地图系数，没写的按 1 倍），`vigilBp` 查表选用；不乘 `LIVE_MAP_BP`，也不用组合系数 `LIVE_COMBO_BP`（那两套是不带技能时拟的）。小档竹林的 9,900 沿用不带技能那套、没有重拟，只核过小道士的期望没超上限。
- **夜探**：`RAID_LIVE.charBp`，按档写，可以按镇子细分；乘在按保底、封顶算好的倍数上（`liveMultiplier`），结果至少 1 份、最多封顶。接在结回上而不是基准价值上：胖师叔、采药女的撤出率高，撤出就有保底，调基准价值压不下去。
  实盘局的角色由核心带上，`settleRaid` 自己取，界面不用管。
- **口径**：角色和地图先**分开扫**（角色在雪原、地图用小道士），两个系数默认相乘；乘出来偏离同档平均 ±0.15 份以上的**组合**单独写在 `LIVE_COMBO_BP`（角色 × 地图 × 档），写了就用整套系数**替换**乘积，尸王加成照旧不缩放。
  原因：胖师叔、采药女这类角色在义庄、冰湖上并不是"各强各的"，乘出来的系数会把他们抬高很多。夜探只有角色一个维度，不需要组合表。目标是每档同档各角色（地图、镇子）之间的普通玩家期望极差 ≤ 0.15 份；系数取到 100（1%）。
  不用封顶、不改加法：组合偏高的原因是角色和地图的强弱不独立，封顶管不到，直接替换乘积最简单。
- **义庄、荒庙豪华档**：规则 40 以前系数 1.79、1.59，乘上天亮倍数 1.92 就封顶 3 份；0.17.3 打通院墙后系数降到 0.85、1.06，天亮不再封顶（部分组合系数折算后仍可能封顶）。
- **0.4.7 全扫**：6 角色 × 6 地图 × 4 档 144 格都量过（角色、地图系数交替拟合，残差超 0.10 的给组合系数，系数夹在 0.5–2.5 倍；小道士 × 雪原不写组合，它就是基准）。
  只有一格出界：豪华档更夫 × 义庄 −0.27（胜率 22.7%，组合系数已到 2.5 倍、赢了也只到封顶 3 份，补不上去）。小白只作参考没有拟合（同一个系数对小白不通用）；
  采药女、胖师叔在夜探里仍是最强的（系数压平了期望，没压平"撤出率"），界面上不要写"夜探最强角色"。
- 以后的新图按同一套方法拟合，偏离同档平均 ±0.15 份以内才开放（`LIVE_MAP_CLOSED`，8.1）。

## 5. 架构

```
games/yexun/
├─ src/core/      模拟核心：固定节拍、确定性，不碰 DOM、网络、时间、随机
├─ src/content/   内容表：法器、被动、进化、怪物、刷怪表、角色、地图、夜探模板、实盘倍数
├─ src/explore/   夜探的规则（地图生成、宝箱、守卫、撤离、结算）
├─ src/view/      Phaser 4 画面层 + DOM 界面（菜单、卡片、HUD 文字）+ 程序画的图和合成的声音
├─ src/platform/  本地存储（yexun. 前缀）、云存档、实盘浏览器端
├─ src/online/    排行榜分数、每日挑战、分享卡、社交部件
├─ src/replay/    浏览器本地录像
├─ worker/        Worker：登录闸门、独立模式根路径、实盘 buyin/settle/refund（自己一份 tsconfig）
├─ tools/         机器人模拟、冒烟截图、手感和耗时测量、封面、字体子集化
└─ tests/         vitest（core/ content/ explore/ view/ platform/ arch/）
```

### 5.1 模拟核心 `src/core/`

- **固定节拍**：每秒 30 拍。`step(state, input)` 推进一拍并返回这一拍的事件（命中、击杀、升级、开宝箱、进化、撤离、结束）。
- **输入**：这一拍的方向（0 = 不动，1–32 = 32 向）+ 可选的升级选择（0–2）。升级弹卡时核心进入"选择中"，不推进时间，只等选择。
- **原地修改（设计上的例外）**：几百个单位每秒 30 拍整体复制太慢，`step` 原地修改它拥有的状态（AGENTS.md 第 4 节"输出新状态"对本模块放宽）。
  存档和回放用"种子 + 输入"重算；确定性用重放测试锁住（状态指纹）。写进模块 `AGENTS.md`。
- **数据布局**：怪、子弹、掉落物用定长的并列数组（`Float64Array` / `Int32Array`，结构数组），空位用空闲表复用，热路径不分配对象。
- **碰撞**：均匀格子分区（格子 64 单位），每拍重建一次（计数排序，O(n)）。怪与怪之间做轻推挤（只和同格、邻格的比），子弹查邻格的怪。
- **上限**：怪 300、子弹 400、掉落物 400（超了就合并最远的魂火）。
- **确定性**（不强求定点数）：
  - 坐标、速度用 JS 的双精度浮点；`+ - * /` 在所有引擎上按 IEEE 754 逐位一致；
  - **禁止** `Math.random`、`Date`、`performance`，以及 `Math.sin/cos/tan/atan2/sqrt/hypot/exp/log/pow/cbrt` 这类引擎可以近似实现的函数；
    方向用 32 向（和需要时 256 向）的单位向量表，表是**写死在源码里的常数**；需要开方的地方（追踪、归一化）用固定迭代次数的牛顿法（`src/core/fmath.ts`），只用四则运算；
  - 允许 `Math.floor/ceil/trunc/round/abs/min/max/sign/imul`（结果是精确的）；
  - 遍历顺序固定（数组下标），不用 `Map`/`Set` 的迭代顺序决定结果，不用 `Array.prototype.sort` 排有相等元素的东西（用稳定且带下标的比较）；
  - 随机数：自己写的 `sfc32`（只用 `Math.imul` 和位运算），按用途分流：刷怪、掉落、升级选项、宝箱、怪的行为、地图生成，各一条流，种子由总种子和用途名哈希得到。
    一条流多用一次不影响别的流（比如多掉一个铜钱不会改变下一张升级卡）。
  - 架构测试扫 `src/core/` 和 `src/content/` 的源码，出现上面禁止的东西就失败。
- **单位**：时间以拍计；距离以"单位"计（主角宽约 40 单位）；伤害、血量是整数，减伤、暴击等百分比按整数万分比算后向下取整。

### 5.2 内容表 `src/content/`

纯数据 + 小函数（伤害公式、刷怪表查询），被核心读取。改数值只改这里；数值变化要过模拟器（第 8 节）。

### 5.3 画面 `src/view/`

- **Phaser 4**（WebGL，失败回 Canvas）。世界层由 Phaser 画：地面、阴影、怪、子弹、特效、伤害数字；界面层用 DOM（菜单、升级卡、结算、设置），字小也清楚、好做无障碍和 44 像素检查。
  界面照全站规范 docs/ui.md：主页上的面板（图鉴、藏宝阁、玩法说明、排行、回放）都走 `view/ui/modal.ts`，右上 ✕、点遮罩、Esc 三种都能关，同时只开一个，关掉后焦点回到打开它的按钮（焦点陷阱和切标签回焦见下）；
  Esc 按"确认框 → 面板 → 设置 → 暂停"关最上一层，什么都没开时不做事；`?` 打开玩法说明「选卡」页的快捷键表；认输、回大厅这类按钮用危险样式（米底红字红边），确认框遇到危险动作时回车默认选取消；
  玩法说明（`guide.ts`）十三个页签、一个页签一页：上手、选卡、养成、角色、地图、流派、套装、进化、合成、配合、守夜、夜探、例子；没有总页数的提示。电脑宽屏（≥900×560）页内分两栏、每页一整块一屏放下，不翻页（`WIDE` 与 `guide.css` 的条件一致）；手机单栏，放不下的页再用 `pager.ts` 翻页。流派页每个流派一张卡：章（`schoolIcon`，和选关页的心法按钮同一个图）、一句话打法（`SCHOOLS[id].brief`）、核心法器和被动（图标）、主修角色和起手（取自 `content/pools.ts`，和角色页「主修」同一份）。「进化」页列满级 + 被动的进化；「合成」页（标题「合成·双修」）列当前规则版本下存在的全部配方，每条带条件徽记（合成 = 两件都进化，双修 = 一件进化 + 另一件满级，文字用图鉴共用的 `mergeHow`）和专属角色。
  选模式页所有选项直接摆出来不折叠（模式、地图、危险 0–5、角色、起手心法、噩梦 1–3、咒印、加成、无尽、开始；角色娱乐和实盘都是一个按钮，点开角色页选人），在 1280×720、1366×768、1440×900、1920×911、1920×1080、844×390、390×844、360×640 下一屏放下、页面和各栏都不滚动（冒烟第 9 段量，另加 2560×1440）；电脑、平板从上到下是 娱乐 / 实盘、守夜 / 夜探两张头图卡、地图（或镇子）横排卡（左边缩略图，右边名字、说明、特色怪小头像），下面一整条配置面板、右边大「开始」：娱乐的面板和实盘同一个排法、同高：危险 0–5 和角色按钮、起手心法一行，噩梦、咒印、加成、无尽一行，最好成绩一句，实盘的面板是档位、角色和起手心法一行，危险档一句，再一行等宽的数字小牌（回钱起点、天亮和尸王的份数，夜探是保底、待满几分钟的保底、多少铜钱算 1 份、最多几份，以及能不能放技能，细则在悬停里）；大屏整块按设计尺寸排好再整体 zoom（`--k` = min(可视宽/1476, 可视高/700) 限 1～1.6，1920×911 是 1.3，卡片不拉伸，冒烟第 9 段核 k 和块宽）。手机横屏是左右两块（左边模式和地图，右边配置和开始），竖屏一列；图鉴、藏宝阁、玩法说明、排行、回放、角色/咒印/加成页在这五个尺寸下也一屏放下，长内容按可用高度翻页（`pager.ts`）；主页的每日提示挂在顶栏"每日"按钮的角标上；所有 DOM 界面（菜单、HUD、选卡、各面板）的字号都用 `screens.css` 顶部那一组 `--fs-*` 变量（12–28 七级，手机竖屏最小一级抬到 13）；面板开着时 Tab 只在面板里转圈，切标签重画后焦点留在原来的标签上。
- **插值**：画面按真实时间跑 60 帧（或屏幕刷新率），核心按 30 拍；画面在两拍之间插值位置。
- **本地预测（验收 ②"一帧内响应"）**：摇杆一动，主角的**画面位置**当帧就按新方向挪（从上一拍的位置外推），下一拍核心算出的位置到了再平滑并上；只影响主角的画面，不进核心。
- **对象池**：怪、子弹、魂火、伤害数字、粒子都用池；同屏精灵 ≤ 1,200。
- **镜头**：跟人，带一点前瞻（朝移动方向偏一点），有界场地在边上停住。
- **打击感**（验收 ②）：命中闪白（两帧着色；同一只怪闪完隔 160 ms、精英首领隔 260 ms 才再闪，光环、寒泉这类持续伤害不会把它一直刷成白剪影）、受击后退、死亡碎片、发光叠加（ADD 混合）、拖尾、暴击和大招停顿（hit-stop：画面暂停送拍 40–80 ms，核心按拍走，不影响确定性）、伤害数字弹跳、连斩毛笔字横幅加墨点。
  震屏只给大事件（进化、精英和尸王倒下），平常命中不震；受击后退是缓出（一下推开、慢慢回位）加轻压扁，大怪几乎不退；死亡先弹起、撑开压扁再淡出；主角起步轻拉长、停步轻压扁（预备和余势）。
  伤害数字：同一只怪接连挨打合成一个数往上加；离主角胸口 70 以内的往外推，不挡主角。这些都只在画面层（`GameScene.ts`、`fx.ts`）。
- **HUD**：布局规则见 docs/art.md 第 2 节。
- **iOS / 手机**（仓库根 AGENTS.md 第 4 节，照开盘的做法）：触屏设备渲染倍数封顶 2，地面这类整屏大图按 1 倍；高度按 `visualViewport` 算的 CSS 变量；双指放大时不改尺寸；WebGL 丢失等几秒才提示、恢复时收起；safe-area 四边让出；省内存设备（触屏且 `deviceMemory ≤ 4` 或 iOS）关粒子、伤害数字减半。
- **图集**：开局用 Canvas 2D 画进四张图集，每张 ≤ 2048 × 2048：主图集、夜探图集、特色怪图集（含纸兵）、角色图集。主图集在渲染倍数 3 时已接近上限，新图放别的图集。
- **横屏与竖屏**：游戏按横屏设计；竖屏也能玩：世界缩放按屏宽定（一屏宽看 460 单位），竖屏开的局刷怪圈转 90°（`setup.tall`，录进录像），横屏局不受影响。

### 5.4 输入和录像（本地）

- 方向量化成 32 向：键盘 8 向是其中的子集；摇杆按角度取最近的一向，拉动不足死区算不动；力度只分两档：拖动距离在死区（10px）外、18px 以内是慢走（只留窄窄一圈：短拖很常见，慢走区宽了玩家会不知不觉变慢，实盘里等于暗中加难度；慢走时摇杆头缩小变淡），输入值 = 方向 + 32（33–64），核心里速度乘 0.5，再远是全速（连续力度会让录像变大，两档足够微调走位）。键盘和机器人只出 0–32，旧录像逐位不变，不升规则版本；录像里慢走写成 `~` 加方向符号。
- **录像 = 规则版本 + 模式 / 档位 / 难度 / 角色 / 加成快照 + 种子 + 每一拍的方向（游程压缩）+ 升级选择（按拍号）**。一局 15 分钟 27,000 拍，摇杆平均几拍换一次方向，压缩后几 KB 到十几 KB。
- **只存在浏览器本地**：`yexun.replays` 存最近 5 局和每个榜自己最好的一局，总量控制在 300 KB 内（超了先删最旧的普通局）。页面能回放自己的录像（暂停、2×、4×）。
  这是玩法功能（看自己怎么打的、发给朋友看的截图），也方便复现 bug。
- 规则版本变了的旧录像标"旧版本，可能放不对"，不删。其中规则版本 < 37 的回放用旧卡池（不看角色池），< 38 的回放用 2.0 之前的首领、刷怪表和首领连战第五关（画皮三图、其余纸扎老爷，没有雪童子、棺钉鬼）；标记是 `World.replayRules`（录像的规则版本），只由 `replay/player.ts` 传给 `createWorld`，不进 `Setup`，从存档、URL 带不进来。`tests/fixtures/` 里留了规则版本 35 和 37 录的两份，回放要逐位一致。
- **为什么不做服务端录像存储和校验**：排行榜和其他游戏一样不防作弊（`docs/project.md` 第 3 节第 7 条）。
  **以后要加**：录像格式已经是"种子 + 输入"，加一个上传接口、在 Worker 或维护者工具里用同一份核心重放比分数即可，核心不用改。

### 5.5 平台接入 `src/platform/`

- 存储 key 一律 `yexun.` 前缀，全表见 AGENTS.md 第 6 节。
- 云存档（平台 5.5）：同步 `profile` 一个槽（铜钱流水、加成、解锁、藏宝阁、成就、统计，估计 < 4 KB）和教程标记；不同步打到一半的那一局、设置、录像。合并：集合并集、计数取大、铜钱取"按局 id 去重后的流水"之和（避免两台设备各花各的出现负数，具体写进 `cloud.ts` 的注释）。
- 进页面先 `GET /api/me`（`detectPlatform`）：独立部署时藏起登录、云存档、排行榜、实盘，"回大厅"改成回游戏首页。

### 5.6 Worker `worker/`

- 入口只导出 `default`（单独部署时具名导出会让 Worker 起不来）。
- 首页三种写法过 kit 的 `loginGate`；站点根 `/` 和 `/api/me` 过 `standaloneRoot`（独立模式）。
- `/games/yexun/api/live/{buyin,settle,refund}`：照开盘 0.11.2——浏览器只给 `ref`、`tier`、`bp`（倍数万分比）、可选战绩小结；带入金额固定是这一档一份、到期 24 小时由 Worker 定；
  **结回前先 `WALLET.view` 取桌上这一份的金额按它算**，不信浏览器报的档位；CSRF（`X-Arcade: 1` + Origin）、请求体 ≤ 2 KB、超时 5 秒；独立部署回 501 `no_wallet`。
- `GET /games/yexun/health`（`worker/route.ts`，入口 `index.ts` 只导出 default）：回 `{"ok":true,"version":"<package.json 版本>"}`、不缓存，给平台巡检用；排在最前面，不过登录闸门、不读存储、不问平台，单独部署时也能访问。
- **没有 Durable Object**（不做联机、不做服务端录像），所以 `wrangler.jsonc` 只有静态资源，外加 `observability`（Workers Logs）。
- 浏览器入口调共用包的 `reportErrors`（`arcade-kit/report`），页面里没人接住的报错发到平台 `/api/client-error`：只带报错、调用栈、路径、游戏和版本，每页最多 5 条。

### 5.7 排行榜

照其他游戏的简单版：页面直接 `POST /api/scores`，不经过游戏 Worker，不防作弊（平台 15.5）。分数公式在 `src/online/score.ts`，榜的显示写在 `public/boards.json`、`public/daily.json`。

| 榜 | boardId | 分数 |
|---|---|---|
| 守夜总榜 | `vigil`（固定榜） | 危险档 × 1e10 + 撑到的秒数 × 1e4 + 击杀（击杀 < 1e4）；打倒尸王算撑满 900 秒再加 100 |
| 夜探总榜 | `raid`（固定榜） | 单局撤出的宝物价值（铜钱） |
| 无尽 | `endless`（固定榜） | 活了多少秒 × 1e4 + 击杀 |
| 每日守夜 | `daily-YYYY-MM-DD-vigil` | 撑到天亮：1e6 + 击杀；没撑到：撑了多少秒 |
| 每日夜探 | `daily-YYYY-MM-DD-raid` | 单局撤出的宝物价值 |
| 每日连战 | `daily-YYYY-MM-DD-rush` | 全清 × 1e9 + 打倒几只 × 1e7 + 一共几只 × 1e5 + 尾数（全清：剩下的秒数；没全清：最后一关打掉的百分比），见 2.5 |
| 本周夜事 | `week-YYYY-Www-vigil` | 同守夜总榜公式（5.8） |

每日挑战：全服同一种子、同一张图、同一组当日咒印；固定角色、不带加成；规则版本变了榜名后面加 `-v<n>`。
周日噩梦日（2026-11-01 起）：守夜的每日挑战在周日改打噩梦 1（危险 6），当日咒印只留 1 条，选档行写「周日噩梦日」；随机数的抽法不变（只截掉多抽的咒印），夜探不变。
主页「开始 / 选模式」下面有一行不可点的提示（只管守夜每日）：平时写「每日守夜 · 周日噩梦日 · 还有 N 天」（`daysToNightmareSunday`，按北京日期，11-01 之前数到 11-01），噩梦日当天换成红色「噩梦日」小标加「噩梦 1」。
只交娱乐和每日挑战的成绩（实盘不上榜）；每日挑战只进当天的每日榜，不进总榜；开了"降低伤害"的局不交总榜；认输的不交（无尽除外）。好友榜用平台的 `scope=friends`。一局结束出结算画面时交一次。

### 5.8 每周夜事（`src/content/weekly.ts`、`src/online/weekly.ts`）

一个单独开局的每周挑战，像每日挑战那样：主页「本周夜事 · XX周」按钮（`view/ui/weekly.ts`，≥ 44×44，样式限定在 `.yx-menu` 下、类名 `yx-mweekly`）点一下直接开局，
对局标签写「本周夜事 · 铜钱周 · 危险 2」，结算页「再来一局」再开同一个挑战。**普通守夜、实盘、夜探、每日挑战都不挂周事件**，总榜和每日榜不受影响。

- **轮换**：北京时间每个自然周（周一起）一个事件，从 5 项的表里按周序号取余轮着来（周序号从 1970-01-05 那个周一数起，不用随机，同一周所有人、所有设备一样，`weeklyFor`）。
  地图按同一个周序号轮换写死的 6 张图（`WEEKLY_MAPS`，不看玩家解没解锁；5 和 6 互质，事件和地图的搭配要隔 30 周才重复）。鬼市不在里面：新图加进守夜不改这周的图，要加进来就从某周起换一张新表。
- **固定配置**（`weeklyPlan(date, seed)`，返回 `{ week, event, setup, boardId }`）：本周事件、轮到的图、危险 2、小道士、不带加成、不带咒印、不开降低伤害。
  种子每局随机，一周可以多打几次取最好。开局走 `main.ts` 的 `startRun(…, fixed, 'weekly')`，`Setup.weekly` 随录像保存；规则核心不碰日期，只认这个字段，没有 = 不开
  （`normalizeSetup` 会把实盘、夜探里的去掉），所以普通局和以前逐拍一样，金标准不变。
- **周榜**：榜名 `week-<ISO 周>-vigil`，例 `week-2026-W44-vigil`。ISO 周按北京时间，周一 0 点换周，年份按该周周四所在的年（`beijingIsoWeek`：2026-12-31 和 2027-01-01 都是 2026-W53，2027-01-04 是 2027-W01）。
  计分同守夜总榜（`vigilScore`，显示用 `formatScore('weekly-vigil')`，危险 2 × 1e10 + 秒数 × 1e4 + 击杀）。本周夜事的局**只交周榜**，不交总榜、不交每日榜；
  平台只收本周的榜：开局那天不在本周的不交，只有周一当天还能交上周的（`weeklyDateOpen`，照每日榜的 `dailyDateOpen`）。认输的不交。排行页多一个「本周夜事」标签。

| 事件 | 效果 |
|---|---|
| 铜钱周 | 这局铜钱（捡的、时间、击杀、天亮等合计）多 50%，结算页单列「本周夜事」，咒印加成在它之后算 |
| 灯会周 | 怪掉铜钱和肉包的概率 ×1.4 |
| 精英周 | 每次精英多一只；打倒一只精英另得 15 枚铜钱（单列）和 50% 的魂珠 |
| 月蚀周 | 全程夜色，只看得见身边约 620 的一圈（只改画面；危险 2 本身没有夜色） |
| 宝箱周 | 精英宝箱开出 5 件 / 3 件的概率 18% / 36%（平时 12% / 33%；规则 56 及以前 10% / 32%，平时 6% / 24%） |

界面还有：对局里计时下面一块"本周夜事 · <事件名>"小牌（和连战的"连战 N/M"同一个样子）、暂停面板「今晚的规矩」里一行「本周」、图鉴夜事页（列全部五种并标出本周）、玩法说明的「模式」页。数值要改走模拟器（8.1）。

## 6. 性能预算

| 项 | 预算 | 怎么量 |
|---|---|---|
| 核心一拍 | 300 怪 + 400 子弹时 ≤ 2 ms（中端手机），≤ 0.5 ms（电脑） | `npm run bench -- --worst` 在 Node 跑满载；手机上带 `?fps` 看帧率 |
| 一帧 | 16.7 ms；中端手机横屏满载 p95 ≤ 20 ms（≥ 50 帧） | 冒烟里记 `requestAnimationFrame` 间隔；手机实测写进 PR |
| 首包 | 游戏代码 ≤ 250 KB gzip（Phaser 另算，单独成块缓存）；字体子集 ≤ 120 KB | 构建输出 |
| 图集 | 四张图集每张 ≤ 2048 × 2048（省内存设备渲染倍数 ≤ 2） | 开局一次，计时写进 PR |
| 内存 | 省内存设备 ≤ 200 MB | 暂无专用估算工具，靠渲染倍数封顶 2、图集尺寸和 `?lowmem` 冒烟兜底 |
| 模拟器 | 一局（无画面）≤ 1 秒；2,000 局一格用多线程跑完，大批量拆到 GitHub runner | `tools/sim.ts` |

实测（0.0.17，2026-10-17，Node）：`bench --worst`（300 怪满额、12 件法器全进化、主角无敌绕圈）每拍平均 0.24 ms、p99 0.53 ms、最慢 0.64 ms，p99 略超电脑 0.5 ms 的预算，可接受、不为它再改。
无头浏览器没有 GPU，帧率是软件渲染的下限，一帧的预算以真机为准：带 `?fps` 打开，左下角显示每秒帧数、这一秒最长的一帧和场上怪数，手机横屏不到 30 帧不过关。

## 8. 机器人和配平工具 `tools/`

- **两个玩家模型**（`docs/balance.md` 第 1 节，带种子、确定性；这个游戏没有隐藏信息，但机器人只用屏幕上看得到的范围）：
  - **小白**（novice）：每 10 拍重新决定方向，朝"离怪最远 + 有魂火"的方向走但带噪声，偶尔贴脸；升级只挑看起来最强的（不全随机，随机选卡会拿到引魂灯这类不直接加战力的被动）；夜探见箱就开，撤离门开了才往那边走、常常走不到。
  - **普通**（normal）：每 3 拍决定，按怪的密度场躲（势场法），会绕圈收魂火；升级按流派单子和进化配方挑，会去凑双修的另一半；夜探会算"走到撤离门要多久"决定开不开下一个箱，逛鬼市、按背包价值和血量选第一扇还是第二扇门。夜探另有贪心（greedy）玩家，多待多搜。
  - 流派单子在 `tools/bots.ts` 的 BUILDS，和玩法说明用的 `guide.ts` 是同一份。
- `tools/sim.ts`：多线程跑 N 局，输出胜率、时长分布、倍数分布和每档实盘期望；`--json` 存每局结局（赢没赢、打没打倒尸王、撑了几拍、死因、第一次双修的拍）供离线拟合，`--from` 错开种子分片，`tools/sim-merge.ts` 拼表；`--nodual` 是双修对照臂。大批量（每格 ≥ 1,000 局）拆到 GitHub runner 上跑。
- `--stop`（实盘配平，配 `--live`）：每格小白、普通两条线按批跑（默认每批 50 局），每批后看两条线实盘期望的 ±2SE 区间，「要不要动系数」定了就停。口径和配平的修正规则一致（超带上限 +0.15 才压，普通低于下限 0.10 以上才抬，小白偏低不管）：普通线区间整个高于上限 +0.15（多发）、整个低于下限 −0.10（偏低）、或整个落在 [下限 −0.10, 上限 +0.15] 里（不用动）就算定了；小白线区间整个高于上限 +0.15（多发）、或上沿不超过上限 +0.15（不用动）就算定了。两条线都定了就停，最少 100 局，最多 `--n`（实盘配平用 300）；区间跨着 上限 +0.15 或 下限 −0.10 的格子跑满。表和 json 写每格实际局数和停的理由（不用动 / 多发 / 偏低 / 跑满）。规则在 `tools/early-stop.ts`，同一个文件能拿已有的 json 离线回放（`node tools/early-stop.ts <json>...`）。种子顺序和跑满一样，提前停的结果就是跑满那一格的前 N 局。拿 11-03 全覆盖测量 387 格回放：停时的动作和跑满 300 局按点估计的动作 0 条不一致，局数省约 45%、耗时（拍数）省约 49%。
- `tools/shot.ts` / `tools/smoke.ts`：无头浏览器截图与冒烟（用法见 AGENTS.md 第 5 节）。
- `tools/bench.ts`：核心耗时；`tools/feel.ts`：手感；`tools/cover.ts`：大厅封面。

**配平方法**：先给弱流派补强，给强流派加克制它的怪，少砍法器；改数值的 PR 里贴同口径的结果表；节奏验收（13.3）写成机器人测试（`tests/core/pace.test.ts`）。

**配平流程**（0.21.1 起）：
- **娱乐和实盘分开发**：新内容、界面、娱乐数值好了就交，实盘用 `World.newNN` 闸住、照上一个规则版本原样，不等实盘量测。
- **实盘对齐一天一批**：白天所有影响数值的改动攒着，晚上一次跑流派清点（8.1）+ 实盘量测（`--live --stop`，守夜默认线 + 最优配置线 + 夜探），第二天早上交一版实盘对齐（开实盘的规则版本 + 系数）；白天不为单个改动重跑全量。
- **白天调数值只做粗筛**：一个角色、只跑受影响的格子，约 20 分钟出方向。
- **先写验收口径再跑**：改数值前把「跑什么、过线标准、过不了怎么取舍」写下来，按口径从准备好的几组里选，不多轮试。

### 8.1 全流派配平口径

目标：至少 10 种搭配能通关最高难度，各流派有轻微强弱但不明显。

- **搭配** = 一个主流派 + 一条进化或双修路线。同一流派走不同进化，算不同的搭配。只计机器人能稳定走出来的构筑。
  - **稳定走出** = 路线走成率 ≥ 30%（危险 5）。走成率是这条路线的进化或合成在局里做成的比例。不到 30% 的路线，要么给机器人加路线策略帮它凑，要么不计入 10 个。
  - 机器人照路线优先拿配方里的法器和被动，其余照流派表（模拟器用 `--build 流派:路线`）：路线还缺的法器（没进化也没满级）和它们的进化被动优先拿；三张都不沾边就先用刷新换一批（`tools/bots.ts` 的 `critical()`，真人做得到的找卡办法）。
- **流派**：剑修、符箓、镇守、五雷、烈火、纸兵、水府，共 7 个（水府 0.7.0 加，路线 `water:spring / tide / leiyu / mirror`，全量结果见 3.4 的表）。
- **通关最高难度** = 危险 5 撑到天亮。用普通机器人，每个搭配 ≥ 1,000 局，在 GitHub runner 上分片跑。通关率 ≥ 25% 算可实现；至少 10 个搭配达标，覆盖全部流派。
- **难度曲线**：危险 5 各流派最好搭配目标 30–45%（避免太容易）；仍要保证至少 10 个搭配走成率 ≥ 30%、通关率 ≥ 25%。危险 2→3 普通胜率降 8–10 个点。普通机器人在危险 5 上普遍接近 0 时，先评估：给机器人加一档"高手"（更早躲尸王技能、更会绕圈），或调危险 5 本身；不擅自降最高难度。
  改危险档要同步核对实盘用到的档位系数（危险 0 / 2 / 3 / 4）。
- **噩梦档**（危险 6–8，0.5.0）：通关率要明显低于危险 5。目标（普通机器人，小道士，雪原）：各流派默认搭配和最强路线都落在 噩梦 1 15–30%、噩梦 2 10–22%、噩梦 3 3–15%；小白 ≤ 2%。
  机器人看得见全场，噩梦 2 起的夜色对它不起作用，真人会比表里难一截；所以噩梦 2、3 的目标定得比实际想要的松。
- **流派平衡**：参考档 = 危险 2、普通机器人，每流派取它最好的搭配，各 ≥ 1,000 局。最高和最低通关率差 ≤ 12 个百分点；任一流派离平均 ≤ 7 个百分点。排名可以有先后，但不能出现某流派明显碾压或明显没法玩。
- **双修**：没有一条组合比同流派最好的单修高 8 个百分点以上（用 `--nodual` 对照臂量净强度）；频率上，普通机器人危险 4 每 20 局合成至少 5 次。
- **实盘**：荒庙、纸兵以及全部角色 × 地图组合，用 `LIVE_CHAR_BP`、`LIVE_MAP_BP`、`LIVE_COMBO_BP` 同一套方法拟合；偏离同档平均 ±0.15 份以内才开放。新内容和配平改动一起上实盘（`LIVE_MAP_CLOSED` 留着给以后的新图用）。
- **2.0 的四个新首领和两种特色怪**（0.15.0）：换了首领的竹林、河滩、冰湖、荒庙，加了特色怪的雪原、义庄，通关率要和换之前（0.14.0，同一批种子 1..300）差 ±3 个点以内。量法：普通机器人、小道士剑修，每格 300 局（2 倍标准误约 ±4–6）。结果（改前 → 改后，危险 2 / 危险 5）：雪原 59% → 57% / 28% → 29%；竹林 82% → 80% / 49% → 46%；冰湖 56% → 53% / 13% → 10%；河滩 64% → 64% / 37% → 35%；义庄 41% → 39% / 11% → 15%；荒庙 40% → 40% / 13% → 13%。调过的：千年竹母血 4800 → 3800、技能间隔 150/115 → 175/135 拍、竹笋伤害 10 → 7、一次召竹精 5 → 3（初版竹林危险 2 掉 8 点、危险 5 掉 6 点）；棺钉鬼占比 5–6% → 1.5–2%、钉 3 → 2 枚、伤害 6 → 4、间隔 150 → 180 拍、坐起距离 280 → 220、空棺 20 → 4 秒（初版义庄危险 2 掉 21 点；把它的占比设成 0 正好回到 41%，所以是它造成的，但这么少的怪影响这么大的原因还没查清）。水猴王、冰魄娘娘、无面佛用的是 D 段的数（水猴王血 4500、无面佛血 4800、香炉全灭 ×1.5）。冰湖两档都正好差 3、义庄危险 5 高 4（危险 2 低 2，方向相反，按噪声看），0.16.0 全量配平复核。夜探新镇按同一量法（危险 2、普通机器人、剑修、每镇 200 局）对三个老镇配撤出率和撤出局平均带出价值，老镇是 古镇 50% / 407、渡口 61% / 293、山寺 50% / 362。戏楼镇初版 74% / 375，调后 57% / 384（巡夜将多一个、3/6/9/11 分钟各一；戏台 30 → 24 秒开一场、一场 8 → 11 个；红衣戏子间隔 100/70 → 70/48 拍、水袖半径 160 → 200、伤害 38 → 55；戏班鬼影占比 25%/40% → 30%/48%）。粮仓镇：街巷密（7×7 = 49 个院子，老镇 5×5），院子挨着院子，普通玩家开的铜箱是古镇的两倍多、宝库常被打开，初版带出价值是老镇平均的两倍。现在铜箱比例 0.1、木箱 8 个、不放庙、宝库在正中往东北一格（再往角上挪就比街上的木箱还浅），每格 300 局：小白 撤出 53% / 带出 178，普通 61% / 426，都在老镇平均 ±20% 以内（小白 138–207、普通 286–428；普通贴着上限，古镇自己是 436）。新镇子要先配平再放：能进的镇子是一张白名单 `RAID_OPEN`（`content/explore.ts`；菜单的 `RAID_PICKS` 从它派生），开一局夜探、链接参数 `?raid=`、再来一局都过 `raidOpen`，线上构建只认白名单，白名单外的镇子只在开发服务器（`import.meta.env.DEV`）里能进，局也不交榜（`online/score.ts`）。链接参数开的夜探只是娱乐局：实盘只能在菜单里选档位后由 `startLive` 开，镇子只认三个老镇（`RaidLiveTemplate`），所以这条路拿不到筹码。`tests/explore/raid-open.test.ts` 锁住。

### 13.8 质量（第 1 节五条）

- 60 帧：中端手机横屏 300 怪不低于 50 帧（给数字）；输入一帧内响应

## 14. 和平台的关系（夜巡是平台体系里的一个游戏，不是孤岛）

| 平台能力 | 夜巡怎么用 |
|---|---|
| 账号、登录闸门 | Worker 首页过 kit 的 `loginGate`（5.6）；单独部署时游客 |
| 钱包、实盘 | 两个模式的实盘走平台钱包（client 模式，Worker 转 RPC，先 view 再结回）；配平按 `docs/balance.md`，档位按 `docs/economy.md` |
| 战绩 | 结回时带战绩小结 `stats`（平台 5.10），只转发不改 |
| 排行、每日挑战 | `POST /api/scores`：守夜、夜探、无尽总榜，每日挑战两个，好友榜 `scope=friends`（5.7） |
| 分享卡 | 结算页"分享这一夜"：kit 的 `arcade-kit/share`（`shareCard`），图上写时长、击杀、build、咒印；标题写模式和档位，每日挑战写"每日挑战 · 守夜/夜探"，本周夜事写"本周夜事 · 这周的事件"；不上传 |
| 社交部件 | kit 的 `arcade-kit/social`：`mountSocial` 报位置（在菜单 / 守夜中 / 夜探中）、收好友邀请的横条；只在有平台且登录时挂 |

| 称号 | 成就给的称号写进 `public/titles.json`，形状照平台读它的格式（平台 5.10），平台战绩页、称号墙能显示 |
| 大厅 | 回大厅入口常驻左上，对局中离开先确认 |
