# 《夜巡》设计稿：架构与性能（第 5–6 节）

> 《夜巡》设计稿的一部分，总纲和目录见 [../DESIGN.md](../DESIGN.md)；节号和代码注释里的「DESIGN x.y」一致。

## 5. 架构

```
games/yexun/
├─ src/core/      模拟核心：固定节拍、确定性，不碰 DOM、网络、时间、随机
├─ src/content/   内容表：法器、被动、进化、怪物、刷怪表、角色、地图、夜探模板、实盘倍数
├─ src/explore/   夜探的规则（地图生成、宝箱、守卫、撤离、结算）
├─ src/view/      Phaser 4 画面层 + DOM 界面（菜单、卡片、HUD 文字）+ 程序画的图和合成的声音
├─ src/platform/  本地存储（yexun. 前缀）、云存档、实盘浏览器端
├─ src/online/    排行榜分数、每日挑战、分享卡、社交部件
├─ src/replay/    浏览器本地录像
├─ worker/        Worker：登录闸门、独立模式根路径、实盘 buyin/settle/refund（自己一份 tsconfig）
├─ tools/         机器人模拟、冒烟截图、手感和耗时测量、封面、字体子集化
└─ tests/         vitest（core/ content/ explore/ view/ platform/ arch/）
```

### 5.1 模拟核心 `src/core/`

- **固定节拍**：每秒 30 拍。`step(state, input)` 推进一拍并返回这一拍的事件（命中、击杀、升级、开宝箱、进化、撤离、结束）。
- **输入**：这一拍的方向（0 = 不动，1–32 = 32 向）+ 可选的升级选择（0–2）。升级弹卡时核心进入"选择中"，不推进时间，只等选择。
- **原地修改（设计上的例外）**：几百个单位每秒 30 拍整体复制太慢，`step` 原地修改它拥有的状态（AGENTS.md 第 4 节"输出新状态"对本模块放宽）。
  存档和回放用"种子 + 输入"重算；确定性用重放测试锁住（状态指纹）。写进模块 `AGENTS.md`。
- **数据布局**：怪、子弹、掉落物用定长的并列数组（`Float64Array` / `Int32Array`，结构数组），空位用空闲表复用，热路径不分配对象。
- **碰撞**：均匀格子分区（格子 64 单位），每拍重建一次（计数排序，O(n)）。怪与怪之间做轻推挤（只和同格、邻格的比），子弹查邻格的怪。
- **上限**：怪 300、子弹 400、掉落物 400（超了就合并最远的魂火）。
- **确定性**（不强求定点数）：
  - 坐标、速度用 JS 的双精度浮点；`+ - * /` 在所有引擎上按 IEEE 754 逐位一致；
  - **禁止** `Math.random`、`Date`、`performance`，以及 `Math.sin/cos/tan/atan2/sqrt/hypot/exp/log/pow/cbrt` 这类引擎可以近似实现的函数；
    方向用 32 向（和需要时 256 向）的单位向量表，表是**写死在源码里的常数**；需要开方的地方（追踪、归一化）用固定迭代次数的牛顿法（`src/core/fmath.ts`），只用四则运算；
  - 允许 `Math.floor/ceil/trunc/round/abs/min/max/sign/imul`（结果是精确的）；
  - 遍历顺序固定（数组下标），不用 `Map`/`Set` 的迭代顺序决定结果，不用 `Array.prototype.sort` 排有相等元素的东西（用稳定且带下标的比较）；
  - 随机数：自己写的 `sfc32`（只用 `Math.imul` 和位运算），按用途分流：刷怪、掉落、升级选项、宝箱、怪的行为、地图生成，各一条流，种子由总种子和用途名哈希得到。
    一条流多用一次不影响别的流（比如多掉一个铜钱不会改变下一张升级卡）。
  - 架构测试扫 `src/core/` 和 `src/content/` 的源码，出现上面禁止的东西就失败。
- **单位**：时间以拍计；距离以"单位"计（主角宽约 40 单位）；伤害、血量是整数，减伤、暴击等百分比按整数万分比算后向下取整。

### 5.2 内容表 `src/content/`

纯数据 + 小函数（伤害公式、刷怪表查询），被核心读取。改数值只改这里；数值变化要过模拟器（第 8 节）。

### 5.3 画面 `src/view/`

- **Phaser 4**（WebGL，失败回 Canvas）。世界层由 Phaser 画：地面、阴影、怪、子弹、特效、伤害数字；界面层用 DOM（菜单、升级卡、结算、设置），字小也清楚、好做无障碍和 44 像素检查。
  界面照全站规范 docs/ui.md：主页上的面板（图鉴、藏宝阁、玩法说明、排行、回放）都走 `view/ui/modal.ts`，右上 ✕、点遮罩、Esc 三种都能关，同时只开一个，关掉后焦点回到打开它的按钮（焦点陷阱和切标签回焦见下）；
  Esc 按"确认框 → 面板 → 设置 → 暂停"关最上一层，什么都没开时不做事；`?` 打开玩法说明「选卡」页的快捷键表；认输、回大厅这类按钮用危险样式（米底红字红边），确认框遇到危险动作时回车默认选取消；
  玩法说明（`guide.ts`）十三个页签、一个页签一页：上手、选卡、养成、角色、地图、流派、套装、进化、合成、配合、守夜、夜探、例子；没有总页数的提示。电脑宽屏（≥900×560）页内分两栏、每页一整块一屏放下，不翻页（`WIDE` 与 `guide.css` 的条件一致）；手机单栏，放不下的页再用 `pager.ts` 翻页。流派页每个流派一张卡：章（`schoolIcon`，和选关页的心法按钮同一个图）、一句话打法（`SCHOOLS[id].brief`）、核心法器和被动（图标）、主修角色和起手（取自 `content/pools.ts`，和角色页「主修」同一份）。「进化」页列满级 + 被动的进化；「合成」页（标题「合成·双修」）列当前规则版本下存在的全部配方，每条带条件徽记（合成 = 两件都进化，双修 = 一件进化 + 另一件满级，文字用图鉴共用的 `mergeHow`）和专属角色。
  选模式页所有选项直接摆出来不折叠（模式、地图、危险 0–5、角色、起手心法、噩梦 1–3、咒印、加成、无尽、开始；角色娱乐和实盘都是一个按钮，点开角色页选人），在 1280×720、1366×768、1440×900、1920×911、1920×1080、844×390、390×844、360×640 下一屏放下、页面和各栏都不滚动（冒烟第 9 段量，另加 2560×1440）；电脑、平板从上到下是 娱乐 / 实盘、守夜 / 夜探两张头图卡、地图（或镇子）横排卡（左边缩略图，右边名字、说明、特色怪小头像），下面一整条配置面板、右边大「开始」：娱乐的面板和实盘同一个排法、同高：危险 0–5 和角色按钮、起手心法一行，噩梦、咒印、加成、无尽一行，最好成绩一句，实盘的面板是档位、角色和起手心法一行，危险档一句，再一行等宽的数字小牌（回钱起点、天亮和尸王的份数，夜探是保底、待满几分钟的保底、多少铜钱算 1 份、最多几份，以及能不能放技能，细则在悬停里）；大屏整块按设计尺寸排好再整体 zoom（`--k` = min(可视宽/1476, 可视高/700) 限 1～1.6，1920×911 是 1.3，卡片不拉伸，冒烟第 9 段核 k 和块宽）。手机横屏是左右两块（左边模式和地图，右边配置和开始），竖屏一列；图鉴、藏宝阁、玩法说明、排行、回放、角色/咒印/加成页在这五个尺寸下也一屏放下，长内容按可用高度翻页（`pager.ts`）；主页的每日提示挂在顶栏"每日"按钮的角标上；所有 DOM 界面（菜单、HUD、选卡、各面板）的字号都用 `screens.css` 顶部那一组 `--fs-*` 变量（12–28 七级，手机竖屏最小一级抬到 13）；面板开着时 Tab 只在面板里转圈，切标签重画后焦点留在原来的标签上。
- **插值**：画面按真实时间跑 60 帧（或屏幕刷新率），核心按 30 拍；画面在两拍之间插值位置。
- **本地预测（验收 ②"一帧内响应"）**：摇杆一动，主角的**画面位置**当帧就按新方向挪（从上一拍的位置外推），下一拍核心算出的位置到了再平滑并上；只影响主角的画面，不进核心。
- **对象池**：怪、子弹、魂火、伤害数字、粒子都用池；同屏精灵 ≤ 1,200。
- **镜头**：跟人，带一点前瞻（朝移动方向偏一点），有界场地在边上停住。
- **打击感**（验收 ②）：命中闪白（两帧着色；同一只怪闪完隔 160 ms、精英首领隔 260 ms 才再闪，光环、寒泉这类持续伤害不会把它一直刷成白剪影）、受击后退、死亡碎片、发光叠加（ADD 混合）、拖尾、暴击和大招停顿（hit-stop：画面暂停送拍 40–80 ms，核心按拍走，不影响确定性）、伤害数字弹跳、连斩毛笔字横幅加墨点。
  震屏只给大事件（进化、精英和尸王倒下），平常命中不震；受击后退是缓出（一下推开、慢慢回位）加轻压扁，大怪几乎不退；死亡先弹起、撑开压扁再淡出；主角起步轻拉长、停步轻压扁（预备和余势）。
  伤害数字：同一只怪接连挨打合成一个数往上加；离主角胸口 70 以内的往外推，不挡主角。这些都只在画面层（`GameScene.ts`、`fx.ts`）。
- **HUD**：布局规则见 docs/art.md 第 2 节。
- **iOS / 手机**（仓库根 AGENTS.md 第 4 节，照开盘的做法）：触屏设备渲染倍数封顶 2，地面这类整屏大图按 1 倍；高度按 `visualViewport` 算的 CSS 变量；双指放大时不改尺寸；WebGL 丢失等几秒才提示、恢复时收起；safe-area 四边让出；省内存设备（触屏且 `deviceMemory ≤ 4` 或 iOS）关粒子、伤害数字减半。
- **图集**：开局用 Canvas 2D 画进四张图集，每张 ≤ 2048 × 2048：主图集、夜探图集、特色怪图集（含纸兵）、角色图集。主图集在渲染倍数 3 时已接近上限，新图放别的图集。
- **横屏与竖屏**：游戏按横屏设计；竖屏也能玩：世界缩放按屏宽定（一屏宽看 460 单位），竖屏开的局刷怪圈转 90°（`setup.tall`，录进录像），横屏局不受影响。

### 5.4 输入和录像（本地）

- 方向量化成 32 向：键盘 8 向是其中的子集；摇杆按角度取最近的一向，拉动不足死区算不动；力度只分两档：拖动距离在死区（10px）外、18px 以内是慢走（只留窄窄一圈：短拖很常见，慢走区宽了玩家会不知不觉变慢，实盘里等于暗中加难度；慢走时摇杆头缩小变淡），输入值 = 方向 + 32（33–64），核心里速度乘 0.5，再远是全速（连续力度会让录像变大，两档足够微调走位）。键盘和机器人只出 0–32，旧录像逐位不变，不升规则版本；录像里慢走写成 `~` 加方向符号。
- **录像 = 规则版本 + 模式 / 档位 / 难度 / 角色 / 加成快照 + 种子 + 每一拍的方向（游程压缩）+ 升级选择（按拍号）**。一局 15 分钟 27,000 拍，摇杆平均几拍换一次方向，压缩后几 KB 到十几 KB。
- **只存在浏览器本地**：`yexun.replays` 存最近 5 局和每个榜自己最好的一局，总量控制在 300 KB 内（超了先删最旧的普通局）。页面能回放自己的录像（暂停、2×、4×）。
  这是玩法功能（看自己怎么打的、发给朋友看的截图），也方便复现 bug。
- 规则版本变了的旧录像标"旧版本，可能放不对"，不删，一律按现行规则重放（不保证跨版本）。
- **为什么不做服务端录像存储和校验**：排行榜和其他游戏一样不防作弊（`docs/project.md` 第 3 节第 7 条）。
  **以后要加**：录像格式已经是"种子 + 输入"，加一个上传接口、在 Worker 或维护者工具里用同一份核心重放比分数即可，核心不用改。

### 5.5 平台接入 `src/platform/`

- 存储 key 一律 `yexun.` 前缀，全表见 AGENTS.md 第 6 节。
- 云存档（平台 5.5）：同步 `profile` 一个槽（铜钱流水、加成、解锁、藏宝阁、成就、统计，估计 < 4 KB）和教程标记；不同步打到一半的那一局、设置、录像。合并：集合并集、计数取大、铜钱取"按局 id 去重后的流水"之和（避免两台设备各花各的出现负数，具体写进 `cloud.ts` 的注释）。
- 进页面先 `GET /api/me`（`detectPlatform`）：独立部署时藏起登录、云存档、排行榜、实盘，"回大厅"改成回游戏首页。

### 5.6 Worker `worker/`

- 入口只导出 `default`（单独部署时具名导出会让 Worker 起不来）。
- 首页三种写法过 kit 的 `loginGate`；站点根 `/` 和 `/api/me` 过 `standaloneRoot`（独立模式）。
- `/games/yexun/api/live/{buyin,settle,refund}`：照开盘 0.11.2——浏览器只给 `ref`、`tier`、`bp`（倍数万分比）、可选战绩小结；带入金额固定是这一档一份、到期 24 小时由 Worker 定；
  **结回前先 `WALLET.view` 取桌上这一份的金额按它算**，不信浏览器报的档位；CSRF（`X-Arcade: 1` + Origin）、请求体 ≤ 2 KB、超时 5 秒；独立部署回 501 `no_wallet`。
- `GET /games/yexun/health`（`worker/route.ts`，入口 `index.ts` 只导出 default）：回 `{"ok":true,"version":"<package.json 版本>"}`、不缓存，给平台巡检用；排在最前面，不过登录闸门、不读存储、不问平台，单独部署时也能访问。
- **没有 Durable Object**（不做联机、不做服务端录像），所以 `wrangler.jsonc` 只有静态资源，外加 `observability`（Workers Logs）。
- 浏览器入口调共用包的 `reportErrors`（`arcade-kit/report`），页面里没人接住的报错发到平台 `/api/client-error`：只带报错、调用栈、路径、游戏和版本，每页最多 5 条。

### 5.7 排行榜

照其他游戏的简单版：页面直接 `POST /api/scores`，不经过游戏 Worker，不防作弊（平台 15.5）。分数公式在 `src/online/score.ts`，榜的显示写在 `public/boards.json`、`public/daily.json`。

| 榜 | boardId | 分数 |
|---|---|---|
| 守夜总榜 | `vigil`（固定榜） | 危险档 × 1e10 + 撑到的秒数 × 1e4 + 击杀（击杀 < 1e4）；打倒尸王算撑满 900 秒再加 100 |
| 夜探总榜 | `raid`（固定榜） | 单局撤出的宝物价值（铜钱） |
| 无尽 | `endless`（固定榜） | 活了多少秒 × 1e4 + 击杀 |
| 每日守夜 | `daily-YYYY-MM-DD-vigil` | 撑到天亮：1e6 + 击杀；没撑到：撑了多少秒 |
| 每日夜探（未开：主页只开守夜每日，`dailyPlan` 和交榜留着夜探分支） | `daily-YYYY-MM-DD-raid` | 单局撤出的宝物价值 |
| 每日连战 | `daily-YYYY-MM-DD-rush` | 全清 × 1e9 + 打倒几只 × 1e7 + 一共几只 × 1e5 + 尾数（全清：剩下的秒数；没全清：最后一关打掉的百分比），见 2.5 |
| 本周夜事 | `week-YYYY-Www-vigil` | 同守夜总榜公式（5.8） |

每日挑战：全服同一种子、同一张图、同一组当日咒印；固定角色、不带加成；规则版本变了榜名后面加 `-v<n>`。
周日噩梦日（2026-11-01 起）：守夜的每日挑战在周日改打噩梦 1（危险 6），当日咒印只留 1 条，选档行写「周日噩梦日」；随机数的抽法不变（只截掉多抽的咒印），夜探不变。
主页「开始 / 选模式」下面有一行不可点的提示（只管守夜每日）：平时写「每日守夜 · 周日噩梦日 · 还有 N 天」（`daysToNightmareSunday`，按北京日期，11-01 之前数到 11-01），噩梦日当天换成红色「噩梦日」小标加「噩梦 1」。
只交娱乐和每日挑战的成绩（实盘不上榜）；每日挑战只进当天的每日榜，不进总榜；开了"降低伤害"的局不交总榜；认输的不交（无尽除外）。好友榜用平台的 `scope=friends`。一局结束出结算画面时交一次。

### 5.8 每周夜事（`src/content/weekly.ts`、`src/online/weekly.ts`）

一个单独开局的每周挑战，像每日挑战那样：主页「本周夜事 · XX周」按钮（`view/ui/weekly.ts`，≥ 44×44，样式限定在 `.yx-menu` 下、类名 `yx-mweekly`）点一下直接开局，
对局标签写「本周夜事 · 铜钱周 · 危险 2」，结算页「再来一局」再开同一个挑战。**普通守夜、实盘、夜探、每日挑战都不挂周事件**（试炼「月黑」借用月蚀周的效果），总榜和每日榜不受影响。

- **轮换**：北京时间每个自然周（周一起）一个事件，从 5 项的表里按周序号取余轮着来（周序号从 1970-01-05 那个周一数起，不用随机，同一周所有人、所有设备一样，`weeklyFor`）。
  地图按同一个周序号轮换写死的 6 张图（`WEEKLY_MAPS`，不看玩家解没解锁；5 和 6 互质，事件和地图的搭配要隔 30 周才重复）。鬼市不在里面：新图加进守夜不改这周的图，要加进来就从某周起换一张新表。
- **固定配置**（`weeklyPlan(date, seed)`，返回 `{ week, event, setup, boardId }`）：本周事件、轮到的图、危险 2、小道士、不带加成、不带咒印、不开降低伤害。
  种子每局随机，一周可以多打几次取最好。开局走 `main.ts` 的 `startRun(…, fixed, 'weekly')`，`Setup.weekly` 随录像保存；规则核心不碰日期，只认这个字段，没有 = 不开
  （`normalizeSetup` 会把实盘、夜探里的去掉），所以普通局和以前逐拍一样，金标准不变。
- **周榜**：榜名 `week-<ISO 周>-vigil`，例 `week-2026-W44-vigil`。ISO 周按北京时间，周一 0 点换周，年份按该周周四所在的年（`beijingIsoWeek`：2026-12-31 和 2027-01-01 都是 2026-W53，2027-01-04 是 2027-W01）。
  计分同守夜总榜（`vigilScore`，显示用 `formatScore('weekly-vigil')`，危险 2 × 1e10 + 秒数 × 1e4 + 击杀）。本周夜事的局**只交周榜**，不交总榜、不交每日榜；
  平台只收本周的榜：开局那天不在本周的不交，只有周一当天还能交上周的（`weeklyDateOpen`，照每日榜的 `dailyDateOpen`）。认输的不交。排行页多一个「本周夜事」标签。

## 6. 性能预算

| 项 | 预算 | 怎么量 |
|---|---|---|
| 核心一拍 | 300 怪 + 400 子弹时 ≤ 2 ms（中端手机），≤ 0.5 ms（电脑） | `npm run bench -- --worst` 在 Node 跑满载；手机上带 `?fps` 看帧率 |
| 一帧 | 16.7 ms；中端手机横屏满载 p95 ≤ 20 ms（≥ 50 帧） | 冒烟里记 `requestAnimationFrame` 间隔；手机实测写进 PR |
| 首包 | 游戏代码 ≤ 250 KB gzip（Phaser 另算，单独成块缓存）；字体子集 ≤ 120 KB | 构建输出 |
| 图集 | 四张图集每张 ≤ 2048 × 2048（省内存设备渲染倍数 ≤ 2） | 开局一次，计时写进 PR |
| 内存 | 省内存设备 ≤ 200 MB | 暂无专用估算工具，靠渲染倍数封顶 2、图集尺寸和 `?lowmem` 冒烟兜底 |
| 模拟器 | 一局（无画面）≤ 1 秒；2,000 局一格用多线程跑完，大批量拆到 GitHub runner | `tools/sim.ts` |

实测（0.0.17，2026-10-17，Node）：`bench --worst`（300 怪满额、12 件法器全进化、主角无敌绕圈）每拍平均 0.24 ms、p99 0.53 ms、最慢 0.64 ms，p99 略超电脑 0.5 ms 的预算，可接受、不为它再改。
首屏（0.35.1）：主页只要 `index` 块（游戏代码、图集画法、规则核心）；Phaser 和对局场景在 `app/engine.ts` 一块，主页画出来后动态加载，起好后空闲时传三张常驻图集、帧循环睡着，开局和回放叫醒、回主页再睡。
WebGL 批大小 4,096（Phaser 默认 16,384，开机顶点缓冲大四倍）。`index` 现在 gzip 274 KB，超首包预算 24 KB：规则核心还在里面（回放、成就统计、每日、几块界面在开机时就引用），要再降就把这些引用挪到引擎块后面。
量法：线上构建（`build:cf`）在无头浏览器里开，电脑 1280 + 手机竖屏 CPU 4× 降速，记主页出来的时间、长任务、帧间隔、WebGL 绘制和纹理上传、样式和布局耗时；改前改后交替各跑几轮取中位数。
无头浏览器没有 GPU，帧率是软件渲染的下限，一帧的预算以真机为准：带 `?fps` 打开，左下角显示每秒帧数、这一秒最长的一帧和场上怪数，手机横屏不到 30 帧不过关。
