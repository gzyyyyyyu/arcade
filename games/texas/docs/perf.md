# 德州扑克：画面性能实测

> 结论和由此定下的约束在 [screens.md](screens.md) 8.7；这里是怎么量的和量到的数。

## CSS 重绘

方法：无头 Chromium 模拟省内存手机（844×390、像素比 2、触屏、CPU 降速 4 倍），自动打 4 手左右，读主线程总占用（`Performance.getMetrics` 的 `TaskDuration`），
用注入样式的办法对比去斜纹、独立合成层、纯色背景、去阴影、去动画、去过渡等方案，每个方案跑两轮以上。

结论：背景和毡面的多层斜纹（`repeating-linear-gradient`）不是负担。画面在降速 4 倍的手机上主线程占用约 11%（折算不降速约 3%），脚本约 0.5%，样式重算 1–2%；各方案的差别都在 ±3 个百分点的噪声里，所以**不为性能改 CSS**：
去斜纹会丢掉毡面的织纹质感，加独立合成层会多吃老 iPhone 的内存。唯一看得出的下降来自整页关掉动画和过渡（约 9%），而动画本来就是画面要的反馈。要再优化，先用 Chrome 的性能面板看具体哪一帧在画，不猜样式。

## 打开和对局（`scripts/perf.ts`）

`npm run build:cf && node scripts/perf.ts [--runs 3] [--play 40] [--out 结果.json] [--profile 目录]`：真的 Worker + 冒烟的假平台，电脑 1280×800 和手机竖屏 390×844（CPU 降速 4 倍）各跑几遍取中位数，
量主页（FCP、LCP、可交互、长任务和超出 50 毫秒的部分之和 TBT、传输字节）、选桌页打开、对局中按默认动画速度打 40 秒（帧间隔 p50/p95/p99、长任务、JS 堆），以及带哈希的资源是不是 immutable。
前后比较要背靠背：同一台机、同一口径连着跑，经 browser-slot 的 exclusive 占满浏览器位子（别的代理同时跑会把长任务量多一倍）。`--profile` 存手机那一遍的 CPU 采样（看函数名先 `vite build --minify false`）。
冒烟的假平台开了请求拦截，Playwright 这时不用 HTTP 缓存，"再次打开"量不出来，只核对头。

现行数（各 3 遍中位数，毫秒；本机空闲时）：

| | 电脑 | 手机（降速 4 倍） |
|---|---|---|
| 主页 FCP / LCP / 可交互 | 132 / 332 / 136 | 368 / 452 / 464 |
| 主页 TBT | 14 | 218 |
| 选桌页打开 | 55 | 126 |
| 对局中帧间隔 p99 / 长任务 / 最长 | 16.8 / 0 / 0 | 16.8 / 1 / 62 |
| JS / CSS（gzip，KB） | 148 / 26 | 同左 |

剩下的：主页那个长任务主要是首次排版（无头 Linux 里第一次找中文字体回退约占一半，真机不同），脚本执行只占约 20 毫秒；
JS 一个包，按需拆出好友房、谜题、分享能省约 13%，但主页可交互几乎不受脚本大小影响，要拆得把页面装配改成异步。
开桌到底牌翻开约 3 秒是发牌动画的节奏，不是卡顿（CPU 只忙约 0.4 秒），电脑上这项随发牌顺序在 2.9–3.4 秒之间跳。

- 牌桌、舞台、body 上不写 `:has()`（docs/screens.md）：手机打 8 手，有它时每次样式重算平均 596 µs，去掉后 311 µs。
