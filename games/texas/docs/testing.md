## 9. 测试

| 层 | 内容 |
|---|---|
| 牌力（vitest） | 每种牌型和踢脚的边界（A-2-3-4-5、同花顺对同花、两对比第三张、葫芦比三条那组）；全量 1.34 亿手的牌型计数和 4,824 个等价类；和朴素实现对拍 10 万对 |
| 规则（vitest） | 两人桌和多人桌的盲注与说话顺序；按钮跳过输光的人；最小加注；**全下不够一次加注不重开**；没人跟的下注退回；**边池**（3 人和 4 人不同筹码全下、弃牌的人的钱留在池里）；**平分和零头**；摊牌顺序和自动盖牌；全下后自动发完；超时过牌或弃牌、连着两手超时转暂离 |
| 复现 | 同种子同操作 → 每一步的状态完全相同（深比较 + JSON）；换种子牌不同；状态 JSON 存取前后一样；随机数用途名的哈希互不相同（ChaCha20 的 RFC 8439 测试向量在 kit 里锁住） |
| 隐藏信息 | 随机几千手，每个座位的 `view` 里不出现别人没亮的牌；`lastHand` 只含真的亮出来的牌；`snapshotBytes` ≤ 8 KB（最坏：9 个真人座位、河牌、长操作记录） |
| 机器人对打 | 10 种性格随机 2–6 人桌连打 1 万手：不卡死（每一刻要么有人能说话要么一手结束）、电脑从不出不合法的操作、**每一步桌上的筹码 + 池子守恒**（只在买入、离桌、电脑换人时按记账变化）；记每种性格每百手的输赢，调参数用 |
| 大场面（`test/core/climax.test.ts`） | 补牌胜率：缺一张穷举、河牌后 1000/0 和平分、翻牌前抽样同局面同数；庆祝档次（葫芦 1 档，四条、同花顺、皇家 2 档，同花顺子不庆祝、弃牌赢和输家大牌不触发）；被逆转（转牌领先 ≥ 80% 才算，领先的赢了、平分、弃牌、没发河牌都不算）；池子分档的门槛 |
| 电脑 CPU | 单次决策和一批的 p50 / p99，超过预算（豪华桌单次 p99 2 ms、一批 p99 10 ms）测试失败 |
| 架构 | `src/core/`、`src/ai/` 里没有 `Math.random`、`Date`、平台相关的数学函数；`src/ai/` 不引用完整状态；浏览器存储的键都以 `texas.` 开头；核心不引用 DOM 和网络 |
| 钱包（vitest + workerd，对着假平台 `arcade-kit/testing`） | 单机每个操作调平台几次、平台写几行如实断言（带入 1/1、重发 1/0、结回 1/1）；CSRF、请求体不对、没登录的不调平台；平台连不上 503；进账到顶 `capped`；好友房的 ref、重办只认一次、结回忙时重办；随机漫步核对每一份正好结回一次 |
| 房间（workerd） | 每步 ≤ 2 行；德州的批量出手 CPU；结算失败重试、关房前先结算；挂机的桌每小时写入上限；接管电脑座位"下一手换买入" |
| 锦标赛、止盈（vitest） | `test/tour/tour.test.ts` 规则（盲注表、淘汰、名次、奖金）；`test/tour/tour-solo.test.ts`、`test/tour/tour-room.test.ts`、`test/worker/tour-room.test.ts`（14.2、14.3）；`test/core/takeprofit.test.ts` 止盈的目标和判定（8.13） |
| 配平、互动（vitest） | `test/ai/tuning.test.ts` 娱乐新手档小白平均赢、高手档平均输（4.10）；`test/ai/levels.test.ts` 场地和难度到强弱档的映射；`test/core/moments.test.ts` 名场面怎么认、电脑的互动性格（13.7） |
| 新手指引（vitest） | `test/core/guide.test.ts`：状态只出一次（走完、跳过、怎么玩重置、老玩家的旧标记）、结果/摊牌提示各一次、五种屏幕尺寸下说明框摆在屏内且不压目标 |

## 12. 已知取舍和要注意的

- **故意输给朋友**：德州里一个人完全可以故意把筹码输给另一个人，这在牌桌上和"打得烂"分不出来。规则上不提供任何转让、赠送；
  牌桌上的输赢就是打牌本身，不去区分。筹码没有价值，好友房买入固定、有上限，能挪的量有限。
- **单机可以改输赢**：按"不防作弊"的决定接受；以后如果做筹码排行（平台固定榜，需要登记），榜上的数同样不防作弊。
- **免费版 CPU**：DO 和 Worker 免费版设不了 `cpu_ms`；德州一批本地实测最大几毫秒（豪华桌，4.4）。
- **规则版本**：状态记 `rv`（`RULES_VERSION`），进行中的牌局按开局时的版本打完；改规则加版本号。
