# 海岛工具和命令细节

> 从 AGENTS.md 搬来。命令表在 AGENTS.md，这里是各工具的完整参数和口径。

## 规则核心目录说明

src/core/      规则核心：基地（建造、升级、产出、收取）、战役结算、战斗（固定步长 20 拍/秒、确定性）、机器人、异步攻防结算（pvp.ts）、快照校验（validate.ts）、悬赏出海和兑换的表（live.ts）、护航和航线实盘的档位表（escortlive.ts、maplive.ts）；进攻战斗里同一个规则版本区间一套函数：`battle.ts` 的 `stepDefensesLegacy` / `stepMinesLegacy`（规则 < 6，旧回放专用）、`stepDefensesBranches`（6–8，塔带分叉）、`stepDefensesCombat`（≥ 9，接入共用的 combat.ts）、`stepMines`（≥ 6）、悬赏守岛的档位和倍数表（tdlive.ts，岛模板在 content/tdlive.ts）、大潮无尽的周算法 / 周种子 / 图和关卡 / 得分编码（tdtide.ts，四张图模板和按波数生成的波次在 content/tdtide.ts）、守岛塔防（td.ts 开局、操作和每拍的战斗，tdhero.ts 英雄（走位、守点、自己挑站位、跟船），tdhook.ts 英雄的锚钩（规则版本 20：开放条件、整数格拉回路线、拖着走、机器人挑目标），tdnav.ts 第二个英雄航海士（规则版本 23：开放条件、急射旗的圈、两个技能怎么放；机器人插旗、画圈在 tdbot.ts 的 `flagSpot`、`rewardSpot`），tdquery.ts 给界面 / 机器人的预告、路线、卖塔清障叫波的出口，tdmech.ts 章末机制（规则版本 16 起每章最后两关的玩家工具），tdevent.ts 关内事件（规则版本 22：赏金船、暴雨、战书，开局挑波）和大潮海况的击杀金、英雄冷却，tdstate.ts 几处共用的状态、塔和英雄数值、流场，td2types.ts 克制表、阶、驻守台、预算公式、星数区间，tdrun.ts 战役 24 关的开局和结算，tdhome.ts 海盗来袭（含加难档、规则版本 21 起按布局挑登陆点），tdbase.ts 分叉和英雄研究和 pvpSnapshot，tdbot.ts 机器人，tdtypes.ts）、护航（escorttypes.ts 类型和常量，escort.ts 船和咬船的纯函数，td.ts 和 tdhero.ts 里 `if (s.escort)` 的分支，escortbot.ts 机器人，escortrun.ts 开局、解锁和结算）；grid.ts 是登陆战和守岛共用的格子流场找路（tdpath.ts 只是旧导入路径的再导出）；types.ts 是公共类型
src/content/   内容表：建筑、兵、旗舰技能、主寨等级、战役关卡、塔的分叉（branches.ts）；守岛的数（td2units.ts：塔的三阶、统一敌人表、英雄技能、局内经济、难度预算、海盗来袭）、11 张关卡岛（td2maps.ts）、24 关的波次配方和旋钮（td2levels.ts，tdmaps.ts 是出口加单测用的样板关）、守岛里分叉的解释（tdbranches.ts）；护航的 3 张航线图（escortmaps.ts）和 9 关（escortlevels.ts）；改数值只改这里

## tools/ 目录

tools/         art-preview.ts（素材渲成 PNG 看图，不开浏览器；`scaffold.png` 是升级脚手架围住建筑的样子）、sim.ts（机器人打每一关）、raid-sim.ts（驻岛英雄、宝藏箱、分叉进攻防前后的配平）、shot.ts（无头浏览器截图冒烟；本身只管参数、起服务、按开关分派，各流程按主题在 shot-base / shot-td / shot-escort / shot-map / shot-pvp / shot-flow.ts，共用的小函数和每个视口的上下文在 shot-lib.ts（基地里点建筑用 `tapBuilding(kind)`：竖屏初始视野常看不到要点的建筑，`where()` 给的是屏幕外的坐标，它先像玩家一样拖地图把建筑拖进屏幕再点），假平台 shot-fake.ts，录像 shot-record.ts）、args.ts（各工具共用的命令行参数解析：opt / num / flag）、perf.ts（帧率和卡顿测量、帧时间曲线、连拍拼图；输出目录里的 perf.md 末尾有"质量线"表：p95 / 中位数 ≤ 1.5、无 > 50ms 长帧、手机降速 JS ≤ 8ms / 帧）、record.ts（shot.ts --record 用的录像）、rig-preview.ts（分件骨架的动作渲成 PNG）、turret-preview.ts（炮台底座和 16 个方向的炮管渲成 PNG）、layout-check.ts（界面拥挤度自动测量）、result-strip.ts（结算演出连拍拼图）、ui-compare.ts（基地、登陆战、守岛固定时刻的前后对比截图：手机竖屏、手机横屏、1280×720、1920×1080 四种视口，基地另拍红点、操作环、放大后的"全景"钮、个人面板，以及悬停名牌、右键菜单、升级面板、升级演出连拍、摆放能放 / 不能放；`--rec-up` 在 1280×720 再录主寨和伐木场的 60 帧升级演出 webm）、sfx-render.ts / sfx-result-wav.ts（音效渲成 WAV）、bake-time.ts（开局烘焙耗时）、content2-preview.ts（狙击塔、盾兵等新素材整张图预览）、td-live-lib.ts（悬赏守岛配平的共用部分，td-live-sim / td-live-merge 用）、econ.ts（经济估算：每天上线几次、每次出海几场（`--fights`）守岛几局（`--td`），这一级建满才升主寨，末尾打"主寨 n → n+1 用几天、几场、几局"的表；`--quiet` 只打这张表）、map-sim.ts（寻宝航线配平）、pace.ts（战役节奏取证：按真实分钟记盼头事件）、sample.ts（模拟和测试共用的"该主寨等级的典型部队"）、fun-shot.ts（宝箱、援军、撤回、试打自己的岛的真实画面冒烟）、noscroll.ts（量六个尺寸（五尺寸加平板竖屏 820×1180）是否滚动、重叠、裁字（含字穿出牌子和按钮的外框；基地主界面另拍一张主寨 8 级、资源上限五位数的；「守岛选关」组用塔选了分叉的存档——`dev.td(hq, true)`，一档、两档交替——驻守台卡片上的分叉牌才量得到）以及质量线四项：触屏顶底栏占比 ≤ 22%、岛可见 ≥ 60%、点按目标 ≥ 44 且间距 ≥ 8、局内同屏文字牌 ≤ 6，口径写在文件头：`node tools/noscroll.ts --out <目录> [--group 流程名] [--view 尺寸]`）

## 长命令说明

| 命令 | 用途 |
|---|---|
| `node tools/live-sim.ts --n 2000 [--tier small] [--from 1]` | 悬赏出海（岛是 `src/content/bountylevels.ts` 的冻结副本，和战役关卡无关；改副本才要重跑）每档每种机器人的期望（份）± 2SE、赢的场次、星数分布、时长（用 `nice` 跑） |
| `node tools/td-live-sim.ts --n 2000 [--tier small] [--from 1] [--json]` | 悬赏守岛：每档两种机器人的期望（份）± 2SE、星数分布、0 星平均撑过几波；`--json` 拆片在 CI 上并行跑，再用 `node tools/td-live-merge.ts 片1.json 片2.json …` 合并（改 `src/core/tdlive.ts` 的倍数表或 `src/content/tdlive.ts` 的岛后要重跑，用 `nice`） |
| `node tools/td-sim.ts [--level td07] [--n 200] [--parts main,anti,hero,care,budget,layouts] [--json] [--rules 13] [--hero nav]`（`--rules` 按旧规则版本打，比规则改动前后；`--hero nav` 带航海士） | 守岛 24 关（关卡岛 + 驻守台，建议养成）：小白、稳、贪三种机器人的星数分布和三星率，另报照建议的新手（`guided`）至少 1★（新手线按它量）、局末没花的金币、升满阶（第几波所有能造的塔位都是 3 阶，没升满的局不算，另报升满的局占几成）；`anti` 全造一种塔、`hero` 英雄拆开看、`care` 零 / 建议 / 满养成、`budget` 预算 ±2%、`layouts` 三种守法（铺开 / 集中 / 先升高阶）；对照 DESIGN 10.4 的验收目标。大批量按关拆片在 CI 上跑（`--json`，再 `--merge` 合并），只跑小样本、用 `nice`；改规则或数值有意改结果时用 `node tools/td-golden.ts` 重生成指纹 |

| `node tools/escort-golden.ts` | 重生成护航指纹锁 `tests/escort-golden.json`（156 局，约 4 秒）：九关和实盘四档，各按规则 24、25 × 种子 1–3 × 小白、普通两种机器人打完一局。生成后 `git diff` 只许出现预期的键变化；`tests/escort-golden.test.ts` 还锁住规则 25 下只有新手档和 24 不同、实盘开局不跟随 |
| `node tools/escort-live-sim.ts --n 2000 [--from 1] [--tier small] [--json 文件]`、`--merge 片…` / `node tools/map-live-sim.ts --days 2000 [--from 2026-11-10] [--json 文件]`、`--merge 片…` | 护航、寻宝航线实盘：每档两种机器人的期望（份）± 2SE、对照 balance.md 第 2 节、星数分布、0 星平均折算、时长；共用 `tools/live-fit-lib.ts`（汇总只存星分布和 0 星折算，合并时按当前 bp 重算，只改 bp 不用重跑）。改 `src/core/escortlive.ts` / `maplive.ts` 的表，或改了实盘借用的护航关（`escortlevels.ts`）、航线的岛和船队（`content/maps.ts`）都要重跑并更新 DESIGN 12.1 / 11.1；`nice -n 10`、拆片并行最多 8 片 |
| `node tools/escort-sim.ts --n 40 [--level strait-easy]` | 护航 9 关：小白、普通机器人的胜率（到港且 ≥ 1★）、星数分布、沉船率；改 `content/escort*.ts` 或 `escortbot.ts`、船速修船常量后重跑并更新 DESIGN 第 12 节（用 `nice`） |

| `npm run shot -- --out <目录>` | 无头浏览器冒烟截图（临时端口），电脑和手机竖屏：基地、机器人代打一关（`--level c04` 换关）、结算，检查控制台零报错和按钮 ≥ 44 像素；`--flow` 用新存档真人点一遍：引导收金币 → 建金库 → 主寨操作环和信息面板 → 船队 → 出海 → 登陆两条船、放炮击 → 结算 → 回家，每步截图；`--td` 真人点一遍守岛一关（默认第 1 关，`--level td07` 换关，选关页会先点到所在章节的标签；驻守台选塔 → 预告卡和地图路线旗 → 敌人图鉴和克制表 → 建塔、升级、卖塔 → 清障 → 英雄走位、拒马、炸药桶 → 开打（电脑用空格和数字键）→ 结算；加 `--nav` 带航海士：驻守台面板上点「带：航海士」，技能一步换成往最近那座塔的方向插急射旗、在英雄身边画重赏圈，核对规则状态里旗和圈都有了）；`--home` 真人点一遍海盗来袭（选关页入口 → 开局 → 造塔、开打 → 撑到结束，4 分钟没完就撤退 → 结算不落星 → 回岛）；`--cam` 量镜头（默认手机竖屏和 1920×1080）：竖屏守岛开场先全景再推镜（内容盒推镜后约占屏高 60%）、拖开后屏边出敌人箭头且点了镜头会移、登陆战开场同样推镜，电脑上守岛内容盒完整在屏内，每处查按钮 ≥ 44 像素和两两不重叠，各截一张；视口 `--view desktop,wide,phonep,phone,small`（wide = 1920×1080，small = 360×640，只在显式指定时跑）；`--pvp` 用真实的接口处理函数加内存存储模拟服务端，真人点一遍找对手 → 进攻 → 结算、被打通知、回放、复仇（还让假服务端回一次 need_reload，截「游戏更新了」弹窗）；`--tide` 真人点一遍大潮无尽（守岛选关页的大潮入口 → 开局 → 造塔、英雄、技能、叫波 → 撑到结束，不到 4 分钟就点撤退 → 结算页；`/api/scores` 用 `page.route` 拦下回 `{best, improved: true}`，核对请求体只交了一次、`haidao.tide` 记上了）；`--map` 真人点一遍寻宝航线（默认电脑 1280×800、1920×1080、手机竖屏三个视口：出海 → 今日航线卡 → 航线图 → 整备 / 补给礁 → 真人登陆打每一站 → 站间条 → 终局演出 → 结算 → 分享 → 回岛；`/api/scores` 拦下核对榜名 `daily-<日期>-map` 和只交一次；电脑那一遍从最后一站的站间条起按 60 帧录终局演出 `map-final.webm`，`--rec-out` 指目录）；`--tdlive` 同样用真实的 `handleLive` 加内存假钱包（`tools/fake-bank.ts`），真人点一遍守岛选关页 → 悬赏守岛选档 → 带入 → 造塔、英雄、叫波 → 结算 → 回家。`--escort` 真人点一遍护航（出海海图的护航卡 → 选图选难度 → 造塔 → 停 / 冲 / 修船 / 跟随 → 打到结束 → 结算 → 回岛），查速度钮 ≥ 44 像素、当前档高亮。`--record <目录>` 录动作短片（需要 ffmpeg 带 libvpx-vp9）：视口 480×400、关泛光、开 `?mt1`，镜头跟住一个单位放大 `--rec-zoom`（默认 1.5）倍；登陆战（`--level`，默认 c07）按 `--rec-kinds sailor,brute[:个数]` 每个兵种开一局录走路、攻击、倒下，守岛（td03）按 `--rec-td`（默认 any，空串不录）录走路和倒下；默认停下帧循环每次推 16.67ms 截一张，拼成 60 帧 webm（`--rec-fps live` 改用 CDP 屏幕广播录实际出的帧），每段另出一张均匀取 12 帧的拼图 png；`--rec-towers battle,cannon,mortar,harpoon,flame,gunTower:1.4,rocket` 录炮台（`battle` = 登陆战里离兵最近的塔，其余是守岛 td03 在 `--rec-slot`（默认 0）塔位上造这种塔再叫波；`种类:倍数` 单独定镜头缩放，默认 `--rec-tzoom` 0.75，镜头对准塔和目标之间）。|
| `node tools/perf.ts --out <目录> [--secs 25] [--runs 2] [--views phone4,desktop] [--scenes battle,td] [--battle c07] [--army 8] [--td td03] [--calls 2] [--focus goldmine] [--zoom 1.1] [--only fps\|diag\|shot\|sheet]` | 帧率和卡顿测量：无头 Chromium，手机竖屏（CDP 降 CPU 4 倍）和桌面 1280×800 各跑登陆战（默认 c07）和守岛（td03）；`--scenes base` 量基地（7 级满配岛，不点东西），镜头 `--focus` 对着一种建筑（`kind#i` 第 i 座）、`edge`（离岛心最远的资源建筑）、`<格x>,<格y>`（任意一格，海上可以是负数）或 `home`（全岛远景），`--zoom` 是相对全景的放大倍数（建筑最密的岛中间 `--focus 11,11` 最慢），固定存档加按拍数对齐的真人点击（不开 auto）。fps = 页面 rAF 计帧（平均帧率、中位 / p95 / p99、p95 ÷ 中位、>33ms / >50ms 长帧、游戏 rAF 回调每帧 JS 耗时、非脚本时间 = 中位帧时长 - JS 平均（没有 GPU 时主要是软件光栅化，单列）、longtask、显示对象数和录完时场上的兵 / 敌人数），每个视口和场景另出一张帧时间曲线 `curve-<视口>-<场景>.png`（帧时长、JS、中位 / 1.5 倍中位 / 50ms 三条线），逐帧数据在 perf.json；diag = CPU 采样（按函数 / 文件的自身耗时、GC）+ WebGL draw / 传贴图计数；shot = 固定拍数截图，前后对比用；sheet = 桌面登陆战里同一个兵连拍 6 帧、主寨受损四阶段、一座建筑倒塌连拍 6 帧，每组拼成一排（`sheet-desktop-*.png`）。输出 perf.json、perf.md、png。大场面：`--army 8` 用主寨 8 的满编船队打登陆战（`sampleProfile`），`--td td14 --calls 6` 换关、每 60 拍叫一次波把几波敌人叠在岛上。没有 GPU 的机器上（SwiftShader 软件渲染），绝对帧率偏低，只看前后对比，并在相近负载下各跑 2 次 |
