## 场景分工

- **登陆战场景的文件分工**（`BattleScene.ts` 只管生命周期 `init` / `create` / `update`、逐拍推进 `stepOnce`、镜头适配、开场俯瞰；拆出去的文件里，场景方法改成第一个参数是场景 `bs` 的函数，字段不再 `private`）：`battlecommon.ts` 类型、常量和小工具；`battlestart.ts` 开局前把关卡 / 别人给的 setup 和开发参数（funseed、devarmy、devhero）拼成 `BattleData`（入口 `main.ts` 只管烘素材、切场景）；`battlehooks.ts` 测试钩子（`__haidao.*`，冒烟和录像脚本靠它们，改名要同步 `tools/`）；`battleinput.ts` 顶栏、船卡、技能钮、点沙滩登陆、悬停、选择状态；`battleunits.ts` 兵和英雄的精灵、弹道；`battlebuildings.ts` 建筑与城墙、受损、迷雾、炮台、血条、倒塌；`battleevents.ts` 规则事件（登陆 / 开火 / 命中 / 爆炸 / 阵亡 / 技能…）到音效和特效的分发，按事件数组顺序；`battleresult.ts` 结算框、失败建议的归咎圈、战利品飞入；`landfx.ts` 登陆编排（木筏对象池、兵一个个跳下水涉水上岸，位移是 `disembark.ts` 的纯函数：整段 ≤ 1 秒、到点和规则位置收敛为 0，`battleunits.ts` 里一个「下船位移」小块调它）；`funui.ts` 撤回钮、漂流宝箱、援军旗标和首次提示。不依赖 Phaser 的纯逻辑：`battleflow.ts`（每拍喂给规则核心的操作 `takeActions`、回放驱动 `driveBattle`）、`battleadvice.ts`（失败建议；连输两次时船坞低于主寨就指船坞，`dockGain` 也给海图岛面板的「建议船坞」那行用）、`battlesettle.ts`（结算拼装、连输计数），`tests/battle-view.test.ts` 锁住。加新逻辑先放对应文件，别回填到 `BattleScene.ts`。
- **守岛场景的文件分工**（`TdScene.ts` 只管生命周期 `init` / `create` / `update`、逐拍推进 `stepOnce`、镜头跟随 `followCam` 和入口 `prepareTd` / `prepareTide`；`create` 里挂测试钩子 `__haidao.*`，改名要同步 `tools/`；拆法同登陆战，场景方法改成第一个参数是场景 `bs` 的函数）：`tdcommon.ts` 类型、常量和小工具；`tdworld.ts` 地面布局、墙、道具、迷雾、大潮、镜头适配的盒子和屏边箭头；`tdhud.ts` 顶栏底栏、波次预告、`updateHud`、横幅、浮字、撤退确认；`tdinput.ts` 点击、悬停、取消、叫波、选技能、扔炸药桶、移动标记；`tdhookfx.ts` 锚钩的瞄准圈、点选目标和甩钩、拉链、收链的演出；`tdsheet.ts` 木台面板、敌人图鉴、卖塔；`tdsync.ts` 每帧把规则状态同步成精灵（`sync`）、炮台、干扰、照明、狙击线；`tdoverlay.ts` 血条 `drawBars`、射程圈、准星、瞄准预览、木台状态、爆炸；`tdevents.ts` 规则事件到音效特效的分发 `onEvent`；`tdresult.ts` 结算框、战利品飞入、护航 / 海盗来袭 / 大潮的结算；`tdreason.ts` 结算里「一句话原因 + 关键时刻」的纯函数（`tdevents.ts` 的 `recordReason` 局内记下每次宝藏真丢（`escape`）是哪波、哪条路、什么敌人，护航记下每口咬船（`bite`），结算写船血掉得最多的那一波，`tests/tdreason.test.ts` 锁住）。加新逻辑先放对应文件，别回填到 `TdScene.ts`。
- **基地场景的文件分工**（`BaseScene.ts` 约 370 行，只管 `create` / `update` / `refresh` / `hasPending`，拆法同上）：`basecommon.ts` 类型和常量；`basegeom.ts` 坐标换算、安全区、镜头聚焦和面板留白；`basehud.ts` 顶栏、资源数字、气泡、收金币飞行；`basemenu.ts` 操作环、右键菜单、快捷键、选择高亮、名牌；`basepanel.ts` 建筑面板、成就、图鉴、预设、个人面板；`baseupgrade.ts` 成就检查、解锁弹窗、庆祝、研究列表、升级与收集；`baseplace.ts` 点选、悬停、按下高亮、遮挡半透明（`fadeFrame`）、建造列表、摆放、拖城墙、确认与取消；`basepick.ts` 选中判定和遮挡的纯函数（占地格优先 → 不透明像素前面优先 → 同一点连点循环；`occluders` 找出盖住焦点占地的前面建筑；`tests/basepick.test.ts` 锁住）；`basenav.ts` 船队、守岛、海图入口和新手引导刷新；`rankui.ts` 主寨面板里的「海盗王阶」区（称号、两条进度条、献上钮、升阶演出、船长钮上的王旗色点），`ranktext.ts` 它的纯文字和进度（`tests/rankview.test.ts` 锁住）。同一组文件里函数名不重复，新加前先查。

## 界面排布、面板和操作

- **三种屏幕的排布**（样式在 `src/view/layout.ts`，写成 `.hd-ui.hd-skin …` 盖过各界面自己的规则，排在皮肤后注入）：竖屏顶上两行（基地在所有手机竖屏只一行，见下），宽屏（≥ 560 宽，含手机横屏和电脑）并成一行；手机横屏（宽 > 高且高 ≤ 500）底部操作区挪到右侧竖着排（基地的底栏、登陆战的兵种卡和技能钮、守岛的技能和叫波），把高度让给岛。基地在所有手机竖屏（宽 < 560）顶上只一行：大厅（只留小房子图标）、金、木、船长头像、设置（船长头像由 `basehud.ts` 按 `PORTRAIT_PHONE` 挪进资源那一行），主寨等级牌和训练营钮收起（主寨等级点主寨看，训练营在主寨的操作环里），「兑换」并进底栏同一行右端；守岛、护航、海盗来袭、大潮在所有手机竖屏（宽 < 560）都这样排——金币 / 撤退并进底栏右端，加速和暂停挪到顶栏（左上「大厅」只留小房子图标、顶栏从 58 起，不然 360 宽上宝藏牌出框），预告卡常显、缩成摘要（第一行第几波、敌人、倒数，第二行只留「先造 / 下一座造」，其余在图鉴里），护航三档船速并成底栏的船速钮（点一下换下一档），「加速」「修船」「跟随」常驻在船速钮正上方一列（`.hd-esc-quick`，`escortview.ts` 按 `layout.ts` 的 `PORTRAIT_PHONE` 把三颗钮挪进挪出；造塔面板开着时收起），没有要展开才看得到的东西，顶底栏合计约 13% 屏高（底栏收起时一起收起）；基地的资源牌在所有手机竖屏（宽 < 560）都写成「/ 25,200」，不写「上限」两字（390 宽上写全会穿出牌子）；登陆战底部两行：上一行能量、技能（48×44，上一行图标 + 能量、下一行名字）和右端的加速 / 撤退，下一行兵种卡（44 高，宽跟着内容走；出完的卡灰着，锁缩到 12 挂在右上角，不盖小兵），相邻点按目标一律隔 8 像素、选中的兵种卡竖屏不上浮，360×640 上顶栏贴顶，上下 HUD 合计 140（21.9%）；窄于 380 宽时左上「大厅」只留小房子图标（点区仍 44×44，`aria-label` 写着「大厅」），顶栏左边从 88 让到 54，侦察期带「侦察中」的计时牌和星星都放得下；「全景」钮贴着顶栏下沿（和守岛一样），不压右上的沙滩；守岛预告卡常显摘要（`.hd-td-plan`，点卡开图鉴；高 ≤ 700 的竖屏只留第一行、只看不点，图鉴从顶栏「图鉴」钮 `.hd-best-btn` 进，平板竖屏护航同样）；护航船速钮（`.hd-esc-sum`）显示当前船速、点一下换档，加速、修船、跟随常驻在它上方。平板竖屏（560–899 宽，如 820×1180）的护航同样把预告卡缩成摘要（速度排保持原大小），顶底栏约 18%（原 28%）；守岛、海盗来袭、大潮在平板上本来约 18%，不动。手机横屏造塔 / 升级面板开着时右下角那块板（拒马钮）收起，免得和面板的关闭钮只隔 3 像素。手机横屏登陆战结算框两栏：横幅占一行，左栏星、摧毁率、战利品和拿了什么的几行（连胜、安慰奖、满仓少拿、掉落、悬赏），右栏说明和按钮（以前左栏只有三项，右栏堆到 358 以上，标题顶出屏外）。手机横屏护航顶栏的船血条收到 112 宽、右段贴着设置钮（以前两段在 844 宽上叠约 14 像素）。手机竖屏海图的「回岛」在顶行大厅和设置之间，「找下一关」在右下角、登录后的「悬赏出海（实盘）」上面（以前两颗钮叠在入口小卡下面，切掉岛名牌）。登陆战竖屏四种兵以上时兵种卡平分一排、图标在上字在下（12 号），再多才横滑。改排布只改 layout.ts，镜头适配自动跟着。
- **字号和不够的说法**（`tests/ui-rules.test.ts` 锁住）：界面字号只有 12 / 14 / 16 / 20 四级（大数字、结算标题 ≥ 24 另算），没有 11px，没写字号的 `small` 也按 12（`layout.ts` 的 `:where(.hd-ui) small`）；花费、建议主寨级这类关键信息 14。基础样式 `view/ui.ts` 里还有 13 / 15 / 18 / 22 和 `.hd-boat small` 的 11，等收口后补进测试的扫描范围。
  资源不够一律写"还差 N 金币 / 木材"（`basefeel.ts` 的 `lackText`，能量写"还差 N 能量"），不写"余额不足 / 不够"；够了用绿色 `.hd-need.ok`，不够才红。宽屏（≥ 900）守岛选关页列宽 `min(100%, 720px)`（`layout.ts`），造塔和升级面板按内容高度。

- **手机不拥挤的量化线**（`tools/layout-check.ts` 四种尺寸 × 基地 / 登陆战 / 守岛量 DOM 矩形，每项给数字和过 / 没过）：竖屏顶栏 + 底栏 ≤ 22% 屏高、可见区 ≥ 60%、点按目标 ≥ 44×44、相邻目标间距 ≥ 8、同屏文字牌子 ≤ 6、底栏在屏幕下 1/3。竖屏的做法：基地 / 守岛第二行紧贴第一行；登陆战把星数并进第一行，加速和撤退挪到底部技能行右边（撤退仍有确认）；技能钮 48×44（上一行图标 + 能量，下一行 12 号名字：引导和提示都说「点炮击」，只有图标找不到），兵种卡一行 44 高，两行之间、卡与卡之间都隔 8，底部合计 96 像素；360×640 上顶栏贴顶（44），上下 HUD 140 像素，在 22% 以内。刘海和圆角：`.hd-screen` 上、左、右缩进 `env(safe-area-inset-*, 0px)`，底栏自己加下边距，镜头适配把这些缩进也算进不能放岛的边。

- **底部卡和技能钮的三态**（`skin.ts`）：兵种卡 `.hd-boat`、技能钮 `.hd-skill`、守岛的 `.hd-td-skill` 统一木板 / 羊皮纸皮肤；选中（`.sel`）= 金底、上浮（手机竖屏登陆战的兵种卡和技能钮都不上浮，免得顶到上面的提示条；提示条离技能行 8）、外圈金光；冷却 / 充能 = 暗化加进度（守岛是 `.cool` 加 `.hd-cd` 的扫光和秒数）；不可用 = 去饱和：兵种卡出完（`.done`）灰掉、名字写「×0」（手机竖屏收起了「已出发 N」那行），点了说「都派出去了」，守岛英雄倒下（`.off`）另加锁。登陆战技能钮两态一眼分清：能用 = 深胡桃木、奶白字、能量数亮金、内圈一道金边；能量不够（`.off`）= 冷灰石板、图标去色、费用变浅红、底下一条进度（`--p` 是现有能量 / 要的能量；手机竖屏 48×44 里图标缩到 18、进度条贴底边高 4）。不挂锁：锁在建造列表里是「主寨几级才开放」，挂在这里会被当成没解锁。字和底的对比度都 ≥ 4.5。对局结束（`over`）时选中的船和技能、底部操作提示一起收掉，结算窗后面不留「点要炮击的地方」。空星图标（`icons.ts` 的 `starEmpty`）外圈深色边、里圈奶白细边，在羊皮纸和顶栏的半透明深木底上都看得清（烘进图标，不用运行时的 CSS 滤镜）。
- **介绍卡片**（数据 `intel.ts`、画法和打开方式 `intelcard.ts`）：每个兵种、每座登陆战防御（`DEFENSE_CARD_KINDS`）、每座守岛的塔一张卡：一句话定位、属性条（条长按同类满级比）和「当前 ➜ 下一级（+差值）」、怎么找目标（图标 + 一句话）、相克（兵种 / 防御的小头像，守岛是护甲名）。数值只读规则核心（`TROOPS`、`raidDefenseBase`、`td2TierStats`），寻敌按规则用的同一份字段（`TroopDef.aim`、`SNIPE_ORDER`、溅射 / 死角 / 几发）拼，相克读 `content/intel.ts`（只写兵种那一边，防御反查）；`tests/intel.test.ts` 锁住。打开方式：`attachIntel` 给出兵栏、船队、建造卡、军械所研究卡、守岛造塔卡挂上「手机长按、电脑悬停浮出、右键弹出」（卡角一个小 i，有鼠标时不显示；登陆战的兵种卡不挂小 i，弹的是精简卡：只有当前数值和寻敌，不放升级对照和相克，手机上不盖住底栏），长按弹卡后吃掉松手补发的那一下点击；升级面板里防御和守岛塔有「i 介绍」钮（`intelButton`）。研究卡、守岛造塔卡升不了 / 造不起时不设 `disabled`（禁用的按钮收不到长按和右键），用 `.na` 灰掉，点了照旧弹原因。
- **登陆战里选中**（`battleinspect.ts`）：什么都没选时轻点、手机长按、电脑右键一个兵或一座防御：画射程圈（防御还画死角）和到它当前目标的连线，屏边贴一张小卡（`pinIntel`，手机在底栏上方、电脑在右上），不暂停；Esc、×、目标死了 / 塌了就取消。长按由 `CamCtl.onHold` 给（450 毫秒没挪开，用掉了松手不再算点按）。
- **一键收取**（`baseupgrade.ts` 的 `claimAll`，规则 `core/base.ts` 的 `collectAll` 和 `core/training.ts` 的 `claimTrain`）：矿里攒着东西或有训练营待领奖励时底栏正上方浮出「一键收取」（写着金、木各有多少，手机横屏挂在右侧竖栏左边），点一下或按 C 全收（先收矿、再领训练营，仓库满了训练营那份留着待领），顺带结算达成的成就，弹汇总框（收了多少、训练营给了多少、仓库满了留下多少、新徽章）；以后加了要手动领的东西都并进这里；升级面板里「先收矿里攒的」也走它（不弹汇总）。
- **训练营**（`training.ts` 面板、`trainplay.ts` 局内，DESIGN 16）：电脑和平板顶栏第二行「训练营」（还有开放了没过的关时带红点）；手机竖屏顶栏没有这颗钮，点主寨，在操作环里点「训练营」（`basefeel.ts` 的 `buildingMenu` 只给主寨加这一项，红点跟钮一样，快捷键 T）。面板一关一块（兵种 / 排兵 / 守岛、开放等级、奖励或「过了」），下一关描金边，放不下就分页；点了直接开打。局内横幅用新手引导同一个 `Tutorial`（钮换成「跳过提示」，只关这一局的提示），高亮要点的船卡；兵种关开局贴一张那个兵的介绍卡片（`pinIntel`），第一船上岸收起；守岛关借开局造法的金圈指木台，不弹「新敌人」小卡。结算框写这关学到的一句、奖励（进一键收取）、「回训练营 / 再来一次 / 下一关」。
- **弹窗**：所有 `.hd-mask` 弹窗都经 `ui.ts` 的 `openModal({ closable, onEsc?, stack?, cls?, parent? })` 打开，不手拼遮罩。同一时间只开一个，新的打开时旧的先关；确认框、成就、宝箱（`stack`）可以叠在别的弹窗（结算）上，最多两层。进场淡入加弹起 0.18 秒，关掉时淡出加微缩 0.14 秒再拿掉（`transitions.ts` 的 `dismiss`；`mask.remove()` 就走它，离场中的不吃点击、不算"开着"，游戏循环停了时墙钟兜底拿掉；同一位置马上要换新的用 `removeNow`）；基地面板关掉同样淡出。切到基地、登陆战、守岛时盖一层幕布 0.2 秒淡掉（`sceneVeil`）。离场和幕布走游戏时钟（`mapfx.ts` 的 `tween`），`frameStep` 录像逐帧走；按钮的悬停（微微上浮变亮）、按下（缩到 0.96、阴影缩短）、键盘焦点框是纯 CSS（`feedbackCss`）。系统减弱动态时都不播。Esc 由 `uiRoot()` 注册的捕获阶段监听接走，只管最上面一层，场景和各页面的快捷键收不到：可关的（`closable: true`：升级庆祝、成就、宝箱、确认框、实盘 / 攻防面板）Esc 和点遮罩都关，确认框等于点取消；必须点按钮的（`closable: false`：登陆战、守岛、大潮、悬赏、攻防的结算，航线每站小结，必须刷新的提示）点遮罩不理，Esc 等于主按钮（`onEsc` 里点它，按钮还没出现时不动）。栈的规矩是纯逻辑（`modalstack.ts`，`tests/modal.test.ts` 锁住）；场景的快捷键用 `modalOpen()` 判断有没有弹窗。
- **稀有掉落弹窗**（`battleresult.ts` 的 `openChest`）：宝箱是程序画的 `lootChestArt(open)`（`art/icons.ts`，合着的铁箍木箱带锁 / 掀盖冒金光，只给 DOM 弹窗用、不进开局烘焙）：合着的先晃两下，换成开着的、身后一圈慢转的光芒，物品从箱口跳到箱子上方；容器上半截留给物品，不压「稀有掉落！」。弹窗打开时结算框先藏起来、收下（或 ✕、Esc、点外面）再回来，不两张框叠着；文案指「回岛点船长头像 → 收藏」（船长钮只有头像没有字）。减弱动态时不晃不转。守岛顶栏的宝藏数用宝箱图标 `treasure`，不和造塔用的金币图标混。
- **设置**：顶栏右上只有一个齿轮钮（`settingsButton()`，类名仍是 `hd-mute`，`layout.ts` 按它定位），点开设置面板：音乐、音效、震屏和振动三个开关（立刻生效、立刻记下，没有保存钮）和"恢复默认"。音乐 / 音效存 `haidao.settings`，震屏和振动仍存 `haidao.feel`（恢复默认清掉它，回到跟随系统）。大厅关了声音（平台的 `arcade.sound` 为 `off`，经 `arcade-kit/client` 的 `platformSoundOn()` 启动时读一次）：这次打开音乐、音效先都关、开关显示关；在这里再打开只管这一次，不写 `haidao.settings`，也不碰平台的 key（`sfx.ts`，`tests/sfx-lobby.test.ts` 锁住）。
- **首屏加载**：`index.html` 的 `#boot` 带进度条和百分比（`BootScene.loadArt` 按素材烘焙进度更新）；烘焙出错时说明原因、进度还在，并出现"重试"钮，点了重新装一遍（已烘好的不重烘）。

## 性能

- **别一格一个对象**：静态大块（地面）用 canvas 烘成一张图（`ground.ts`）；飘字、粒子、火花、炮口光、序列帧特效（`framefx.ts` 的 `FrameFx`：命中火花、6 帧爆炸、倒塌烟尘、刀光、枪口火光，登陆战和守岛共用）、弹道（`shots.ts`，守岛的塔、炮艇、友军船、岸防老炮都走它）一律走对象池，不在每次命中 / 开火时新建图像、文字和定时器；建筑挨打的压扁回弹（`fx.ts` 的 `HitSquash`，曲线 `motion.ts` 的 `hitSquash`：立刻压到 94%、衰减回弹，140 毫秒回原样）由场景每帧推，不为每一下新建补间；建筑图（`b.*`）烘的时候裁掉四周全透明的边（`textures.ts`：画布裁到 alpha > 0 的外框，帧设成 trim，Phaser 按原尺寸算锚点、按偏移画，所以位置和外观不变；全透明像素照样要逐个混合，岛中间建筑叠得密时帧时间主要花在这里），按原画布坐标读像素一律走 `alphaAt`（减掉裁掉的偏移），别直接 `getPixelAlpha`；`artBox` 仍是原画布坐标。改画面后跑 `tools/perf.ts` 看帧率和 JS 每帧耗时有没有回退。
- **打开海岛只烘基地要用的图**（`main.ts`）：加载层只等通用素材（`allArt({ troops: false })`：建筑 1–2 级、海岸、点缀、特效、图标）和存档里这座岛的建筑；兵的动作帧和分件骨架图集（只有登陆战、守岛用）在基地就绪后由 `warmField` 在后台一张张烘（`textures.ts` 的 `bakeIdle`，每张之间等浏览器空闲），进登陆战、守岛前等它烘完（这时不再让出主线程、挂「装船中…」）。海图的岛、纪念章只进 DOM（`ui.ts` 的 `img`），不烘成纹理。
- **烘好的图存本机**（`artcache.ts`，Cache Storage `haidao.art`）：每张图（和每张图集）烘完存成 PNG，键是 SVG 内容的哈希 + 渲染倍数（画法一改自动作废）；下次打开 `createImageBitmap` 直接解码，不再光栅化 SVG、不再逐像素找外框。条目记写入时的版本，后台烘完后删掉旧版本写的、这次没用到的。浏览器不给缓存时照常现烘。
- **收取气泡的底是一张贴图**（`basehud.ts` 的 `bubbleTex`，按渲染倍数画一次）：每个气泡一个 Graphics 的话，满配岛十几个每帧重新三角化，手机上基地每帧 JS 一半花在这里。
- 量打开海岛用 `tools/boot-perf.ts`（生产构建：首屏可交互、首屏长任务、基地静置帧、开海图；`--warm` 量第二次打开）。

## 一屏放下

**一屏放下**（仓库根 docs/ui.md 第 11 节）：任何界面在五个尺寸（1280×720、1920×1080、844×390、390×844、360×640）不出滚动条、不截内容；放不下先缩间距和排布，长列表（建造列表、成就、收藏、图鉴、防守记录、军械所研究网格）用页内翻页（`.hd-pager`），不用滚动；军械所在 844×390、360×640 上按页放研究卡，整组都不在这一页的小标题一起收起。出海海图是例外：拖动平移的地图（`.hd-map` 用 `overflow:clip` + transform，滚轮不响应，按钮和面板在地图外固定），「找下一关」平移回下一关（第一座解锁了还没拿星的岛，岛上插「下一关」旗、旁边一颗「出发」，点开岛面板后这颗收起，面板里的「出发」只留一颗；预计掠夺按打满（三星、100%，连胜加成和新星奖励都算）写，和结算毛收入是同一个数（规则核心 `campaignGross`，`tests/campaign-gross.test.ts` 锁住），比仓库剩下的位置多时，岛面板写「仓库只装得下 N 金币，先回岛花掉」（`basefeel.ts` 的 `roomText`）；上一场仓库满了，回岛先出一次「升金库」引导（`basenav.ts` 的 `vaultGuide`，排在训练营那步前面，「先不了」只关这一条））；侦察取景框同理。改界面后跑 `node tools/noscroll.ts --out <目录> [--group 流程名] [--only 界面名] [--view 尺寸]`，它同时查滚动 / 截断、触屏点按区 < 44、可点元素互相压住（同一层、交叠 > 2 像素）、字被裁（`scrollWidth > clientWidth`）和质量线四项（不达标的在终端列出，数字在 `noscroll.json` 的 `q`）。数字列用 `.hd-n`（等宽右对齐），带符号的增减用 `.hd-pos` / `.hd-neg`（`ui.ts`）。
