# 海岛画面与界面实现笔记

> 从 AGENTS.md 搬来的实现细节：画面层各块怎么分工、怎么测。约定和硬规矩仍以 AGENTS.md 为准；改对应代码时同步改这里。

## 场景分工

- **登陆战场景的文件分工**（`BattleScene.ts` 约 450 行，只管生命周期 `init` / `create` / `update`、逐拍推进 `stepOnce`、镜头适配、开场俯瞰；拆出去的文件里，场景方法改成第一个参数是场景 `bs` 的函数，字段不再 `private`）：`battlecommon.ts` 类型、常量和小工具；`battlestart.ts` 开局前把关卡 / 别人给的 setup 和开发参数（funseed、devarmy、devhero）拼成 `BattleData`（入口 `main.ts` 只管烘素材、切场景）；`battlehooks.ts` 测试钩子（`__haidao.*`，冒烟和录像脚本靠它们，改名要同步 `tools/`）；`battleinput.ts` 顶栏、船卡、技能钮、点沙滩登陆、悬停、选择状态；`battleunits.ts` 兵和英雄的精灵、弹道；`battlebuildings.ts` 建筑与城墙、受损、迷雾、炮台、血条、倒塌；`battleevents.ts` 规则事件（登陆 / 开火 / 命中 / 爆炸 / 阵亡 / 技能…）到音效和特效的分发，按事件数组顺序；`battleresult.ts` 结算框、失败建议的归咎圈、战利品飞入；`landfx.ts` 登陆编排（木筏对象池、兵一个个跳下水涉水上岸，位移是 `disembark.ts` 的纯函数：整段 ≤ 1 秒、到点和规则位置收敛为 0，`battleunits.ts` 里一个「下船位移」小块调它）；`funui.ts` 撤回钮、漂流宝箱、援军旗标和首次提示。不依赖 Phaser 的纯逻辑：`battleflow.ts`（每拍喂给规则核心的操作 `takeActions`、回放驱动 `driveBattle`）、`battleadvice.ts`（失败建议；连输两次时船坞低于主寨就指船坞，`dockGain` 也给海图岛面板的「建议船坞」那行用）、`battlesettle.ts`（结算拼装、连输计数），`tests/battle-view.test.ts` 锁住。加新逻辑先放对应文件，别回填到 `BattleScene.ts`。
- **守岛场景的文件分工**（`TdScene.ts` 约 470 行，只管生命周期 `init` / `create` / `update`、逐拍推进 `stepOnce`、镜头跟随 `followCam` 和入口 `prepareTd` / `prepareTide`；`create` 里挂测试钩子 `__haidao.*`，改名要同步 `tools/`；拆法同登陆战，场景方法改成第一个参数是场景 `bs` 的函数）：`tdcommon.ts` 类型、常量和小工具；`tdworld.ts` 地面布局、墙、道具、迷雾、大潮、镜头适配的盒子和屏边箭头；`tdhud.ts` 顶栏底栏、波次预告、`updateHud`、横幅、浮字、撤退确认；`tdinput.ts` 点击、悬停、取消、叫波、选技能、扔炸药桶、移动标记；`tdsheet.ts` 木台面板、敌人图鉴、卖塔；`tdsync.ts` 每帧把规则状态同步成精灵（`sync`）、炮台、干扰、照明、狙击线；`tdoverlay.ts` 血条 `drawBars`、射程圈、准星、瞄准预览、木台状态、爆炸；`tdevents.ts` 规则事件到音效特效的分发 `onEvent`；`tdresult.ts` 结算框、战利品飞入、护航 / 海盗来袭 / 大潮的结算；`tdreason.ts` 结算里「一句话原因 + 关键时刻」的纯函数（`tdevents.ts` 的 `recordReason` 局内记下每次宝藏真丢（`escape`）是哪波、哪条路、什么敌人，护航记下每口咬船（`bite`），结算写船血掉得最多的那一波，`tests/tdreason.test.ts` 锁住）。加新逻辑先放对应文件，别回填到 `TdScene.ts`。
- **基地场景的文件分工**（`BaseScene.ts` 约 370 行，只管 `create` / `update` / `refresh` / `hasPending`，拆法同上）：`basecommon.ts` 类型和常量；`basegeom.ts` 坐标换算、安全区、镜头聚焦和面板留白；`basehud.ts` 顶栏、资源数字、气泡、收金币飞行；`basemenu.ts` 操作环、右键菜单、快捷键、选择高亮、名牌；`basepanel.ts` 建筑面板、成就、图鉴、预设、个人面板；`baseupgrade.ts` 成就检查、解锁弹窗、庆祝、研究列表、升级与收集；`baseplace.ts` 点选、悬停、按下高亮、遮挡半透明（`fadeFrame`）、建造列表、摆放、拖城墙、确认与取消；`basepick.ts` 选中判定和遮挡的纯函数（占地格优先 → 不透明像素前面优先 → 同一点连点循环；`occluders` 找出盖住焦点占地的前面建筑；`tests/basepick.test.ts` 锁住）；`basenav.ts` 船队、守岛、海图入口和新手引导刷新；`rankui.ts` 主寨面板里的「海盗王阶」区（称号、两条进度条、献上钮、升阶演出、船长钮上的王旗色点），`ranktext.ts` 它的纯文字和进度（`tests/rankview.test.ts` 锁住）。同一组文件里函数名不重复，新加前先查。

## 打击感、动作和血条

- **打击感分级**（`src/view/feel.ts`，纯逻辑，`tests/feel.test.ts` 锁住）：系统的"减弱动态效果"整个画面层只在这里读一次（`REDUCED`，各处演出压短、不晃、不飘都看它），重击门槛 `HEAVY_HIT` 登陆战和守岛共用（逻辑拍长 `STEP_MS` 在 `motion.ts`）；震屏、顿帧只给大事件（主寨 / 一般建筑倒塌、主寨宝藏箱挨重击、半径 ≥ 1.5 格的大爆炸、首领登场 / 技能 / 被打倒、宝藏被抢），调用处一律 `bigEvent(scene, hs, '事件名')` 查 `BIG_EVENT` 表，不自己写档位；
  普通命中（小兵普通攻击、塔普通开火）只给局部反馈：闪白一帧、压扁回弹、对象池里的小火花 / 木屑（`Particles.sparks`，上限 3 粒）。震屏分三档，冷却 300 毫秒，冷却里只有更高一档能打断。放兵、放技能、建筑倒塌、胜负、基地升级完成和放下建筑给 `navigator.vibrate` 短振动（iOS 不支持就跳过）。右上角静音钮下面的开关同时管震屏和振动。
- **动作和缓动**（`src/view/motion.ts` 纯函数，`tests/motion.test.ts` 锁住；`anim.ts` 是 Phaser 侧的倒下列表）：兵、英雄、守岛敌人的位置按逻辑拍（20 拍 / 秒）之间插值显示（`interpPos`，一拍跳 > 4 格算传送不插），不一拍一跳；转向用 `turnStep`（朝向在 -1..1 连续变，scaleX = 朝向 × 基准，经过 0 时压扁，不用 `setFlipX` 瞬切）；
  兵、英雄、守岛敌人的身体动作走下面的分件骨架；退化成单张帧的（远处的兵、鹦鹉群和鹦鹉王）走路按走过的距离换帧（`strideFrame`），攻击按进度换帧（`attackFrame`），倒下 `deathPose`（`DyingList` 每帧推进，不新建补间）；
  建筑受损分阶段（`damageStage`：<66% 冒烟、<33% 着火、<15% 半塌，外观和烟火间隔在 `STAGE_LOOK`），建造升起 `riseScale`，倒塌 `collapseScale`。**缓动统一**：补间的曲线名一律取 `motion.ts` 的 `EASE`（`strike` 出手、`recover` 收招 / 呼吸、`land` 落地回弹、`recoil` 后坐、`fall` / `fade` 倒下淡出、`bounce`），不在各处写 `'Quad.easeOut'` 之类的字符串、不用线性。
- **血条**（`src/view/bars.ts`，`tests/bars.test.ts`）：满血不显示，掉血后显示 3 秒再淡出（`BarTracker`，再掉血重新计时）；挨得近的条上下错开（`stackBars`，临时数组复用）；守岛里扎堆时每 48 像素见方最多画 2 条小条、残血的先留，墙和拒马全画（`crowdBars`，免得十几条错开成一根柱子盖住人）；条的记录用数字作键（兵 / 敌人是编号、英雄 -1、建筑和墙是负数），清单是复用的 `BarList`，不每帧拼字符串、建数组；兵的条小而细、建筑和墙的稍大（`BAR_SIZE`）。登陆战和守岛共用。

## 分件骨架（兵、英雄、守岛敌人）

- **分件骨架**（兵、英雄、守岛敌人，`tests/rig.test.ts` 锁住）：
  - 每个兵种拆成影子、后腿、前腿、后臂、身体、头（睁眼 / 眨眼 / 出手张嘴三张）、帽子、前臂、武器、刀光共 10 个部件，另加一张挥砍弧形残影（`rig.arc.<倍数>`，开局用 Graphics 画一次），全部 SVG 程序画（`art/rigparts.ts`，衣服、脸、帽子和原来整张帧共用 `art/troops.ts` 的 `DECO`、`torsoShape`、`head`，守岛敌人共用 `art/tdart.ts` 的 `tdMan`），开局烘进一张图集 `rig`（`textures.ts` 的 `bakeAtlas`，皮肤另烘 `rig~<兵种>~<皮肤>`），每个部件的关节点存在帧的 `customData` 里。
  - 画面侧是 `rigsprite.ts` 的 `Rig`：一个 Container 装 10 张图，每帧由纯函数 `rig.ts` 算：关键帧采样 `sampleClip`（循环动作用 Catmull-Rom 穿过关键帧，一次性动作逐段用 `motion.ts` 的缓动）→ 加站姿 `onRest` → 正解 `solveRig`（腿挂在髋上，头、两肩跟着身体前倾，武器在手上，整个人绕脚底转 `rot`）。姿势通道都是角度（往前为正）和设计单位的位移，`Pose` 的说明在 `rig.ts` 开头。
  - 动作数据全在 `rig.ts`：`WALK`、`IDLE`、`LOOK`、`COMMAND`、`SLASH`、`SMASH`、`SHOOT`、`CANNON`、`THROW`、`HEAL`、`RAM`、`HIT`、`HIT_HEAVY`、`DIE_FLY`、`DIE_KNEEL`、`DIE_SHOT`、`DIE_BURN`、`DIE_SOFT`，每个 ≥ 8 个关键姿势，都是相对站姿的增量；兵种差异写在 `STYLE`（站姿、`scaleClip` 放大缩小的走路 / 攻击、节奏 `ms`、受击幅度、待机小动作），骨架尺寸在 `SKEL`。改动作先用 `node tools/rig-preview.ts <目录> [t.sailor,e.fog]` 渲成 PNG 看（走路 8 格、攻击按关键帧、待机、受击、两种倒下），不开浏览器。
  - 对齐规则：走路按走过的距离推进相位（一个循环的步幅 `strideOf` 由腿长和摆角 `WALK_SWING` 算，脚不打滑；身体起伏 `WALK_BOB`，触地那一拍压扁 `WALK_SQUASH`）；走路一个循环两步共 16 个关键姿势（`gaitClip` 按兵种的步态参数生成：落脚压得快、蹬地抬得慢，腿出得快收得慢，手臂反相、比腿晚半拍还带一点过头回弹，头比身子滞后，左右两步不镜像）；各兵种先定想要的步频（重兵慢而沉，水手碎步快），再按规则移速反推腿的摆幅，步幅跟着变，所以仍不打滑；攻击按规则的冷却算进度（`atkPhase`：离下次出手 hit·ms 内是预备和出手，出手后 (1-hit)·ms 内是余势和收招），出手段用 `fall` 加速进、`recoil` 减速出，最快的一帧落在规则的出手拍（远程即 `shoot` 事件），刀光 `trail` 跟着亮；挥砍、重砸、投掷是全身动作（蓄力身子后仰、整体后转、重心后移，出手前压、前脚迈出，收招回原位），`Clip.arc` 标了的画弧形残影（`arcLook`，壮汉的锤最长最亮）；出手点上这个兵自己顿 `HITSTOP_MS`（60 帧下 2–3 帧）再 smoothstep 追回规则进度（`stopK`），不顿全屏、不进大事件；动作之间 140ms 混合，不跳姿势；待机呼吸，偶尔东张西望（只在待机时插）；受击叠加闪白和后仰，一下掉最大血量 ≥ 25% 或伤害 ≥ 90 算重击（`HIT_HEAVY`：更大后仰、踉跄一步、火花 5 粒，判定在 `dmgkind.ts` 的 `isHeavyDmg`）；倒下由 `deathStyleFor` 按伤害类型选：炮弹 / 爆炸炸飞（`DIE_FLY`，落地弹两下带尘）、枪弹中弹倒地（`DIE_SHOT`）、火烧焦（`DIE_BURN`，渐黑冒烟）、被晕着倒的软倒（`DIE_SOFT`），伤害类型由 `dmgkind.ts` 从开火 / 爆炸事件推（规则不给，推不出退回 `deathStyle`：单次伤害 ≥ 90 或一下掉半血以上飞，否则跪倒），帽子单独飞（`hatDrop`），再淡出，交给 `DyingList` 推进，播完回对象池。减速（焦油、冰冻类命中，规则核心只读的 `slowUntil`）的兵身上黑点和脚下粘油挂在 `Rig` 里跟着兵的深度走；焦油陷阱被踩是黑油溅开加地面水洼（`tarfx.ts`，池子 10 个），不放爆炸。
  - 性能：`RigPool` 对象池（不在出兵时新建）；`lodOf`：离屏（留 `LOD_MARGIN`）隐藏不算、身高小于 `LOD_PX` CSS 像素换成单张烘焙帧；同屏完整骨架多于 `CROWD`（36）时按编号错开隔 2～3 帧重算姿势（`poseEvery`），位置照样每帧插值。显示对象数（容器里的部件也算）由 `countObjects` 报给 `perf.ts`。
  - 测试钩子（只给工具用）：`?devarmy=<兵种>[:<个数>]` 全军换成这种兵；`?dev&devwalls` 登陆战去掉最外面的金矿、在沙滩和炮台之间拉一道城墙（拍手雷越墙）；`__haidao.tdFx('stun' | 'lob' | 'shield')` 守岛里放一次震晕 / 手雷的画面、或把第一个敌人换成盾兵（只在 `?dev` 下）；`snipeLive()` 现在有几条狙击预警线在画（连拍等预警出现再开拍）；`units()` 对盾兵多给 `gx/gy`；`?mt1` 把 WebGL 合批限到 1 张纹理（SwiftShader 多纹理合批会随机丢整个精灵，只在录像时开，测帧率别开）；`__haidao.units()` 列出场上单位、`follow(id, zoom)` 镜头跟住一个单位、`towers()` 列出炮台（含当前目标的屏幕坐标）、`lookAt(x, y, zoom)` 镜头对准一点、`turretStats()` 开火次数和开火时还没转到位要补的角度、`occluded()` 画过遮挡剪影的帧数、`frameStep(n, ms)` / `frameEnd()` 停下帧循环手动推帧。
  - 盾兵的大木盾（`shieldlook.ts` 纯函数，`tests/content2-fx.test.ts` 锁住）：盾不是兵手里的武器，是图集里单独一个部件（`<种类>.shield`，只有 `t.shield`、`e.shield` 有），`Rig` 把它挂在容器里，每帧按规则给的盾朝向（`BUnit.gx/gy`、`TdEnemy.gx/gy`，世界坐标 ×100，经 `RigIn.gx/gy` 传入）摆：世界方向换成屏幕方向，盾在身体朝那一侧（朝下宽而完整、朝左右变窄、朝上藏到后臂后面），转身时摆法逐帧追向目标（约 100 毫秒绕过去，不瞬跳）；被震晕（`RigIn.gdown`）盾垂下。规则推 `guard` 事件时场景调 `Rig.guard`：盾沿盾面往身体里一顿再弹回（`guardKick`，260 毫秒阻尼振荡）、盾心（`Rig.shX/shY`）爆一团亮闪 + 几粒火星 + 一点木屑、播 `guard` 音效；减弱动态只亮闪不晃。被溅射打到规则不推 `guard`，画面就不出这些。
  - 倒下的单位（`anim.ts` 的 `DyingList`）：深度压低 0.6（排到同格活人下面），压暗到 0.8 倍、后半段更快淡掉（`dyinglook.ts` 的 `dyingDim`），扎堆时活人一眼能挑出来。
  - 遮挡（`occlude.ts`，纯函数 `occludes` / `boxOf` 在 `fxlayout.ts`）：兵走到建筑后面时人照常不透明，在挡住他的建筑上面另画一张他当前动作的整帧剪影（浅蓝、半透明）。建筑的不透明外框按 128 像素的格子分桶，每个兵只查身体中点那一格的几座，不两两全比；剪影图走对象池。城墙、陷阱、岩石、海怪和装饰（棕榈、旗杆、雕像、宝箱，名单 `fxlayout.ts` 的 `NO_OCC`，登陆战和守岛共用）不算挡；只给完整骨架（`lod` 0）的兵画，同屏最多 14 个剪影。护航商船不是 Rig，被塔楼挡住时 `escortview.ts` 用 `Occluder.blocker` 查挡它的建筑，在建筑上面画一张浅蓝剪影（按时间淡入淡出，减弱动态直接到位）；船头顶上另有一条一直在最上层的血条（`shiplook.ts`，掉血时白色残段按时间收回）。
  - 伤害数字（`fx.ts` 的 `DamageNumbers`）：字号是屏幕像素，按镜头的实际缩放换算（录像跟拍时也对），近景不会跟着放大；`dmgFontPx` 封顶到小兵屏幕身高的一半多一点，最小 13 像素。守岛里扎堆时，0.3 秒内、56 像素内的不同目标共用一个键（`tddmg.ts` 的 `DmgClusters`，墙钟毫秒、4 倍速下也一样），合成一个“这一团的总伤害”，再由 `DamageNumbers` 累加和错开。

## 炮台

- **炮台**（`src/view/turret.ts`、`aim.ts`、`shots.ts`、`art/turrets.ts`，纯函数在 `aim.ts`，`tests/aim.test.ts` 锁住）：登陆战和守岛的加农炮、火枪塔、臼炮、喷火塔、鱼叉炮、火箭塔拆成底座（`turretBaseArt`，原建筑图去掉炮管）加 16 个方向的炮管（每个方向按真透视画，`art/turrets.ts`，开局和底座一起烘进图集 `tur.<种类>.<档>`；档按等级分 `turretTier(kind, level)`：炮台 1–2 / 3–4 / 5–6 / 7–8 四档（`tier4`，和底座同一套分档），火枪塔的火枪手 1–2 / 3–4 / 5–8 三档；整张图（图标、没烘好分件时）上的炮头由 `turretHeadBody` 画，和分件图集同一套画法、同一个代表等级；火枪塔的顶棚另烘一张，只在 2、4、6–8 级有，`gunTowerRoof` 别的等级给 null），朝向在两个方向之间用一点残余旋转补上，转起来是连续的。
  - 瞄准：炮管有角速度上限和加减速（`aimStep` 梯形速度曲线、不过冲），规则的开火拍不动，画面按离下次开火的时间提前转；来不及就在离开火时间很短时切成三角速度曲线赶，开火那一帧还差的角度直接补上（`aimSnap`，`turretStats` 记次数和最大补角）。没目标时慢慢回到待机朝向（`idleAim`）。
  - 开火：预备（往后一缩）→ 炮口闪光加一团烟（粒子池）→ 后坐 → 复位（`recoilAt`，各塔的幅度、时长在 `TURRET_SPEC`），底座小抖（`shakeAt`），不震全屏。火枪塔的小人举枪、开火、通条装填（`musketPose`）；喷火塔的火舌有起、持续、收尾（`flameStep`，火舌图 `fx.flamejet`）；鱼叉炮开火后炮上是空的，叉子带绳飞出去、命中后绳子先绷紧再收回（`ropeBack`），收回才重新装上；火箭塔打完空架子，装填时间到了再装上。
  - 狙击塔（`sniper`，登陆战和守岛共用）：瞭望台底座（`buildings.ts` 的 `sniper()`，四档轮廓见下面「防御建筑的剪影」）加 1.1 格长的细炮管（`turrets.ts` 的 `sniperDir`，管上架瞄准镜、炮口消焰口；铁管木托 / 铜箍黄铜镜 / 乌铁金箍红镜片 / 再加一块冷钢护盾），进 16 方向炮管图集。规则推 `aim` 事件（带 `fireAt` 开火拍）时 `SnipeLines`（`snipefx.ts`，样子在 `snipelook.ts` 纯函数）从炮口到目标胸口画红线、目标脚下画红色等距准星，`SNIPE_WARN`（0.5 秒）里线越来越粗越实、准星越收越紧、最后亮出白芯，开头几下轻闪；预警期间炮管跟着被锁定的目标转（`renderTurrets` / `syncTurrets` 用 `fireAt` 当离开火的时间）。开火（`shoot` 事件）收掉预警：炮口一大团亮光加三团顺炮管拉出去的长焰、深后坐、底座轻颤，弹道用 `snipe` 素材（`Shots` 直线飞、记一道白色弹迹 260 毫秒淡掉，命中点一团白闪）、一声重枪（`synth.ts` 的 `snipe`）。目标倒下、逃走、塔没了，预警自动收掉。减弱动态：线不闪、准星不收缩、弹迹更短。
  - 弹道（`Shots`）：按规则的发射拍 / 命中拍逐帧插值，臼炮高抛、炮弹低弧、火箭微弧、子弹直线（`arcHeight`），地面阴影随高度变小变淡（`shadowLook`），落点按材质（`LandMat`：沙地、水、木、石；地面再按 `onSand` 分岛外沙滩和岛上草地）分轻 / 中 / 重三档出特效：水花加两圈涟漪、石屑加火星、木屑碎片、草地土块加草屑、沙尘（`fx.ts` 的 `impact*` / `ripple`，碎片朝向和数量由落点序号散列，可复现）；落点粒子总量封顶 `IMPACT_CAP`，超了先淡掉最老的（`fadeOldest`），减弱动态只一帧淡闪；图像对象池，阴影和绳子画在两张每帧重画的 Graphics 上。
  - 性能：不在每帧或开火时新建对象；离屏的炮台只推进角度、不改图；分件没烘好时退回旧的整图后坐补间。

## 镜头适配

- **镜头按岛适配（fit）**（`src/view/camfit.ts`，`tests/fitcam.test.ts` 锁住）：基地、登陆战、守岛三个场景进场时，横屏和电脑是整座岛含沙滩都在"可见区"里，不用拖就能找到任何建筑和登陆点；手机竖屏（可见区高 > 宽 × 1.2）改按"有内容的区域"适配（`fitView`，内容 `Content`）：登陆战和守岛（`whole`）放大到内容盒约占屏高 60%（`PORTRAIT_LIVE`），上下完整在可见区里、左右可以裁；基地能拖，允许裁掉左右空沙角（可见区至少看到内容盒宽的 40%），但主寨必须在屏内；基地内容盒的高最多放到屏高的 60%（`PORTRAIT_BASE_H`，岛占屏高照样过 60%），不再放大到 70% 多把两侧建筑拦腰切掉。可见区 = 整屏扣掉顶栏和底部（手机横屏是右侧）操作区，扣多少不写死，`measureInsets` 读界面真实位置（`.hd-hall` `.hd-bar` `.hd-bar2` `.hd-td-bar` `.hd-td-bar2` 算顶部；`.hd-bottom` `.hd-cards` `.hd-td-bottom` 宽的算底部、窄而靠右的算右侧）；`islandBox` 给包围盒（登陆战含四面 3 格沙滩和登陆点，基地和守岛外沿留 1 格，守岛再加临时塔位和登陆口），`fitBox` 算缩放和中心，最大缩放 1.5。内容盒由各场景给（`cellsBox`，格子矩形外扩 N 格）：基地 = 建筑占地外扩 1 格（`must` = 主寨）；登陆战 = 建筑占地外扩一圈沙滩宽（3 格，夹进登陆区）；守岛 = 塔位、临时塔位、宝藏箱和其他建筑、`tdRoutes` 给的登陆口到宝藏箱的真实路线格，外扩 1 格。放大是可选的：双指 / 滚轮（`CamCtl`，最小缩放是整岛适配的缩放，玩家随时能缩出去看全岛，最大是适配的 3 倍），松手不自动回弹；`FitCam`（第 6 个参数传内容盒）在放大或平移离开全景后显示"回到全景"钮（`.hd-fitbtn`，56 像素），转屏 / 窗口变化时没放大过就重新适配。
  - **竖屏放大的登陆战、守岛**（`FitCam.live`；纯函数在 `src/view/camguide.ts`，`tests/camguide.test.ts` 锁住）：开场先停 1 秒全景（按内容盒装、不再按含沙滩的整岛盒；有主寨时裁掉左右空沙角再放大一档，岛占的高度比整岛盒多约六成），再用 0.9 秒慢进慢出推到落点（`camAt`，缩放按比例插值），落点由 `FitCam` 第 7 个参数给世界 x（守岛 = 第一波要用的登陆口，登陆战 = 发光沙滩多的那半边的最外沿），`focusCx` 夹住不越出内容盒；单击（下船、放技能）不打断推镜，拖开超过点按阈值（鼠标 6、触屏 10 像素，`camgesture.ts` 的 `takesCamera`）、双指或滚轮才停下、把镜头交给玩家（以前一点就停，镜头留在全景，竖屏岛只占屏高三成）。"全景"钮一直显示，在整岛全景和开场视角之间切换（字跟着变"全景" / "放大"）。开场推镜走完后是**自动构图**（一套逻辑，登陆战、守岛、护航共用）：`FitCam` 每帧问场景的 `Director` 看哪里（`setDirector`），缩放不动，只平移；死区、限速、慢进慢出是纯函数 `autoStep`（偏离超过可见宽的 18% 才起步，追到 2% 以内停，护航跟船 `track` 没有死区），减弱动态时只慢慢平移。看哪里：登陆战是自己的兵里最大的一簇（`biggestCluster`）加它们多数人在打的那座建筑；守岛是离宝藏最近的敌人那一拨（`groupAround`）加最近的宝藏，岛上没敌人、这一波还有人没上岸时看登陆口沿路往岛里走 3 格（`laneFocus`，`tdIncomingWave`、`tdWaveLanes`），都没有就不动（开波前、两波之间造塔时镜头不乱跑）；护航是船前方 3 格（`EscortView.camFocus`）。主组和目标放得进可见区八成就一起框（`frameFocus`），放不下只看主组，所以一拨人正冲宝藏时新一波上岸不会把镜头拉走。让位：玩家拖、捏、滚轮、点屏边箭头、切全景都记一笔（`FitCam.markUser`），停手 4 秒（`AUTO_IDLE`）后接回；刚点过画面 2.5 秒内（`TAP_HOLD`）、开着造塔 / 升级面板、在瞄技能、登陆战还选着船（还在下船）、停在整岛全景时都不动。守岛里屏外的敌人在可见区边上出红圈箭头加剑图标和「×N」（`.hd-td-edge`，44 像素，点一下镜头平移过去），屏外的空木台出不能点的木牌「+」（几块并成「+N」，只在够钱造最便宜的塔时出现，`.hd-td-edge.slot`），护航屏外的路口和关口出黄旗加箭头（`.hd-td-edge.gate`，和地图上的路口旗一致）：`edgeMarks` 沿"可见区中心 → 它"求和边缘轨道的交点，每条边按 52 像素分段、同种同段合成一个，隔 120 毫秒重算、对象池。系统减弱动态时不推镜，直接到开场视角。横屏和电脑不进这个模式，行为不变。
  测试钩子 `api.home()` 回开场视角，`api.fitInfo()` 给内容盒投到页面上的范围（量占屏高百分比、有没有被裁）；`api.beach(i)`、守岛的 `api.tdPt(x, y)` 遇到屏外的点会先把镜头平移过去。护航的适配盒要并进航线起点到终点（`withRoute`，上沿再多留一个船身高度 `SHIP_H`），电脑开场商船和旗才不被屏上沿切掉。加新场景：建完界面再 `new FitCam(scene, cc, ui, () => 包围盒, r)`。

## 质感、配色和界面皮肤

- **质感和配色**（全部程序生成、烘焙进静态纹理，运行时零开销；`tests/look.test.ts` 锁住确定性）：
  - 调色板：颜色取自 `art/palette.ts`（含光照的混色源 `sunWarm` / `shadowCool`、内线色 `inkSoft`、湿沙和三代建材的色）；素材生成时在 `kit.ts` 的 `wrap` / `piece` 里统一过 `art/grade.ts` 的 `gradeSvg`（轻微降饱和 `GRADE.sat`、拉开明暗、亮面偏暖暗面偏冷）。旗帜红、火焰、紫色技能、宝藏的亮金点登记在 `VIVID` 里保持鲜艳；调色板的 `gold` 是黄铜色，跟着分级走；特效和图标用 `pieceRaw` 不分级。地面（`terrain.ts` 的 `TERRAIN`）也过 `gradeHex`。
  - 光源固定在屏幕左上（`kit.ts` 的 `mat(base, kind?)`；`kind` 是材质类别，三个面共用、交给 `wear()` 选纹理，调用方知道画的是什么就明说——蓝灰的玄武岩、混过冷色的背光面按颜色会被猜成铁，不传才按基色猜一次）：顶面 = 基色 ×1.06 再向暖阳色混 24%（金属 30%），左面 = 基色，右面（背光）= 基色 ×0.78 再向海天冷蓝混 28–35%（木 / 石 / 金属递增），不向纯白、紫黑混；`lighten` / `darken` 同样向暖白、深海蓝混。`wear.ts` 给每个面叠光照：左面檐下一条冷暗带，右面冷影加下沿 25% 的沙滩暖反光，立面下沿冷色暗角；建筑 `shell` 里一层偏右下的长投影加一圈脚下接触阴影；`textures.ts` 的 `finish` 对建筑、`bakeAtlas` 对炮塔会转的部分（`tur.*`）再盖一层左上暖、右下冷的渐变（建筑另加颗粒）。
  - 材质（`wear.ts`，尺度按 1× 看得清定）：木 = 6–8 像素一条的拼板缝（缝下沿一条受光木棱）+ 两三条长木纹 + 至多一个木节；石 = 错缝砌块（行高 6–7、块宽 9–12、灰缝 1 像素，两成整块提亮或压暗），顶面只放几块明暗；铁 = 不撒碎点，下沿一两处锤纹加铆钉；炮管（`tube`，填色必须是 `#rrggbb`）是四段色带（上沿受光 → 中调 → 核心暗带 → 下沿反光）加一条留断口的高光窄带。木质圆台（`cyl` 的材质是木、半径 ≥ 14）顶面每 7 像素一道拼板缝；圆锥顶左前一条迎光亮面、两圈瓦缝。面积太小的面不画。同色同宽同透明度的线段（板缝、灰缝、木纹）和同色的色块（砌块明暗、锤痕）各并成一条 path 输出（`wear.ts` 的 `Batch`、`kit.ts` 的 `lines`，方盒的横纹 / 竖纹 / 砖缝同理）：一面墙几十条线原来是几十个元素，烘焙时逐个光栅化；背光面下沿的冷暗角和沙滩暖反光合成一个渐变，顶面不加渐变。
  - 描边，外重内轻：`box` / `cyl` / `hip` / `gable` / `cone` 各面填色不描边，最后沿整体剪影画一圈外轮廓（`sw` × 1.1，本体色向深褐靠拢 0.62）；面与面的交界画细的内结构线（立面中缝暗线、顶面前两条边和屋脊的迎光亮棱 `#fff7dc`）；`poly` 等的默认线宽 `SW` = 1.4 是门窗屋檐这类内线。渐变等非十六进制色退回 `OUT`；小道具和装饰传小 `sw` 或 0。

## 演出、音效和后期

- **收尾演出**（`src/view/endfx.ts`，弹结算框之前在战场上演一小段，不碰结算数字和存档，结算当场就存好）：登陆战赢了活着的兵原地举武器跳（各兵错开，`cheerAt`），镜头缓推到主寨（`pushView`）；输了屏边压暗。守岛关卡赢了炮台齐射礼花，输了镜头推向冲上岸的海盗、红圈一闪、屏边压暗（`tdEnd`，`tdresult.ts` 的 `endFxLead` 从原来的等待里扣出这段，弹窗总时间不变；护航、悬赏、大潮、海盗来袭不演）。时间走游戏时钟（场景 postupdate，录像的 frameStep 也逐帧走），点一下或滚轮跳过（开始 250 毫秒内的点不算），减弱动态时不演、按原来的延迟直接弹窗。
- **结算演出**（样式在 `skin.ts`，时间点和声音共用 `src/view/audio/result.ts`，`tests/sfx-result.test.ts` 锁住）：框落下 → 横幅落下（`h2` 变成木板横幅，失败是灰蓝色且慢一点、不弹，守岛大潮、海盗来袭没撑过 5 波也加 `hd-lose`，这两种不落星）→ 星星依次落（登陆战每颗 350ms、守岛 300ms，从横幅落地之后开始）→ 战利品滚动 → 图标飞进仓库 → 按钮最后淡入。结算处一律调 `resultTimes(kind, stars, win)` 取 `starAt(i)`、`rollAt`、`flyAt`、`sd`、`fin`，把 `sd`、`fin` 写到结算框 `style` 的 `--sd`（其余内容淡入）和 `--fin`（按钮淡入）；声音用 `resultBeats` 排好、`playBeats`（`audio/beats.ts`）按时间点放：横幅落地一声 `land`、每颗星一声 `star`（音高每颗 ×1.12，三星最后一颗换成 `star3` 号角，不再叠 `win`）、滚动时 `coin` 连击、最后 `win` 短句；失败整体更慢更低（`land` 压低、`coin` 压低、一句 `lose`）。0 星框加 `hd-lose`，三星的遮罩加 `hd-s3`（转动的光芒）。系统开了"减弱动态效果"就不播入场动画（声音照放）。改节奏只改 `result.ts` 的常量，画面和声音一起变。
- **寻宝航线的画面**（`src/view/maproute.ts` 流程和航线图页、`mapend.ts` 终局演出 / 结算 / 分享卡、`mapfx.ts` DOM 动画时钟、`mapcss.ts` 样式、`maprules.ts` 规则注入点）：出海面板顶上一张"今日航线"卡（`.hd-mapcard`，和护航卡一起竖排在 `.hd-seacards` 容器里，按内容高度往下排；卡上只有标题和一行状态、不闪，终点写在悬停提示里，海图的主角是下一关）→ 航线图页（`.hd-route`，盖在基地场景上：羊皮纸海图、港口加 4 层节点从下到上、节点卡带风格 / 侦察 / 满分宝分 / 风险星，岛的小图按风格挑造型（`art/mapart.ts` 的 `STYLE_SHAPES` / `isleLook`：金库厚 → 黑珍珠宝箱、王座城堡，炮台多 → 成排炮台、红帆、龟壳堡垒，有暗雷 → 骷髅礁石、沉船，臼炮多 → 雾、火山要塞，终点 → 首领岛；同组里再按岛 id 散列选造型和配色，`tests/isle-look.test.ts` 锁住），小船沿航路开过去）→ 选岛弹整备条（休整一条船）或补给礁二选一 → 登陆战（`BattleScene` 的 `map` 钩子：到 `MAP_STOP_TICKS` 截断、顶上 `.hd-mapstrip` 站名 + 宝分 + 倒计时条、结束时按 `aliveByBoat` 数每条船的存活交回）→ 站间条（`.hd-route-mid`）→ … → 终局（宝箱 / 收航 / 沉船演出后接通用结算框）。画面只调 `maprules.ts` 给的规则函数；休整能回几个人、补给礁加多少都是拿规则函数试算出来显示的。DOM 动画（小船、数字滚动、宝箱、金币）由 `mapfx.ts` 挂在游戏循环的 `step` 事件上推进、曲线用 `EASE`，所以 `frameStep` 录 60 帧视频时也逐帧走；金币走小对象池。电脑：节点卡悬停放大、1 / 2 选节点（补给礁里 1 / 2 选补兵 / 补能量）、Enter 出发、H 收航、Esc 取消。
- **音效接线**（`src/view/audio/`：`synth.ts` 合成、`mix.ts` 并发上限 / 变体 / 闪避 / 同名最小间隔、`ambience.ts` 环境声、`sfx.ts` 出口、`pick.ts` 事件到声音名的映射、`result.ts` + `beats.ts` 结算）：三个场景 create 里 `setAmbience('base' | 'battle' | 'td')`；开火按塔种类（`towerFire`）、命中按目标材质（`hitSound`：木 / 石 / 铁甲 / 通用）、建造升级倒塌按建筑大小分档（`isBigBuilding` 等）、出兵 `shout`、受击 `cry`（`MIN_GAP_MS` 里 450ms 限频）、技能 `barrage` / `flare` / `heal` / `keg` / `rally`；按钮点击 `tap` 在 `ui.ts` 的 `button()` 里统一放（确认框的确认钮传 `'confirm'`），别逐个按钮加。密集事件靠 `MIN_GAP_MS`（同名最小间隔）和 `GROUP_MAX`（同组同时在响的上限）压住，`sfx(name, { pitch, gap })` 可调音高和间隔。音乐（环境声）和音效分开开关，存 `haidao.settings` 的 `music`、`sfx`（`src/view/settings.ts`，旧版的 `muted` 只在没有新字段时当作两个都关，写回时同步），切后台整个音频上下文暂停。测试钩子：`window.__haidao.sfxStats()` 返回每种声音的请求 / 放出 / 限频丢 / 并发丢次数和最近 40 次，`shot.ts` 跑完会打印汇总（`--sfx-out <文件>` 写 json）；`tools/sfx-render.ts` 把每个声音渲成 WAV，`tools/sfx-result-wav.ts` 把结算序列按时间轴混成 WAV 听节奏。
- **整屏后期**（`src/view/post.ts`）：画布和界面之间一层静态 CSS 渐变（晴天是清透的深海蓝暗角 + 很淡的暖色调色；守岛关卡按天气换色：雾 / 黄昏 / 夜，`weatherOf` 先看关卡已有的 `fogZones`、`bossSkill`，再用 id 表补，不改关卡数据）；火焰、爆炸、炮口放泛光（`Bloom`：加色混合的柔光圆盘，池子 10 个，不新建、不补间）。**低端机自动关**：手机平板默认不开，开着时连续 2 秒帧率低于 30 就永久关，系统减弱动态也不开；`?bloom=1` 强制开（不自动关）、`?bloom=0` 强制关，帧率 A/B 用 `perf.ts --query bloom=0`。
- **环境动画**（`src/view/envfx.ts`，每个场景一个 `EnvAnim`，所有动画由一个 update 推进）：棕榈不旋转，换 5 张烘好的树冠错切帧（`palmSwayFrames`，0-1-2-3-4-3-2-1）；主寨的场景图不带旗布（`hqNoFlagArt`，`art.ts` 的 `sTex` 选图），旗布 3 帧另贴在 `HQ_FLAG_AT` 的挂点上随主寨的位置缩放显隐走；烟囱（`CHIMNEY_AT` 返回烟口偏移的建筑）隔一阵放一团小烟，走粒子池，总量吃紧时不放，手机间隔更长。建筑倒塌换成瓦砾时要 `env.undress(img)`。新增会换纹理的环境动画，素材记得进 `piecesFor` 的烘焙清单。
- **海盗王阶的画面**（DESIGN 2.6，规则在 `core/rank.ts`，画面只读 `rank`，不进任何战斗数值）：王旗 `art/rankflag.ts`（旗杆加旗面，6 帧波浪，4 阶起另有 6 帧带闪光扫过的，按阶用到才烘焙，key 前缀 `rk.`）由 `EnvAnim` 挂在主寨精灵旁边（`RANK_FLAG_AT` 在占地外，不拦点击、不改占地；构造时给王阶、基地里献上升阶后 `setRank`，新旗弹出来）；基地、攻防进攻（`PvpHooks.rank`，对手的王阶由服务端随对手信息回，防守回放和试打用自己的）都画，战役的电脑岛没有；进攻方自己的船帆按自己的王阶涂装（`shipArt(kind, rank)`：木筏的小帆在 `landfx.ts` 里烘好才用，寻宝航线的旗舰是 DOM 图），看别人进攻自己的回放时不涂。

## 性能

- **别一格一个对象**：静态大块（地面）用 canvas 烘成一张图（`ground.ts`）；飘字、粒子、火花、炮口光一律走对象池，不在每次命中 / 开火时新建图像、文字和定时器；改画面后跑 `tools/perf.ts` 看帧率和 JS 每帧耗时有没有回退。
