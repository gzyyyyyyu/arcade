## 4. 筹码（`docs/economy.md`）

- **娱乐**：不碰钱包，按小档的数显示"分"。
- **实盘**：从平台钱包带一份进场，档位表同其他游戏：小 2,000 / 中 10,000 / 大 50,000 / 豪华 200,000。
  **只带整份**：钱包不够一份就进不去这一档（单机提示换个小档或去领补给，好友房按被拒算），不少带。
  底分和"最多赢 3 份"都按整份算，少带的话输最多输掉带入、赢却能赢满 3 整份（钱来自庄家）；底分是整桌一个数、没法按人缩，只按带入封顶也挡不住（一把就顶到封顶），所以不让少带。单机经本模块 Worker 带入时 Worker 也只收整份（`bad_amount`），页面绕不过去。
- **底分 = 一份 ÷ 25**（小档 80；血流成河再减半，2.10），川麻实盘一场 1 局（娱乐默认 8 局）。目标是 `economy.md` 第 2 节三条：大多数场次不碰封顶（输光、赢满 3 份都少）、实盘一场 3–6 分钟、越往上电脑越强。
  用模拟器量（`npm run sim`），做法和结论见 4.1，数字在 [docs/balance-results.md](balance-results.md)。
- 单机：娱乐分新手、普通、高手三个难度，实盘档位越高电脑越强（新手性格多、手软的在低档，强性格、手紧的在高手和豪华档，表在 5.3）。好友房实盘的电脑从高档四个人里挑（见下面"至少两个真人"）。
- 钱包只走平台的 `WalletService` RPC（服务绑定 `WALLET`，`props.game = "mahjong"`），不碰 D1。平台的登记里要有 `mahjong`（钱包游戏表从登记派生）。
  - **单机**（client 模式）：页面经本模块 Worker 的 `/games/mahjong/api/stake/buyin`、`/settle` 转发；`ref` = 这一场的随机号，`op` 每个动作一个；一场打完 settle 带 `stats`（页面算好的小结，Worker 原样转发、不改不补）。
    打到一半关了页面：存档在 `mahjong.solo`，回来接着打；24 小时没回来平台到期退回。
    钱的几条规矩：
    - **带入先存再发**：存档先记"带入中"（`buying`：ref、操作号）再调平台；平台明确拒了（钱不够、上限……）就丢掉这一场；没回话、平台暂时不行就留着，
      下次点"接着打上一场"用同一个操作号重发（平台去重，不会多扣），成了才开打。
    - **离开时带回没成**：存档里留着带回的数和操作号（`settle`），提示"下次打开会自动带回"；打开页面、点"接着打上一场"都只重发带回，不再接着打。
    - **存档只有一份，每一场有自己的号**（`id`）：有没带回的实盘存档时，"单机开打"先问、先结了再开；停下的旧一场（晚到的带回）只改、只删自己那份，不碰新一场的。
    - **好友房等人页"离开房间"**先发离座再断开：只断开的话 kit 只记掉线、座位还占着，房主开打会照样从他钱包带一份。
  - **好友房**（server 模式）：开打时给每个真人座位记一笔带入（effects），到账前 `waiting`；离座把手上的筹码带回（带 stats；一局打到一半走的，这一局由电脑替他打完再带回，见第 6 节）；有人接管电脑座位时给他带入一份；整场打完把每个真人的筹码带回。电脑座位的输赢归庄家（平台）。
    - **至少两个真人，电脑用最强的两个**（和掼蛋、德州一样）：好友房是来和朋友打的，不是来赢电脑的。电脑座位的钱归庄家，
      平台对 server 模式不设每天净赢上限（单机有上限是因为结果由浏览器报），所以不能让它变成"一个人对电脑、没有上限的实盘"。
      - 等人页：实盘房坐着的真人不到 2 个，"开打"灰着，提示"实盘好友房至少要两个人；一个人想玩实盘，去单机"；
      - 旧页面、脚本绕过时（kit 没有拒绝开局的钩子）：开局时坐着的真人不到 2 个，这一场整场不计输赢、不碰钱包，按娱乐打（`unrated`）；
      - 开打以后还在下注的真人（筹码是他的，或者带入在路上）不到 2 个（有人离座、开局带入被拒）：这一场当场结束（玩法的 `finish`），
        桌上所有人的筹码按那一刻的数带回（`cut`），不让剩下的一个人接着对电脑赢；之后可以"再来一场"叫朋友回来；
      - 实盘桌的电脑从高档四个性格（火锅婆婆、稳哥、算盘、老鹰）里挑、手软 150，不按档位变；电脑最多两家，各坐一家、不重名（`venues.ts` 的 `roomSeatPlan` 让电脑座位先拿性格）。
      模拟见 [docs/balance-results.md](balance-results.md)：两个普通水平的真人对它们，各档期望都不为正。
- **stats**（`docs/platform-wallet.md` 5.10）：`rounds` 局数、`wins` 胡了几局、`best` 这一份里最大一局净赢、`titles` 称号 id（最多 5 个，按稀有程度挑）、`max: { xz_fan }` 最大番、`sum: { xz_gang, xz_zimo }` 杠数和自摸数。
  称号和自定义数都带玩法前缀（川麻 `xz_`，日麻 `rc_`），钱包的游戏 id 只有一个 `mahjong`。称号中文名在 `public/titles.json`。

### 4.1 模拟结果

各场地的数字和结论摘要都在 [docs/balance-results.md](balance-results.md)（只留现在的值，注明用哪个脚本、多大样本）；目标见 [docs/balance.md](balance.md)。

- **工具**：`npm run sim`（电脑对打、性格统计）、`node scripts/balance.ts [--rounds 1 | --three] <局数> <场地>`（小白、普通两个模拟玩家，`scripts/play.ts`，确定性、只拿自己的视图）、
  `scripts/strength.ts`（性格强弱）、`scripts/stake-room.ts`（好友房实盘桌）、`scripts/ladder.ts`（擂台）。立直用 `scripts/sim-riichi.ts`、`scripts/balance-riichi.ts`，数字在 `docs/riichi.md` 第 7 节。
  改了电脑、底分或场地表（5.3）就重跑并更新结果文件。大样本放到 CI 上分片跑。
