# 练习与每日玩法、云存档

> 从 [DESIGN.md](../DESIGN.md) 第 7 节拆出：每日何切、听牌速判、茶馆擂台、云存档。浏览器存储的键在 DESIGN.md 第 8 节，擂台的配平在 [balance-results.md](balance-results.md)。

## 每日何切（`game/hekiri.ts`、`view/hekiri.ts`）

每天五手一样的牌，选打哪张，揭晓牌效，一分多钟做完；主页"我的进度"那排的"何切"胶囊点进去，右上角显示今天几分。

- 出题（纯函数，种子由北京时间的日期按 `mahjong-hekiri:` 加盐派生，用途 `puzzle`、序号是第几题）：14 张手牌取自两门数牌（川麻缺一门），另有 6–10 张"桌上已经打出"的牌，这些牌和手里的牌一起扣掉，剩下才摸得到。
  随机发牌，合格才收，每题最多试 4,000 副，不合格的重来：打完最好的一手是 0–2 向听、至少 3 种不同打法；最好的比第三名向听更少或进张严格更多；至少有一个"向听一样、进张更少"的诱人错选；这手牌打之前还没和。
  难度往上走：第 1、2 题一向听且最好的比第二名多 4 张以上（一眼能看出来）；第 3、5 题一向听、同向听的打法至少 3 种、前两名只差 1–4 张；第 4 题两向听、同样的要求。
- 牌效（`evaluate`）：对手里每一种牌，算打掉它之后的向听数和有效牌（摸到向听数减一的牌种）能摸到几张；刚打出去的这张也算看见了。排序：向听小的在前，同向听进张多的在前。
- 打分（`scoreOf`）：最好的 20 分（进张和最好的一样多也满分）；向听一样的按 `round(20 × 进张 / 最好的进张)`；向听更大的 0 分。一天满分 100。评价：满分 ✓、有分 △、0 分 ✗。
- 画面：一页走完。出题页是"第 n/5 题"、桌上的牌和 14 张手牌；点一张抬起来，再点同一张或点"打出这张"才打出（←/→ 换牌，Enter 打出 / 下一题，Esc 回主页）。揭晓页写评价和得分（滚上去），前三名的打法和"你选的"各一行（向听、进张几种几张、有效牌画出来），最佳打法金框；打对了出金色的"好牌！"和音效。
  五题完出成绩卡：总分、五题符号、连续天数和最好，"分享"（`hekiriCardOf`，不含牌）、"再练一遍"（练习）、"回主页"；100 分另有"全对！"的大字。触控按钮不小于 44 像素；竖屏手牌分两行（每行 7 张）。
- 成绩：做完当天第一遍才记（`mahjong.hekiri`，见 [storage.md](storage.md)），之后再做是练习。有平台并登录时，第一遍的总分交给平台每日榜 `POST /api/scores { gameId: 'mahjong', boardId: 'daily-YYYY-MM-DD-hekiri', score }`，失败（没登录、榜没登记、断网）不吭声；榜怎么显示写在 `public/daily.json`。

## 听牌速判（`core/puzzles/ting.ts`、`game/ting.ts`、`view/ting.ts`）

60 秒一轮：每题一手 13 张清一色，把它听的牌（这一门的 1–9 里挑）全点出来再"提交"，全对才得分，连对有加成；主页"我的进度"那排的"速判"胶囊进，值是"今天 N 分"（今天打过今日一轮）或"今天未做"。只是娱乐，不碰筹码、不接钱包。

- 出题（`tingQuestion(key, i)`，纯函数）：随机一门，先凑一副完整的 14 张（4 组顺子或刻子加一对，八分之一的概率凑七对形）再拿掉一张，所以必听牌；听哪些牌用 `core/hand` 的 `waits`（川麻牌型：一般型加七对，龙七对算两对），手里已有 4 张的那种不算。
  按档位的目标种数出题：先在目标种数范围内随机定一个数，试 400 手凑到正好；不行再试 4,000 手放宽到档位范围；还不行取至少听 1 种的一手（测试保证实际几乎用不到）。
- 档位（`tingTier(i)`，按第几题）：第 1–2 题听 1–2 种；第 3–5 题 2–3 种；第 6–9 题 3–5 种；第 10 题起 5–9 种（九面听也能出）。
- 种子：随机只用 `stream(key, 'ting', 第 i 题)`，题和题互不影响。练习的 key 由页面层 `crypto.getRandomValues` 给，核心只收 key；每日一套的种子 `tingKey(date)` 只由北京日期字符串派生（前缀 `mahjong-ting:`，盐和何切、每日挑战不同），今日一轮用它，所有人这一天同一套题。
- 判题（`judge(waits, picks)`）：选的集合正好等于听的集合才算对；返回选对的（hit）、漏的（missed）、选错的（wrong）。
- 计分（`scoreOf(听的种数, 连对数)`，整数）：答对一题得 `10 × 听的种数 + 5 × min(连对数, 6)`，连对数是答这题之前已经连对几题（第一题加成 0，加成最多 30 分）；答错 0 分、连对清零。一轮的累加是 `answer(状态, 听的牌, 选的牌)`，状态有分数、答了几题、答对几题、现在连对、最长连对。
- 画面：先一屏说明，两个按钮："今日一轮"（每天一次）和"练习"（随机题，不计今日成绩）；今天已经打过，今日一轮的位置显示"今天 N 分"，只剩练习。答题页上面是倒计时条（最后 10 秒变红）、分数和连对，中间 13 张手牌，底下 9 个按钮（牌面，竖屏 3×3 小键盘样子，横屏一排，每个至少 44 屏幕像素）和"提交"。
  点一下抬起、金框、角上一个勾，再点取消；没选牌时"提交"灰着。电脑上 1–9 切换、回车提交、Esc 回主页。提交后亮答案：选对的金框带勾、漏的虚线金框带"漏"、选错的红框压暗带 ×，约 1.1 秒后下一题（点一下任意处跳过）。
  听 5 种以上答对弹大字（"五面听！"…"八面听！"，9 种是"九莲宝灯！"，`view/fx.ts` 的 celebrate；减少动态效果时只留淡入淡出）。时间到：答题中立刻结束，答案亮着则等它翻过去；成绩页是分数、答对几题、最长连对、本机最好，破纪录有"新纪录！"，可"再来一轮"或回主页。
- 成绩：本机 `mahjong.ting`（见 [storage.md](storage.md)）。最好成绩今日一轮和练习都算，破了才改。
- 今日一轮的记账（`daily`，纯函数在 `game/ting.ts`）：`{ date, score, correct, bestStreak, done, sent }`。开始那一刻就写 `0 分、done=false、sent=false`，中途刷新、关页面不能重来；每答一题更新分数；时间到写 `done`，随后提交，成功才写 `sent`。
  进听牌速判页和主页时清账（`settleDaily`）：日期不是今天的丢掉（不补交昨天）；今天没打完的按已得分算打完；done 没 sent 的再交一次；sent 了不再交。
  只有登录才交：`POST /api/scores { gameId: 'mahjong', boardId: 'daily-YYYY-MM-DD-ting', score, userId }`，断网、榜没登记都不吭声、不挡成绩页；榜怎么显示写在 `public/daily.json`。
- 分享：成绩页的"分享"（`tingCardOf`，不含牌）。今日一轮写日期，"60 秒判了 N 手、最长连对 M"和分数；练习的卡写"练习 · 不计成绩"、不带日期。打完今日一轮后，成绩页的"再练一轮"是练习。

## 茶馆擂台（`game/ladder.ts`、`view/ladder.ts`、`app/solo-flow.ts` 的 `playLadder`）

单机连打三桌，电脑一桌比一桌强（新手 → 普通 → 高手，`LADDER_LEVELS`），三桌全赢拿这种打法的称号。主页"我的进度"那排的"擂台"胶囊进，值是"第 N 桌"（有一轮没打完）、"N 个称号"或"去打擂"。纯娱乐，不碰筹码，称号不进平台的榜和资料（只存本机和云存档）。

- 打法四种（`LADDER_MODES`）：`xz` 血战到底、`xl` 血流成河、`x3` 三人两房（不换三张）、`rc` 立直；各玩法在主页切换项（`HomeChoice.ladder`）里给自己的号和一桌的规则：娱乐短局、默认规则（川麻 1 局，立直一局），不看玩家平时的规则设置，也不改上次选的档位。
- 赢：一桌打完净分 ≥ 0（`winsTable`），进下一桌；输了这一轮结束，下次从第一桌重来（`RETRIES = 0`，模拟见 [balance-results.md](balance-results.md)）。三桌都赢拿称号（血战擂主、血流擂主、立直擂主），每种打法还记最远赢到第几桌。
- 种子：开一轮时页面层 `crypto.getRandomValues` 给这一轮的密钥，每一桌的牌局密钥是 `tableKey(run)`，按 `stream(密钥, 'ladder:桌号:第几次')` 派生；三个电脑照常按牌局密钥的 `persona` 分流、按这一桌的难度挑。
- 中途离开：这一桌就是一个普通的单机存档（`mahjong.solo`，多存一个 `ladder: { mode, table }`），刷新、回大厅后照常"继续上局"，或在擂台页"接着打第 N 桌"；擂台记着这一桌的存档号（`run.solo`），存档被别的单机盖掉了就按同一副牌重开这一桌。
- 一场打完：结算弹窗里多一行擂台结果和三桌的圆点（`ladderEnd`，只在这一轮记着的存档号还是这一场时记一次，重画不重复记），按钮是"回擂台"和"下一桌"（赢了）/"再开一轮"（输了）；打通了只留"回擂台"。擂台的一桌不给"换到轻松一档"。顶栏写"玩法 · 擂台第 N 桌 · 难度"。
- 中途点"大厅"或"离开"：确认"先离开，下次在擂台接着打这一桌"，存档留着（`Solo.leave` 对擂台的一桌不收场），回来接着这一手打，不换牌、不重来。
- 云存档：登录后称号和最远几桌同步到账号（槽 `ladder`，见下文「云存档」），换设备登录也在；没打完的一轮只在这台设备上。
- 擂台页：四种打法各一张卡（横屏一排四张，竖屏上下摆），三个圆点（赢过的金色、正在打的金框）、称号、最远第几桌，按钮"开擂"/"接着打第 N 桌"/"放弃这一轮"/"再打一轮"；有一轮没打完时开新的一轮先确认放弃。

## 云存档（`net/cloud.ts`、`app/cloud.ts`）

照 `docs/platform-backend.md` 5.5。只同步一个槽 `ladder`，内容是 `cloudPart`：`{ v: 1, titles, best }`。
- 启动：有平台、带着 `__Host-arcade_li` 才问 `/api/me`（`user.id`、`saves` 档位），再 `GET /api/saves/mahjong?userId=` 合并；合并前本机那份备份到 `mahjong.ladder.pre-sync`。`/api/me` 不是 200 或 `saves: 'paused'` 时这次打开不同步。
- 合并（`mergeLadder`，纯函数）：称号取并集、最远取较大，没打完的一轮留本机的；交换、重复合并结果一样。
- 上传：`writeLadder` 写完通知 `cloud.touched()`，10 秒防抖，同一个槽两次上传至少隔 5 分钟；每个 PUT 都带 `userId`。切后台（`visibilitychange`、`pagehide`）和离开牌桌时用 keepalive 补传，离上次上传不到 3 分钟就留到下次打开。
- 回话：409 `conflict` 备份、合并 `current`、用它的 `rev` 只重交一次；409 `wrong_user` 不合并、不重试，按换号处理；429 按 `retryAfter` 再传；413、400、422、404 这次打开不再传；503 暂停；401 当作退出；连不上留着待传。
- 换号（`/api/me` 的账号和 `mahjong.cloud` 记的不同，或 `wrong_user`）：不问玩家，本机那份备份到 `mahjong.ladder.pre-switch.<旧账号>`（已有就先合并）并读回核对，本机写成空档、元数据换成新账号并立即存盘，再拉新账号的；备份写不进去就什么都不清、暂停（云朵"存储满了"）。
  以后登录回那个账号，拉完把备份并回来、上传成功后改名 `.restored`。回到前台、拿到焦点时离上次确认身份超过 1 分钟再问一次 `/api/me`；别的标签页换了号，这边跟着换。
- 云朵：擂台页标题右边，未登录 / 已同步 / 同步中 / 待上传 / 已合并 / 暂停同步 / 存储满了（后两个带小红点）。点"未登录"去 `/login?from=mahjong`，别的只弹一句现在怎样；单独部署（没有平台）不显示。
